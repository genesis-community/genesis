=head1 NAME

Genesis::Secret::X509 - X.509 certificate secret type for Genesis

=head1 SYNOPSIS

  use Genesis::Secret;

  # Build an X.509 certificate secret via the factory method
  my $cert = Genesis::Secret->build('x509', 'kit', 'path/to/cert',
    names    => ['example.com', '*.example.com'],
    valid_for => '1y',
    signed_by => 'path/to/ca',
  );

  # Build a self-signed CA certificate
  my $ca = Genesis::Secret->build('x509', 'kit', 'path/to/ca',
    is_ca    => 1,
    valid_for => '10y',
    usage     => [qw/server_auth client_auth crl_sign key_cert_sign/],
  );

  # Get the vault operator string for use in a BOSH manifest
  my $op = $cert->vault_operator('certificate');
  # Returns: (( vault meta.vault "/path/to/cert:certificate" ))

  # Check the signing CA
  my $ca_secret = $cert->ca();

=head1 DESCRIPTION

C<Genesis::Secret::X509> manages X.509 certificate secrets stored in
Vault. It handles both leaf certificates and CA certificates, supporting
certificate issuance via C<safe x509 issue>, renewal via C<safe x509
renew>, Subject Alternative Names (SANs), key usage extensions, signing
chains, and import from CredHub.

This class inherits from L<Genesis::Secret> and should be instantiated
via C<Genesis::Secret-E<gt>build('x509', ...)> rather than directly.

Each X.509 secret stores up to five Vault keys at its path:

=over 4

=item * C<certificate> - the PEM-encoded certificate

=item * C<key> - the PEM-encoded private key

=item * C<combined> - the certificate and key concatenated

=item * C<serial> - the CA serial counter (CA certificates only, not CredHub)

=item * C<crl> - the certificate revocation list (CA certificates only, not CredHub)

=back

Constructor arguments are validated by C<_validate_constructor_opts>.
See that method under L</INTERNAL METHODS> for the full list of
accepted options and their validation rules.

=head1 METHODS

=head2 new

  my $obj = Genesis::Secret::X509->new();

Constructs a new X.509 secret by delegating to the parent
C<Genesis::Secret> constructor, then initialising two additional instance
flags: C<signed> (set to C<0>) and C<ordered> (set to C<0>).

In normal use, call C<Genesis::Secret-E<gt>build('x509', ...)> rather
than this constructor directly.

B<Returns:> a new C<Genesis::Secret::X509> object.

B<Examples:>

  # Typically called indirectly via the factory
  my $cert = Genesis::Secret->build('x509', 'kit', 'path/to/cert',
    names => ['example.com'],
  );
  print ref($cert); # Returns: Genesis::Secret::X509

=head2 ordered

  my $flag = $obj->ordered();
  $obj->ordered(1);
  $obj->ordered(0);

Accessor/mutator for the C<ordered> flag, which tracks whether this
certificate has been placed in the correct dependency order relative
to its signing CA. When called with no argument, returns the current
value (C<1> or C<0>). When called with an argument, sets the flag to
C<1> if the argument is true, C<0> otherwise.

B<Parameters:>

=over 4

=item * C<$value> (optional) - boolean, new value for the ordered flag

=back

B<Returns:> When setting, returns the new flag value (C<1> or C<0>).
When getting, returns the current flag value (C<1> or C<0>).

B<Examples:>

  print $cert->ordered();   # Returns: 0
  $cert->ordered(1);
  print $cert->ordered();   # Returns: 1

=head2 read_names

  my @names = $obj->read_names();

Reads the stored certificate and extracts all DNS names and IP addresses
associated with it. If the secret has not yet been loaded, triggers a
store read first. Parses the certificate using C<openssl x509> to extract
the Subject Common Name and any Subject Alternative Names (SANs) of type
C<DNS> or C<IP Address>.

Returns an empty list if the secret has no value or if the stored value
contains no C<certificate> key.

B<Returns:> A deduplicated list of name strings: the subject CN followed
by all SAN entries, with trailing whitespace stripped.

B<Examples:>

  # For a cert with CN=example.com and SANs *.example.com, 10.0.0.1
  my @names = $cert->read_names();
  # Returns: ('example.com', '*.example.com', '10.0.0.1')

  # For a secret with no certificate stored
  my @names = $cert->read_names();
  # Returns: ()

=head2 ca

  my $ca_secret = $obj->ca();

Returns the C<Genesis::Secret::X509> object representing the CA that
signed this certificate. If the certificate is self-signed (i.e., the
C<self_signed> definition property is true), returns C<$self>. Otherwise
looks up the secret at the path specified by the C<signed_by> definition
property in the current plan.

B<Returns:> A C<Genesis::Secret::X509> object - either C<$self> for
self-signed certificates, or the CA secret from the plan's store.

B<Examples:>

  my $ca = $cert->ca();
  print ref($ca);          # Returns: Genesis::Secret::X509
  print $ca->path();       # Returns: e.g. 'path/to/ca'

  # Self-signed certificate returns itself
  my $self_ca = $self_signed_cert->ca();
  print $self_ca == $self_signed_cert ? 'same' : 'different';
  # Returns: same

=head2 vault_operator

  my $op     = $obj->vault_operator($key);
  my $op_map = $obj->vault_operator();

Returns the Vault operator string (for embedding in BOSH manifests) for
a specific key within the X.509 secret. When called without a key argument,
returns a hashref mapping all three logical keys to their operator strings.

Recognized C<$key> values:

=over 4

=item * C<'certificate'> - the PEM certificate at C<E<lt>pathE<gt>:certificate>

=item * C<'key'> or C<'private_key'> - the private key at C<E<lt>pathE<gt>:key>

=item * C<'ca'> - the CA certificate; for self-signed certs, equivalent to
C<'certificate'>; for certs signed by an absolute path, uses that path directly;
otherwise delegates to C<< $self->ca->vault_operator('certificate') >>

=back

Dies (via C<bug()>) for any other key value:

=over 4

=item * C<"Invalid key for vault_operator on %s secret"> where C<%s> is the secret type

=back

B<Parameters:>

=over 4

=item * C<$key> (optional) - one of C<'certificate'>, C<'key'>, C<'private_key'>,
or C<'ca'>; omit to get all three

=back

B<Returns:> A Vault operator string (e.g.,
C<(( vault meta.vault "/my/path:certificate" ))>), or a hashref with
keys C<ca>, C<certificate>, and C<private_key> when called without an argument.

B<Examples:>

  my $op = $cert->vault_operator('certificate');
  # Returns: (( vault meta.vault "/path/to/cert:certificate" ))

  my $op = $cert->vault_operator('key');
  # Returns: (( vault meta.vault "/path/to/cert:key" ))

  my $all = $cert->vault_operator();
  # Returns: { ca => '...', certificate => '...', private_key => '...' }

=head2 label

  my $label = $obj->label();

Returns the human-readable type label for this secret class.

B<Returns:> The string C<"X.509 certificate">.

B<Examples:>

  print $cert->label(); # Returns: X.509 certificate

=head2 process_command_output

  my ($out, $rc, $err) = $obj->process_command_output($action, $out, $rc, $err);

Post-processes the output from a C<safe>/vault command. Overrides the
L<base class implementation|Genesis::Secret/process_command_output> to provide X.509-specific formatting for
rotate operations.

When C<$action> is C<'rotate'> and C<$out> matches the pattern for a
successful renewal (C<"Renewed x509 cert...expiry set to ...">), reformats
the output to a human-friendly expiry message including the number of
days remaining. Uses a 2-minute buffer when computing elapsed days. If
the date parse fails, appends the Perl error string to the expiry message
instead.

For all other actions, returns C<($out, $rc, $err)> unchanged.

B<Parameters:>

=over 4

=item * C<$action> - the action string, e.g. C<'add'>, C<'rotate'>, C<'remove'>

=item * C<$out> - standard output from the command

=item * C<$rc> - exit code from the command

=item * C<$err> - standard error from the command

=back

B<Returns:> The list C<($out, $rc, $err)>, with C<$out> reformatted on
successful rotate operations.

B<Examples:>

  my ($out, $rc, $err) = $cert->process_command_output(
    'rotate',
    "Renewed x509 cert at secret/env/cert expiry set to Jan 01 2027 00:00 UTC",
    0,
    '',
  );
  # Returns: ("[checkmark]Expiry updated to Jan 01 2027 00:00 UTC (365 days)", 0, '')

=head1 INTERNAL METHODS

These methods are internal to the implementation. They may change without
notice and should not be called directly.

=head2 _description

  my ($label, @features) = $obj->_description();

Returns the label and feature annotations for this certificate, used by
the inherited L<describe|Genesis::Secret/describe> method to build the human-readable description.

The label is always C<"X.509 certificate">. Feature annotations are:

=over 4

=item * C<"CA"> if the certificate is a CA (C<is_ca> is true)

=item * C<"self-signed"> or C<"explicitly self-signed"> if C<self_signed>
is 1 or 2 respectively

=item * C<"signed by 'E<lt>pathE<gt>'"> if C<signed_by> is set and the
certificate is not self-signed

=back

B<Returns:> A list of C<($label, @features)> with C<undef> entries
filtered by the caller.

=head2 _required_value_keys

  my @keys = $obj->_required_value_keys();

Returns the list of Vault key names that must be present for this
certificate's stored value to be considered complete. Always includes
C<certificate>, C<combined>, and C<key>. For CA certificates
(C<is_ca> true) whose source is not C<'credhub'>, also includes C<crl>
and C<serial>.

B<Returns:> A list of key name strings.

=head2 _validate_constructor_opts

  my ($args)          = $class->_validate_constructor_opts($path, %opts);
  my ($orig, $errors) = $class->_validate_constructor_opts($path, %opts);

Validates the constructor options for an X.509 secret definition.
Called by the inherited L<validate_definition|Genesis::Secret/validate_definition> method.

Accepted options in C<%opts>:

=over 4

=item * C<valid_for> - validity duration, must match C</^[1-9][0-9]*[ymdh]$/>.
Error: C<"Invalid valid_for argument: expecting E<lt>positive_numberE<gt>[ymdh], got E<lt>valueE<gt>">

=item * C<subject_cn> - explicit Subject Common Name string

=item * C<names> - arrayref of one or more non-empty strings for SANs.
Errors include:
C<"Invalid names argument: expecting an array of one or more strings, got a hashmap">,
C<"Invalid names argument: expecting an array of one or more strings, got the string 'E<lt>valueE<gt>'">,
C<"Invalid names argument: expecting an array of one or more strings, got an empty list">,
C<"Invalid names argument: cannot have an empty name entry">,
C<"Invalid names argument: cannot have an entry that is not a string">

=item * C<usage> (or deprecated C<key_usage>) - arrayref of key usage
identifiers. Valid identifiers are the union of standard key usage and
extended key usage types from the module's lookup tables. Error if
unknown keys are supplied:
C<"Invalid usage argument - unknown usage keys: 'E<lt>keysE<gt>'\n[[Valid keys are: >>'E<lt>keysE<gt>'">

=item * C<is_ca> - boolean (C<1> or empty string). Must match
C</^1?$/>.
Error: C<"Invalid is_ca argument: expecting boolean value, got 'E<lt>valueE<gt>'">

=item * C<signed_by> - relative vault path string matching
C</^[a-z0-9_-]+(\/[a-z0-9_-]+)*$/i>.
Error: C<"Invalid signed_by argument: expecting relative vault path string, got 'E<lt>valueE<gt>'">

=item * C<base_path> - always consumed (no validation)

=item * C<fixed> - consumed if present (no validation)

=back

Additional validation rule: non-CA certificates must supply at least one
name. Error: C<"Non-CA certificates must supply at least one name">.

Any option key not listed above produces:
C<"Invalid 'E<lt>keyE<gt>' argument specified">

B<Returns:> On success, a single-element list containing the validated
args hashref. On failure, a two-element list of C<(\%orig_opts, \@errors)>.

B<Examples:>

  # Valid definition
  my ($args) = Genesis::Secret::X509->_validate_constructor_opts(
    'path/to/cert',
    names     => ['example.com'],
    valid_for => '1y',
    signed_by => 'path/to/ca',
  );
  # Returns: ({ names => ['example.com'], valid_for => '1y', signed_by => 'path/to/ca', ... })

  # Invalid definition
  my ($orig, $errors) = Genesis::Secret::X509->_validate_constructor_opts(
    'path/to/cert',
    valid_for => 'bad',
  );
  # Returns: (\%orig_opts, ["Invalid valid_for argument: ...])

=head2 _validate_value

  my ($results, @order) = $obj->_validate_value();

Validates the stored X.509 certificate value against the secret's
definition. Uses C<openssl> to parse the certificate and key, then
checks multiple aspects of the stored value.

Validation checks performed (in result order):

=over 4

=item * C<is_ca> - verifies that the CA:TRUE basic constraint is present
(or absent) as expected by the C<is_ca> definition property

=item * C<self_signed> - for self-signed certs, verifies that subject key
identifier matches authority key identifier (falling back to CN comparison)

=item * C<signed> - for externally-signed certs, verifies the chain by
comparing key identifiers, then by C<openssl verify>, then via
C<safe x509 validate> as a last resort

=item * C<valid> - checks the certificate's Not Before/Not After dates
against the current time; warns if expiring within 30 days

=item * C<modulus_agreement> - confirms that the private key's modulus
matches the certificate's modulus

=item * C<cn> - if C<subject_cn> or C<names[0]> is set, verifies the
certificate's Subject CN matches

=item * C<san> - for non-CA certs, verifies that SANs match the C<names>
definition (CA SANs are not validated)

=item * C<usage> - checks key usage extensions against expected usage
via C<_check_usage>

=back

B<Returns:> A two-element list of C<(\%results, @order)> where C<%results>
is a hash of C<< validation_name => [$status, $message] >> pairs and
C<@order> is the ordered list C<qw/is_ca self_signed signed valid
modulus_agreement cn san usage/>.

=head2 _get_safe_command_for_add

  my @cmd = $obj->_get_safe_command_for_add();

Builds the C<safe> command array for issuing a new X.509 certificate.
Called by the inherited L<get_safe_command_for|Genesis::Secret/get_safe_command_for> dispatch for the C<'add'> action.

For CA certificates with no configured names and no C<subject_cn>, an
auto-generated CN is created as C<ca.nNNNNNNNNN.E<lt>base_pathE<gt>>.
Delegates to C<_base_safe_command> for the core command, then appends
C<--ca> for CA certificates and C<--no-clobber> to prevent overwriting
existing certificates.

B<Returns:> A list of command tokens suitable for passing to C<safe>.

=head2 _get_safe_command_for_rotate

  my @cmd = $obj->_get_safe_command_for_rotate(%opts);

Builds the C<safe> command array for rotating an X.509 certificate.
Called by the inherited L<get_safe_command_for|Genesis::Secret/get_safe_command_for> dispatch for the C<'rotate'> action.

If the secret has no current value, delegates to
C<_get_safe_command_for_add>. Otherwise defaults to a C<renew> action.
If C<opts{regen_x509_keys}> is true and the stored value contains a
private key, switches to C<issue> action to regenerate the key pair.

For CA certs with no configured names and no C<subject_cn>, reads the
current names from the stored certificate via C<read_names>.

For C<renew> action, adds C<--subject cn=E<lt>nameE<gt>> when
C<opts{update_subject}> is true or the C<GENESIS_RENEW_SUBJECT>
environment variable is set.

B<Parameters:>

=over 4

=item * C<%opts> - optional hash of flags:

=over 4

=item * C<regen_x509_keys> - if true, use C<issue> instead of C<renew>
to regenerate the key pair

=item * C<update_subject> - if true, pass C<--subject> to C<safe x509 renew>

=back

=back

B<Returns:> A list of command tokens suitable for passing to C<safe>.

B<Examples:>

  my @cmd = $cert->_get_safe_command_for_rotate(regen_x509_keys => 1);
  # Returns: ('x509', 'issue', 'secret/env/path/to/cert', '--ttl', '3y', '--name', 'example.com', ...)

=head2 _import_from_credhub

  my ($status, $msg) = $obj->_import_from_credhub($value);

Imports an X.509 certificate from a CredHub credential value. Called by
the inherited L<import_from_credhub|Genesis::Secret/import_from_credhub> method after fetching the CredHub data.

C<$value> must be a hashref with at least C<certificate> and
C<private_key> keys. Stores the certificate, key, and combined value
in Vault. For non-CA certificates, returns immediately with the imported
key list.

For CA certificates, additionally runs C<safe x509 renew> to generate the
C<serial> and C<crl> values that CredHub does not provide, then restores
the original certificate and key (since the renew would replace them).

B<Parameters:>

=over 4

=item * C<$value> - hashref with keys C<certificate> and C<private_key>

=back

B<Returns:> A two-element list of C<($status, $message)>:

=over 4

=item * C<('error', 'expecting a hash, got a E<lt>typeE<gt>')> if C<$value>
is not a hashref

=item * C<('error', 'missing keys in credhub secret: E<lt>keysE<gt>')> if
C<certificate> or C<private_key> are absent

=item * C<('ok', 'Certificate imported with these keys: E<lt>keysE<gt>')>
on successful non-CA import

=item * C<('error', ...)> if CA serial/CRL generation fails

=item * C<('ok', 'CA certificate imported with these keys: E<lt>keysE<gt>')>
on successful CA import

=back

B<Examples:>

  my ($status, $msg) = $cert->_import_from_credhub({
    certificate => $pem_cert,
    private_key => $pem_key,
  });
  # Returns: ('ok', 'Certificate imported with these keys: certificate, combined, key')

=head2 _key_usage_types

  my @types = _key_usage_types();

Returns the complete list of valid key usage identifier strings
recognised by this module. The list is the deduplicated union of all
values from the standard key usage lookup table and the extended key
usage lookup table.

Valid identifiers include: C<digital_signature>, C<non_repudiation>,
C<content_commitment>, C<key_encipherment>, C<data_encipherment>,
C<key_agreement>, C<key_cert_sign>, C<crl_sign>, C<encipher_only>,
C<decipher_only>, C<client_auth>, C<server_auth>, C<code_signing>,
C<email_protection>, C<timestamping>.

B<Returns:> A deduplicated list of usage identifier strings.

=head2 _expected_usage

  my ($usage, $usage_str, $usage_type) = $obj->_expected_usage();

Returns the expected key usage configuration for this certificate based
on its definition.

=over 4

=item * If C<usage> is explicitly defined: returns the defined array,
the string C<"Specified key usage"> (or C<"No key usage"> if the array
is empty), and C<'warn'>.

=item * If C<is_ca> is true and no C<usage> is defined: returns
C<[qw/server_auth client_auth crl_sign key_cert_sign/]>,
C<"Default CA key usage">, and C<'warn'>.

=item * Otherwise: returns C<[qw/server_auth client_auth/]>,
C<"Default key usage">, and C<'warn'>.

=back

B<Returns:> A three-element list of C<($usage_arrayref, $label_string, $type_string)>.

=head2 _get_usage_matrix_from_text

  my %found = $obj->_get_usage_matrix_from_text($openssl_text);

Parses the text output of C<openssl x509 -text> to extract the key usage
and extended key usage extensions present in the certificate. Maps the
OpenSSL display names (e.g. C<"Digital Signature">) to the internal
identifier strings (e.g. C<"digital_signature">) using the module's
lookup tables. Unknown OpenSSL key names are silently ignored.

B<Parameters:>

=over 4

=item * C<$openssl_text> - the full text output from C<openssl x509 -text>

=back

B<Returns:> A hash where the keys are internal usage identifier strings
and the values are C<1> for each usage found.

B<Examples:>

  my %found = $cert->_get_usage_matrix_from_text($openssl_text);
  # Returns: (digital_signature => 1, server_auth => 1, client_auth => 1)

=head2 _check_usage

  my $result = $obj->_check_usage($openssl_text);

Compares the key usage extensions present in the certificate against the
expected usage from C<_expected_usage>. Handles the C<non_repudiation>/
C<content_commitment> equivalence (both being valid representations of
the same extension).

Returns an arrayref of C<[$status, $message]>:

=over 4

=item * C<['ok', 'E<lt>usage_strE<gt>: E<lt>listE<gt>']> if all expected
keys are present and no unexpected keys are found

=item * C<[$usage_type, 'E<lt>usage_strE<gt> (missing: ...; extra: ...)']>
if there are discrepancies; C<$usage_type> is always C<'warn'> if no
keys were found in the certificate at all

=back

B<Parameters:>

=over 4

=item * C<$openssl_text> - the full text output from C<openssl x509 -text>

=back

B<Returns:> An arrayref of C<[$status, $message]>.

B<Examples:>

  my $result = $cert->_check_usage($openssl_text);
  # Returns: ['ok', 'Default key usage: server_auth, client_auth']

=head2 _base_safe_command

  my @cmd = $obj->_base_safe_command($action, @names);

Builds the common set of C<safe x509> command tokens shared by the add
and rotate operations. Constructs the base C<x509 E<lt>actionE<gt>
E<lt>full_pathE<gt> --ttl E<lt>ttlE<gt>> command, appending C<--signed-by>
if the certificate has a C<signed_by> definition, subject and name
arguments appropriate for the certificate type, and C<--key-usage> flags
for each usage identifier from C<_expected_usage>.

Default TTL is C<10y> for CA certificates and C<3y> for leaf certificates
unless C<valid_for> is explicitly defined.

For CA certificates, passes C<--subject cn=E<lt>cnE<gt>> and a single
C<--name> (to work around a C<safe> limitation with SANs-less CAs). For
non-CA issue operations, passes C<--subject> only if C<subject_cn> is
defined; always passes C<--name> for each unique name in C<@names>.

B<Parameters:>

=over 4

=item * C<$action> - the C<safe x509> sub-command: C<'issue'> or C<'renew'>

=item * C<@names> - the list of SAN/hostname strings

=back

B<Returns:> A list of command tokens suitable for passing to C<safe>.

B<Examples:>

  my @cmd = $cert->_base_safe_command('issue', 'example.com', '*.example.com');
  # Returns: ('x509', 'issue', 'secret/env/path/to/cert', '--ttl', '3y',
  #           '--name', 'example.com', '--name', '*.example.com',
  #           '--key-usage', 'server_auth', '--key-usage', 'client_auth')
