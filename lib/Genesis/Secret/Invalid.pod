=head1 NAME

Genesis::Secret::Invalid - Sentinel secret type representing an invalid or unrecognized secret definition

=head1 SYNOPSIS

  use Genesis::Secret;

  # Invalid secrets are produced automatically by the framework
  # when a definition fails validation. You do not construct them directly.
  my $secret = Genesis::Secret->build('unknown_type', 'kit', 'path/to/secret');
  if (!$secret->valid) {
      my $msg = $secret->describe();
      print $msg;
  }

  # Or from a failed validation via reject()
  my $invalid = Genesis::Secret->reject(
      'random', ['Missing length'], 'path/to/secret', {}
  );
  print ref($invalid); # prints 'Genesis::Secret::Invalid'

=head1 DESCRIPTION

C<Genesis::Secret::Invalid> is a sentinel subclass of C<Genesis::Secret>
used to represent a secret definition that failed validation or whose type
is unrecognized. Rather than dying at the point of failure, the Genesis
secrets framework wraps the error in an C<Invalid> object so it can be
collected and reported alongside other secrets.

Instances are created automatically by C<Genesis::Secret> via its C<build> class method when the
type is unknown, or by its C<reject> class method when a derived class
constructor rejects its options. The C<data>, C<errors>, and C<subject>
fields in the definition carry the error context.

C<Genesis::Secret::Invalid> overrides C<valid()> to return false and
overrides C<describe()> to produce a human-readable error report suitable
for display to the operator.

=head1 METHODS

=head2 new

  my $invalid = Genesis::Secret::Invalid->new($path, %opts);

Constructor. Delegates entirely to C<< Genesis::Secret->new() >>. In
practice, invalid secrets are created via C<Genesis::Secret>'s C<build>
or C<reject> class methods rather than by calling this constructor
directly.

B<Parameters:>

=over 4

=item * C<$path> - The Vault path for the secret.

=item * C<%opts> - Definition options. For invalid secrets these typically
include C<subject> (a label string), C<errors> (an arrayref of error
messages), and C<data> (the raw definition that failed validation).

=back

B<Returns:> A new C<Genesis::Secret::Invalid> object.

B<Examples:>

  # Typically produced by the framework, not called directly
  my $invalid = Genesis::Secret->reject(
      'random', ['Missing length'], 'path/to/secret', { length => undef }
  );
  print ref($invalid); # prints 'Genesis::Secret::Invalid'

=head2 valid

  my $bool = $secret->valid();

Returns false (C<0>). Overrides the L<base class|Genesis::Secret/valid> to signal that this secret
represents an invalid definition.

B<Returns:> C<0>

B<Examples:>

  my $invalid = Genesis::Secret->reject(
      'random', ['Bad option'], 'path/to/secret', {}
  );
  print $invalid->valid(); # prints '0'

=head2 describe

  my $msg                      = $secret->describe();
  my ($path, $label, $msg)     = $secret->describe();

Produces a formatted error report for the invalid secret definition.

In scalar context, returns a multi-line string of the form:

  Invalid definition for <subject> secret:
  - <error 1>
  - <error 2>
    path: <vault-path>
    data: <raw-definition>

where C<< <subject> >> comes from the C<subject> definition field
(defaulting to C<"Unknown">), and C<< <errors> >> from the C<errors>
field (defaulting to C<["Invalid secret definition"]>). If the C<data>
field is a reference it is serialized as YAML (falling back to JSON if
YAML serialization fails). The path is colorized and annotated with the
kit feature or manifest variable name when applicable.

In list context, returns a three-element list:

=over 4

=item 1. The raw Vault path string (C<< $secret->path() >>).

=item 2. The human-readable label (C<< $secret->label() >>).

=item 3. The same formatted error message string as in scalar context.

=back

B<Returns:> In scalar context, a formatted error string. In list context,
C<($path, $label, $msg)>.

B<Examples:>

  my $invalid = Genesis::Secret->reject(
      'random',
      ['Missing required option: length'],
      'path/to/secret',
      {}
  );

  # Scalar context
  my $msg = $invalid->describe();
  print $msg;
  # prints:
  #   Invalid definition for random secret:
  #   - Missing required option: length
  #     path: path/to/secret
  #     data: <undefined>

  # List context
  my ($path, $label, $msg) = $invalid->describe();
  print "$path\n"; # prints 'path/to/secret'
  print "$label\n"; # prints 'Invalid'

=head1 INTERNAL METHODS

These methods are internal to the implementation. They may change without
notice and should not be called directly.

=head2 _validate_constructor_opts

  my ($args, $path) = $class->_validate_constructor_opts($path, %opts);

Override point called by L<validate_definition|Genesis::Secret/validate_definition>. For invalid secrets,
all options are accepted without any validation -- the object is a
placeholder for an already-failed definition and there are no constraints
to enforce.

Returns the options hashref and path as-is.

B<Examples:>

  my ($opts, $path) = Genesis::Secret::Invalid->_validate_constructor_opts(
      'path/to/secret', subject => 'random', errors => ['bad input']
  );
  # Returns: (\%opts, 'path/to/secret') -- all opts accepted unchanged

=head2 _description

  my ($subject, $error) = $self->_description();

Returns the C<subject> and C<error> fields from the object's internal
hash. Note that C<describe()> is overridden on this class and does not
delegate to C<_description()>; this method exists for compatibility with
the parent L<describe|Genesis::Secret/describe> dispatch machinery.
