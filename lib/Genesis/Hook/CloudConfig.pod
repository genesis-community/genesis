=head1 NAME

Genesis::Hook::CloudConfig - Hook subclass for generating BOSH cloud configs from Genesis environments

=head1 SYNOPSIS

    package Genesis::Hook::CloudConfig::my_kit;
    use parent 'Genesis::Hook::CloudConfig';

    sub perform {
        my ($self) = @_;

        my $config = {};

        push @{$config->{azs}}, {
            name             => 'z1',
            cloud_properties => { availability_zone => 'us-east-1a' },
        };

        push @{$config->{vm_types}}, $self->vm_type_definition(
            'default',
            common                  => { instance_type => 't3.medium' },
            cloud_properties_for_iaas => { aws => { instance_type => 't3.medium' } },
        );

        push @{$config->{networks}}, $self->network_definition(
            'deployment',
            strategy       => 'ocfp',
            dynamic_subnets => { subnets => undef, allocation => { size => 64 } },
        );

        $self->done($config);
    }

    1;

=head1 DESCRIPTION

C<Genesis::Hook::CloudConfig> is the base class for Genesis kit hooks that
generate BOSH cloud configs. Kit authors subclass this class, implement
C<perform>, build a cloud config hashref using the provided definition
helpers, and call C<done($config)> when finished.

The class extends C<Genesis::Hook> with cloud-config-specific functionality:

=over 4

=item *

AZ lookup and CPI-shadow AZ generation

=item *

Network definition building (OCFP dynamic, greedy, and VIP strategies)

=item *

Subnet range calculation and allocation tracking (including Logical Subnet
Amalgamation for multi-AZ shared-CIDR deployments)

=item *

VM type, VM extension, and disk type definition helpers

=item *

User- and director-level override application from environment files

=back

When C<done> is called, the class validates the config hashref, processes
subnets into BOSH-compatible form (including LSA conversion), serializes the
result to canonical YAML with deterministic key ordering, and stores it on
the object for retrieval via C<results>.

Instances are cached per C<id> (basename plus optional purpose), so multiple
calls to C<init> for the same deployment return the same object.

See also:

=over 4

=item L<Genesis::Hook>

=item L<Genesis::Hook::CloudConfig::LookupRef>

=item L<Genesis::Hook::CloudConfig::LookupNetworkRef>

=item L<Genesis::Hook::CloudConfig::LookupSubnetRef>

=item L<Genesis::Hook::CloudConfig::Helpers>

=back

=head1 METHODS

=head2 init

    my $hook = Genesis::Hook::CloudConfig->init(%opts);

Constructs and returns a cloud config hook object. The C<env> key in C<%opts>
is required. If the environment uses C<create-env> (i.e., is a BOSH director
bootstrap environment), the call dies because directors have no cloud config
of their own.

The object is cached by a composite key built from C<basename> and C<purpose>,
so calling C<init> again with the same parameters returns the previously
constructed object without reinitializing.

Calls the base-class C<init> to set up shared hook state, then populates:

=over 4

=item *

C<overrides> - environment and director cloud-config override data

=item *

C<network> - BOSH director network data fetched from director exodus

=item *

C<ocfp_config> - OCFP C<net>/C<vpc> config, only for OCFP environments

=back

B<Parameters:>

=over 4

=item C<%opts>

Key-value pairs. The following keys are recognized:

=over 4

=item C<env>

B<(required)> A C<Genesis::Env> object for the deployment being operated on.

=item C<purpose>

B<(optional)> A subtype string appended to the basename to form the object
identity key. Defaults to the C<GENESIS_CLOUD_CONFIG_SUBTYPE> environment
variable if set.

=item C<basename>

B<(optional)> The base name used to prefix component names. Defaults to
C<< env->name . '.' . env->type >>.

=back

=back

B<Returns:> A blessed C<Genesis::Hook::CloudConfig> object (or a subclass
instance if called on a subclass).

B<Errors:>

=over 4

=item C<"Create-env environments do not have deployment cloud configs,as there is no director to upload them to.">

Thrown when C<env> uses create-env mode.

=back

B<Examples:>

    my $hook = Genesis::Hook::CloudConfig->init(env => $env);
    # Returns: a Genesis::Hook::CloudConfig instance

=head2 done

    $self->done($contents);

Marks the cloud config hook as complete. Validates that C<$contents> is a
hashref, processes subnet definitions into BOSH-compatible form (converting
shared-CIDR subnets into Logical Subnet Amalgamations as needed), serializes
the result to YAML with deterministic key ordering (C<name> first,
C<cloud_properties> last), and stores the result on the object.

Modifies the object in-place by setting C<< $self->{contents} >>.

After this call, C<completed> returns true and C<results> returns the
serialized cloud config.

B<Parameters:>

=over 4

=item C<$contents>

B<(required)> A hashref containing the full BOSH cloud config structure.
Expected keys include C<azs>, C<vm_types>, C<disk_types>, C<networks>, and
C<vm_extensions>, though the structure is not validated beyond the type check.

=back

B<Returns:> The return value of the base class C<done> method.

B<Errors:>

=over 4

=item C<"CloudConfig hook must return a hashref containing the cloud config - got %s">

Thrown when C<$contents> is not a hashref. C<%s> is replaced with the ref
type of the argument, or C<'scalar value'> if it is not a reference.

=back

B<Examples:>

    $self->done({
        azs      => [{ name => 'z1', cloud_properties => {} }],
        vm_types => [{ name => 'default', cloud_properties => {} }],
    });
    # Returns: the base-class done() return value; sets hook as completed

=head2 results

    my ($config, $network) = $self->results;
    my $hashref = $self->results;

Returns the cloud config produced by the hook after it has completed. Returns
C<undef> (with a trace-level warning) if called before the hook completes.

B<Returns:>

In list context, returns a two-element list:

=over 4

=item C<$config>

The serialized cloud config as a YAML string.

=item C<$network>

The BOSH director network data hashref used during config generation.

=back

In scalar context, returns a hashref with keys C<config> and C<network>.

B<Examples:>

    # List context
    my ($yaml, $net) = $self->results;
    # Returns: ('--- azs: ...', { azs => {...}, subnets => {...} })

    # Scalar context
    my $r = $self->results;
    # Returns: { config => '--- azs: ...', network => {...} }

=head2 basename

    my $base = $self->basename;

The string used to prefix every component name this hook generates. Set
at construction time; defaults to C<< env_name.env_type >> unless an
explicit C<basename> is passed to C<init>.

B<Parameters:> None.

B<Returns:> A string of the form C<< env_name.env_type >>.

B<Examples:>

    my $base = $self->basename;
    # Returns: 'my-env.bosh'

=head2 contents

    my $yaml = $self->contents;

The serialized YAML cloud config stored by C<done>.

Before C<done> has been called this is the empty hashref C<init> seeded
it with, B<not> a string -- so a caller that assumes a string will get a
reference. Check C<completed> first, or call this only after C<done>.

B<Parameters:> None.

B<Returns:> A YAML string once C<done> has run; C<{}> before that.

B<Examples:>

    my $yaml = $self->contents;
    # Returns: "azs:\n- name: z1\n  cloud_properties: ...\n"

    # Before done() has been called:
    my $yaml = $self->contents;
    # Returns: {} -- an empty hashref, not an empty string

=head2 overrides_base

    my $path = $self->overrides_base;

The base lookup path used to find cloud config override definitions in

B<Parameters:> None.

B<Returns:> The string C<'bosh-configs.cloud'>.

B<Examples:>

    my $path = $self->overrides_base;
    # Returns: 'bosh-configs.cloud'

=head2 name_for

    my $name = $self->name_for(@parts);

Constructs a component name by joining the hook's C<basename> with the
hyphen-joined C<@parts>, separated by a dot. This is how every generated
cloud-config component gets a name that is unique per environment.

B<Parameters:>

=over 4

=item C<@parts>

One or more strings identifying the component. Joined with hyphens.
Calling with no parts yields a trailing dot and an empty suffix.

=back

B<Returns:> A string of the form C<< basename.part1-part2-... >>.

B<Examples:>

    my $name = $self->name_for('vm', 'default');
    # Returns: 'my-env.bosh.vm-default'

    my $name = $self->name_for('compilation');
    # Returns: 'my-env.bosh.compilation'

=head2 ocfp_reserved_ip_target_aliases

    my @aliases = $self->ocfp_reserved_ip_target_aliases($target);

Override point for kits. Returns the alias target names under which
C<$target> may also have reserved IPs declared, so a renamed kit still
finds reservations filed under its old name -- openbao inheriting
vault's, for example.

The base class returns nothing; kits that have been renamed override
this. Declaring the alias on the kit itself is preferred over the
module-level C<%OCFP_RESERVED_IP_TARGET_ALIASES> fallback, so the rename
story stays with the kit that was renamed.

B<Parameters:>

=over 4

=item C<$target>

The reserved-IP target name being resolved.

=back

B<Returns:> A scalar name, an arrayref of names, or nothing. Callers
normalise the result through C<_as_list>.

B<Examples:>

    # Base class: no aliases.
    my @aliases = $self->ocfp_reserved_ip_target_aliases('vault');
    # Returns: () -- nothing

    # In a renamed kit's subclass:
    sub ocfp_reserved_ip_target_aliases {
        my ($self, $target) = @_;
        return 'vault' if $target eq 'openbao';
        return;
    }
    # Returns: 'vault' for the openbao target

=head2 build_cloud_config

    my $config = $self->build_cloud_config(\%config);

Applies any extended cloud config definitions from the environment file
(from C<bosh-configs.cloud> in the env YAML) onto the given C<%config>
hashref. Extended definitions may add new VM types, disk types, and VM
extensions via C<<based-on>> inheritance.

B<Parameters:>

=over 4

=item C<\%config>

B<(required)> The partial cloud config hashref assembled by the kit's
C<perform> method. Modified in-place by adding entries from the environment's
extended cloud config.

=back

B<Returns:> The C<\%config> hashref, with any extended definitions merged in.

B<Examples:>

    my $config = { vm_types => [...], networks => [...] };
    $self->build_cloud_config($config);
    # Returns: $config with any env-defined vm_types/disk_types/vm_extensions added

=head2 build_cpi_azs

    my %az_block = $self->build_cpi_azs(%options);

Builds CPI-specific shadow AZ definitions for environments with a custom CPI
enabled. Returns an empty list if the environment does not have CPI enabled.

Each AZ in the parent's available AZs gets a corresponding shadow AZ using
the environment's AZ prefix plus the AZ index number. The network data is
updated to record the CPI-specific AZ name for each base AZ.

B<Parameters:>

=over 4

=item C<%options>

B<(optional)> Options passed through to C<_az_definition_for>. The
C<virtual> option suppresses cloud properties from the AZ definition.

=back

B<Returns:> In list context, a two-element list C<(azs => \@azs)> suitable
for direct inclusion in a cloud config hashref. Returns an empty list if CPI
is not enabled.

B<Examples:>

    my %cpi_block = $self->build_cpi_azs;
    # Returns: (azs => [{ name => 'my-env-z1', cloud_properties => {...}, cpi => '...' }])

    push @{$config->{azs}}, $cpi_block{azs}->@* if %cpi_block;

=head2 cpi_name_for_az

    my $cpi = $self->cpi_name_for_az($az_key, \%az_data);

Returns the CPI name to inject into an AZ definition. The default
implementation ignores its arguments and returns C<cpi_name>, so every AZ
uses the environment's single CPI.

This is the extension point for kits that route AZs to different CPIs (for
example, a single director serving multiple IaaSes). Override this method
and return a CPI name per AZ key; the loops in C<build_az_definitions> and
C<build_cpi_azs> call it for every AZ they emit when CPI is enabled.

B<Parameters:>

=over 4

=item C<$az_key>

The AZ's key as returned by C<get_available_azs> (the vault key, not the
rendered AZ name). May be C<undef> when the caller did not supply one.

=item C<\%az_data>

The AZ's data hashref.

=back

B<Returns:> The CPI name string to use for this AZ.

B<Examples:>

    # Base class: every AZ routes to the hook's own CPI.
    my $cpi = $self->cpi_name_for_az('z1', $az_data);
    # returns 'my-env.bosh.cpi' -- the same as $self->cpi_name

    # In a kit hook, route AZs via an az_map from the environment config:
    sub cpi_name_for_az {
        my ($self, $az_key, $az_data) = @_;
        my $az_map = $self->env->lookup('bosh-configs.director-cpi.az_map', {});
        return $az_map->{$az_key} if exists $az_map->{$az_key};
        return $self->cpi_name;
    }
    # returns the mapped CPI name for a listed AZ, else the hook's own

=head2 relinquish_networks

    $self->relinquish_networks(@networks);

Removes the claim records for the named network targets from all subnets in
the network data. This allows previously allocated IP ranges to be freed and
re-allocated to other networks.

B<Parameters:>

=over 4

=item C<@networks>

One or more network target names (the target portion, not the fully qualified
name). Each is released under both its bare form and its
C<name_for('net', $_)> form, since a kit may have claimed under either; see
C<update_network>.

=back

B<Returns:> Nothing.

B<Examples:>

    $self->relinquish_networks('deployment', 'compilation');
    # Removes allocation claims for my-env.bosh.net-deployment and
    # my-env.bosh.net-compilation from all subnet claim records

=head2 network_definition

    my $config = $self->network_definition($target, %rules);

Builds and returns a BOSH network definition hashref for the named network
target. The network strategy is selected via the C<strategy> key in C<%rules>
and dispatched to the corresponding builder method.

Unlike C<vm_type_definition>, C<vm_extension_definition>, and
C<disk_type_definition> -- which are pure transformations of the kit's
declared values -- this method reads live state. It queries the deploying
BOSH director's exodus data for the network definition B<and> for what is
already allocated, so allocations can be grown and shrunk across
deployments rather than being recomputed from scratch each time.

From that it determines the base containing network and its subnets, and
hence what is available for allocation, which AZs are available, DNS,
gateway, and so on. Network ranges are derived dynamically from three
inputs: the master range, the existing allocations, and any static values
-- and static values may legitimately fall outside the range the
allocation mask generates.

A network may be defined as a single common definition, or as a set of
subnets each with their own. Definition filters distinguish OCFP from
non-OCFP deployments, which generally want different allocation
behaviour.

Supported strategies:

=over 4

=item C<'vip'>

Returns a minimal VIP network config (name and type only).

=item C<'ocfp'>

Builds a full OCFP network definition using one of the OCFP network models
(C<dynamic_subnets>, C<greedy_subnets>, or C<subnets>). The chosen model key
must be present in C<%rules>.

=item C<'generic'>

Not yet implemented; calls C<bug()> if invoked.

=back

After building the definition, records subnet IP allocations via
C<update_network>. The method leaves the caller's C<$_> untouched, so it is
safe to call from inside C<map> or C<for> over a list of constants.

B<Parameters:>

=over 4

=item C<$target>

The network target name (e.g., C<'deployment'>, C<'compilation'>).

=item C<%rules>

Key-value options controlling network generation:

=over 4

=item C<strategy>

B<(optional)> The network strategy. Defaults to C<'generic'>.

=item C<name_prefix>

B<(optional)> When set, the network name is C<name_prefix . target> rather
than C<name_for('net', target)>.

=item C<dynamic_subnets>, C<greedy_subnets>, C<subnets>

For OCFP strategies, one of these keys must be present. Its value is a
hashref describing the allocation model (subnets filter, allocation counts,
cloud properties, etc.).

=back

=back

B<Returns:> A network definition hashref (with at minimum C<name> and C<type>
keys), or an empty list if the strategy/environment combination does not
apply (e.g., OCFP strategy requested on a non-OCFP environment).

B<Errors:>

=over 4

=item C<"Network definition strategy %s is not supported by the cloud config hook">

Thrown when C<strategy> names a method that does not exist on the class.
C<%s> is the unsupported strategy name.

=back

B<Examples:>

    my $net = $self->network_definition('deployment',
        strategy       => 'ocfp',
        dynamic_subnets => {
            subnets    => undef,
            allocation => { size => 64, statics => 8 },
            cloud_properties_for_iaas => { aws => { subnet => 'subnet-abc' } },
        },
    );
    # Returns: { name => 'my-env.bosh.net-deployment', type => 'manual', subnets => [...] }

=head2 network

    my $network_data = $self->network;

Returns the BOSH director network data hashref, loading it lazily from
director exodus if not already cached on the object.

B<Returns:> A hashref containing C<azs>, C<subnets>, and related BOSH
director network information.

B<Examples:>

    my $net = $self->network;
    # Returns: { azs => { z1 => {...} }, subnets => { 'ocfp-a' => {...} } }

=head2 update_network

    $self->update_network($target, \%config, %options);

Updates the internal network data to record IP allocation claims made by
C<$target>. Clears any pre-existing claims for the network before recording
new ones. Skips claim recording for greedy networks (those with the
C<greedy_subnets> option set).

Claims are keyed by the network name that reaches the cloud config, which
is C<< $config->{name} >>, falling back to C<name_for('net', $target)>. The
two differ whenever a kit passes a C<name_prefix> to C<network_definition>,
including an empty one. Releases before this keyed the claim by the
C<name_for> form regardless, so that key is cleared here as well and the
claim is rewritten under the real name. Both OCFP subnet models adopt a
claim found under either key as their own. Keying by C<name_for> alone
again would make a network's existing claim look foreign on the next
deploy: it would be subtracted from the available pool and requested a
second time, failing with C<"Not enough available IPs">.

B<Parameters:>

=over 4

=item C<$target>

The network target name, used for the fallback key and the legacy key.

=item C<\%config>

The network definition hashref produced by C<network_definition>. Its
C<name> is the claim key, and its C<subnets> array is iterated to extract
subnet names, ranges, and reserved ranges for allocation tracking.

=item C<%options>

If the C<greedy_subnets> key is present, claim recording is skipped.

=back

B<Returns:> Nothing (or early-returns for greedy networks).

B<Examples:>

    $self->update_network('deployment', $config);
    # Returns: nothing; records allocation claims for each subnet in $config->{subnets}

=head2 get_allocated_networks

    my $allocations = $self->get_allocated_networks;

Returns a hashref summarizing all current network allocation claims across all
subnets. The structure maps fully qualified network names to per-subnet
records containing the allocated IP range and availability zone.

B<Returns:> A hashref of the form:

    {
        'my-env.bosh.net-deployment' => {
            'ocfp-a' => { allocated => '10.0.1.0-10.0.1.63', az => 'z1' },
            'ocfp-b' => { allocated => '10.0.2.0-10.0.2.63', az => 'z2' },
        },
    }

B<Examples:>

    my $allocs = $self->get_allocated_networks;
    # Returns: { 'env.bosh.net-deployment' => { 'subnet-a' => { allocated => '...', az => 'z1' } } }

=head2 lookup_az

    my $az_name = $self->lookup_az($az);

Resolves an AZ identifier to the canonical AZ name used by BOSH. Searches by
exact key, by the C<name> field in the AZ definition, by the CPI-specific
AZ mapping if CPI is enabled, and by the short form C<zN> of the rendered
name. Returns the CPI-specific name when CPI is
enabled.

B<Parameters:>

=over 4

=item C<$az>

The AZ identifier to resolve (e.g., C<'z1'>, C<'us-east-1a'>).

=back

B<Returns:> The canonical AZ name string for use in subnet definitions.

B<Errors:>

=over 4

=item C<"No availability zones available; you may need to run a deploy on the %s BOSH director to update its network information.">

Thrown when the network data contains no AZs at all. C<%s> is replaced with
the BOSH director alias.

=item C<"Availability zone %s not found in the available AZs for the network">

Thrown when the given AZ identifier does not match any known AZ. C<%s> is
replaced with the C<$az> argument.

=back

B<Examples:>

    my $az_name = $self->lookup_az('z1');
    # Returns: 'us-east-1a'  (the canonical AZ name from BOSH director data)

=head2 az_cloud_properties

    my $cloud_properties = $self->az_cloud_properties($az);

Returns the decoded cloud properties of an availability zone from the BOSH
director network data. Resolves C<$az> the same way C<lookup_az> does, so
the AZ key, its rendered name, its CPI-specific name, and the short form
C<zN> all work. The director stores each AZ's cloud properties as a JSON
string; this decodes it into a fresh hashref on every call, so a kit may
extend the result without altering the shared network data.

Use this when a kit has to emit an AZ under a name a release hardcodes (a
bare C<z1>, for instance) but wants that AZ to carry the placement pins of
one of the director's own zones, such as a Proxmox C<target_node> or a
vSphere datacenter and cluster.

B<Parameters:>

=over 4

=item C<$az>

The AZ identifier to resolve (e.g., C<'z1'>, C<'my-env-z1'>, or the AZ key
from the OCFP config such as C<'pvea'>).

=back

B<Returns:> A hashref of the AZ's cloud properties, or an empty hashref when
the AZ defines none.

B<Errors:>

=over 4

=item C<"No availability zones available; you may need to run a deploy on the %s BOSH director to update its network information.">

Thrown when the network data contains no AZs at all. C<%s> is replaced with
the BOSH director alias.

=item C<"Availability zone %s not found in the available AZs for the network">

Thrown when the given AZ identifier does not match any known AZ. C<%s> is
replaced with the C<$az> argument.

=item C<"Invalid JSON in the cloud properties for availability zone %s: %s">

Thrown when the stored cloud properties cannot be decoded. The placeholders
are the C<$az> argument and the decoder's error.

=item C<"Cloud properties for availability zone %s must be a JSON object, got %s">

Thrown when the stored cloud properties decode to something other than a
JSON object. The placeholders are the C<$az> argument and the type found.

=back

B<Examples:>

    my $cloud_properties = $self->az_cloud_properties('z1');
    # Returns: { target_node => 'pvupvecf101' }  (on a Proxmox bloc)

=head2 _build_ocfp_network_model_dynamic_subnets

    $self->_build_ocfp_network_model_dynamic_subnets($target, $config, %options);

Builds an OCFP dynamic subnet network definition. Dynamically allocates IP
ranges for each OCFP subnet based on existing claims, total VM counts, and
static IP requirements. Supports Logical Subnet Amalgamation for subnets
sharing the same CIDR.

B<OCFP address-space convention>

Each subnet is split between the management environment and the OCFP
environment:

=over 4

=item C<*-mgmt>

Owns C<.0> through C<.31> of each subnet, with fixed offsets for the
core services:

  offset  service
  ------  -----------------------
  5th     bosh
  6th     vault
  7th     jumpbox
  8th     concourse web
  9th     prometheus
  10th    shield
  11th    doomsday / ocfp-ui
  rest    dynamic

=item C<*-ocfp>

Owns C<.32> through the last address of each subnet.

=back

The split is not inferred -- it is expressed in the OCFP config, per
subnet:

=over 4

=item C<< net.subnets.<subnet>.reserved-offsets >>

Offsets held back from allocation, e.g. C<'0-5,7-10'>.

=item C<< net.subnets.<subnet>.available-offsets >>

Offsets available for allocation, e.g. C<'12-254'> or C<'31-n'>, where
C<n> means the last address in the CIDR block. When omitted, everything
not reserved is assumed available -- which is usually B<not> what you
want.

=back

Only one of the two is strictly required, but both are supported and
supplying both is clearer. Older OCFP configurations rooted these under
C<vpc.> rather than C<net.>; both paths are still honoured for backwards
compatibility.

Subnets themselves are read from vault, under

  /secrets/{params.ocfp_config_path}.{env-name}/{mgmt|ocfp}/bosh/iaas/subnets/<name>/<id>

with the reserved list at C<< ...ips.[mgmt|ocfp].reserved >>.

B<Logical Subnet Amalgamation>

BOSH does not permit two subnets with the same range. When the OCFP
config produces subnets that do share a range, they are combined into a
single subnet and each contributing subnet's static IPs are allocated
from that shared range, with the reserved ranges recomputed to match.

Amalgamated subnets must also share a gateway; their DNS servers are
merged into a single de-duplicated list. AZ calculation has to account
for the join as well, and cannot distinguish by subnet id -- the subnet
id is ignored and only the network id is used.

B<The pool a network slices from>

For each subnet the model starts from the B<band>, which is the subnet's
available range with the subnet-reserved range removed, captured before
anything else is taken out. The free pool is the band minus every other
network's claim on the subnet, minus every other target's reserved-ips
record (see L</_all_reserved_ip_records>), and minus this target's own
records (see L</_get_reserved_allocation>). Dynamic addresses come only from
that pool, so a network never takes an address that another target's
reserved-ips record names.

B<Counting own records>

This target's own records that sit inside the band count toward its size.
A network that asks for 15 addresses on a band where it owns one record
slices 14 dynamic addresses. Own records outside the band, such as a
director's C<bosh_ip> in the subnet-reserved range, do not count.

B<Repairing a saved claim>

The saved claim for this network is read from the director's network
exodus, and these steps run in order.

=over 4

=item 1.

The subnet-reserved range is removed from it.

=item 2.

If another target's record sits inside it, the build stops with the PRUNE
error from L</_prune_claim_of_reserved_records>, because dropping the
address could move a VM that holds it. A BOSH director's compilation
network (target C<compilation> built by a
C<Genesis::Hook::CloudConfig::Director> hook) drops those addresses with a
warning instead, because compilation VMs exist only during a deploy. Any
network named in the comma-separated C<GENESIS_ALLOW_CLAIM_PRUNE>
environment variable drops them with the same warning, so an operator can
accept one prune for one run after checking C<bosh vms>.

=item 3.

This target's own records are removed from it, because they are handled
separately.

=item 4.

If what is left still overlaps another network's claim, the build stops
with the CLASH error from L</_bail_on_claim_clash>, because no reserved-ips
record says which network is right.

=back

The claim then grows from the free pool, or shrinks from its high end, to
the dynamic count (see L</_calculate_subnet_allocation>).

B<Statics>

Statics are taken from the claim as stored, which is the allocated dynamic
addresses together with this target's own in-band records, sliced from the
front the way earlier releases sliced them. A network whose own record sits
among its statics therefore keeps the same static addresses it had before
this check existed. The own records are then added to the statics or to the
allocated range, according to the target's C<_static> flag.

B<When another network holds an own record>

The owner of a reserved-ips record wins. The network keeps its record, and
L</_warn_own_records_in_other_claims> warns that the other network still
claims the address and names the command that rebuilds it. The other
network gives the address up the next time its cloud config is built.

B<Parameters:>

=over 4

=item C<$target>

The network target name.

=item C<$config>

The partial network config hashref. Populated in-place with a C<subnets> array.

=item C<%options>

Must contain C<dynamic_subnets>, a hashref with:

=over 4

=item C<subnets>

B<(optional)> A subnet filter passed to C<_filter_subnets>.

=item C<allocation>

A hashref specifying allocation sizes via one of:

=over 4

=item C<total_size>

Total VM count distributed evenly across subnets.

=item C<vms_per_subnet>

A hashref mapping subnet names to individual counts.

=item C<size>

A fixed count per subnet (or a CIDR mask like C<'/26'>).

=back

=item C<statics>

B<(optional)> Static IPs per subnet, taken from the front of the subnet's
allocation: a count, a CIDR mask (C<'/30'>), or a percentage of the
subnet's allocation (C<'25%'>). Defaults to 0.

=item C<cloud_properties_for_iaas>

B<(optional)> IaaS-specific cloud properties for subnets.

=back

=back

B<Returns:> C<1> on success.

B<Errors:>

=over 4

=item C<"No ocfp-* subnets found in the ocfp configuration for network %s">

Thrown when no OCFP-prefixed subnets exist. C<%s> is the target name.

=item C<"More static IPs requested (%d) than the allocation for the %s subnet for network %s allows (%d)">

Thrown when static count exceeds subnet allocation.

=item C<"Network %s on subnet %s has %s in its saved claim, but those addresses are reserved-ips records for %s. ...">

The PRUNE error, thrown when a saved claim holds another target's

=item C<"Network %s and network %s both claim %s on subnet %s, and no reserved-ips record names an owner for those addresses. ...">

=item C<"Not enough available IPs in the subnet for the network '%s' allocation:  (has %d, needs %d)">

Thrown when the free pool cannot satisfy the network's growth. See

=back

B<Examples:>

=head2 _add_extended_cloud_config

    $self->_add_extended_cloud_config(\%config);

Reads the C<bosh-configs.cloud> environment overrides and appends any defined
VM types, disk types, VM extensions, or network entries to C<%config>.
Supports C<< <based-on> >> inheritance (deep-merging from an existing entry)
and deferred processing to resolve ordering dependencies. Network additions
are not currently supported and will throw.

A source named by C<< <based-on> >> may be a kit entry already in C<%config>
or another extended entry in the same group. In the second case the target
is put back at the end of the queue and retried once its source has been
built, so a chain of extended entries resolves whatever order the group's
keys come out in. Before deferring, the C<< <based-on> >> chain is walked
through the group, and a name met twice is reported as a cycle; a single
"already deferred" flag cannot do this, since a chain of three visited in the
wrong order is deferred twice without being cyclic. Each definition is
processed on a copy, because C<lookup> returns the environment's own
structure and removing the meta-keys from it would leave a deferred target,
or a second build in the same process, with no C<< <based-on> >> to follow.

An override is an addition only when nothing in C<%config> already carries
its name. A kit may register an entry under the bare target name rather
than the C<name_for> form (C<network_definition> with an empty
C<name_prefix> does this for names a release hardcodes), so an entry named
either C<name_for($prefix, $target)> or C<$target> counts as present.
Matching on the prefixed form alone would turn such an override into a
second entry under the bare name.

B<Parameters:>

=over 4

=item C<\%config>

The cloud config hashref to extend. Modified in-place.

=back

B<Returns:> The modified C<\%config> hashref.

B<Errors:>

=over 4

=item C<"Invalid cloud config definition '#R{%s}' in #C{%s} environment file">

Thrown when an override group key is not a recognized plural type name.
C<%s> are the group key and environment name.

=item C<"Extended cloud config network definitions are not supported yet: '%s' in #C{%s} environment file">

Thrown when a network entry is found in the extended config. C<%s> are the
target name and environment name.

=item C<"Cyclic dependency detected for target '%s' in extended cloud config for type '%s'">

=head2 _subnet_definition

B<Errors:>

=head2 _evaluate_matching_rule

    my $properties = $self->_evaluate_matching_rule($target, \%rule, $config);

Evaluates a single conditional override rule against the current config.
Conditions are evaluated as OR between condition sets and AND within each set.
Patterns may be literal values, C<undef>, or regex strings in the form
C<"/pattern/flags"> or C<"!~/pattern/flags">, and a field may carry a list of
patterns, any one of which satisfies that field.

A condition's field names a key of the flattened config exactly, so a nested
property is written with dots, C<cloud_properties.instance_type>, an element
of a list property with its index, C<cloud_properties.security_groups[0]>,
and a property whose own name contains a dot with the C<~> that C<flatten>
substitutes for it. The field is read from the flat config directly rather
than resolved as a path, which is what lets a dotted key and a list of
patterns work; a nested map as a condition value is refused rather than
silently failing to match.

B<Parameters:>

=over 4

=item C<$target>

The resource target name (used as context, not directly evaluated).

=item C<\%rule>

A hashref with a C<conditions> arrayref (sets of field-pattern maps) and a
C<properties> hashref.

=item C<$config>

The flattened resource config hashref to evaluate against.

=back

B<Returns:> The rule's C<properties> hashref if conditions match, or C<{}>.

B<Errors:>

=over 4

=item C<"Matching rule condition for %s must name a flattened config key, not a nested map; write it as %s.<subkey>">

Thrown when a condition's value is a hashref. Both placeholders are the
field name.

=back

B<Examples:>

    my $props = $self->_evaluate_matching_rule('default', $rule, $config);
    # Returns: { disk_size => 10240 }  (if the rule conditions matched)

=head2 _calculate_subnet_allocation

    my $range = $self->_calculate_subnet_allocation(
        $target, $available, $existing, $count
    );

the existing allocation to reach C<$count> IPs. When growing, it adds the
lowest addresses of the free pool that the existing claim does not already
hold, so a claim can grow below its current start as well as above its end.
When shrinking, it removes addresses from the high end of the existing
claim.

The caller has already repaired C<$existing> before passing it in. It holds
no other target's reserved-ips record, none of this target's own records,
and nothing another network claims, so this method trusts it as it is.

B<Parameters:>

=over 4

=item C<$target>

Network target name (used in error messages).

=item C<$available>

An C<IPv4> range object of the free pool, which is the band minus other
networks' claims and minus every reserved-ips record on the subnet.

=item C<$existing>

An C<IPv4> range object of the network's repaired saved claim.

=item C<$count>

The desired total IP count.

=back

B<Returns:> A simplified C<IPv4> range object of the new allocation.

B<Errors:>

=over 4

=item C<"The allocation for network '%s' must not be negative (got %d)">

Thrown when C<$count> is below zero. Without this check a negative count
would read as a shrink and release the whole claim.

=item C<"Not enough available IPs in the subnet for the network '%s' allocation:  (has %d, needs %d)">

Thrown when the free pool, less the addresses the existing claim already
holds, cannot satisfy the growth request. The "has" figure is the size of
the free pool.

=back

B<Examples:>

    my $range = $self->_calculate_subnet_allocation('deployment', $available, $existing, 64);
    # Returns: IPv4 range object of 64 IPs

=head2 _calculate_static_allocation

    my $range = $self->_calculate_static_allocation(

=back

=head2 _get_reserved_allocation

    my ($allocation, $static) = $self->_get_reserved_allocation($target, \%subnet);

Retrieves the pre-reserved IPs for a named network target within a subnet,
read from C<< $subnet->{'reserved-ips'} >>. Also returns the static flag
C<< ${target}_static >> (defaults to C<1>).

A target declares its reservation in one of two spellings, never both:

=over 4

=item C<< ${target}_a >>, C<< ${target}_b >> (and C<_c>, C<_d>, ...)

A B<range>, given as B<exclusive> bounds: the addresses either side of what
is being reserved. C<< bosh_a >> of C<.63> with C<< bosh_b >> of C<.65>
yields the single address C<.64>.

=item C<< ${target}_ip >>

A B<single> address. Keys sharing that prefix (C<< ${target}_ip_smoke >>,
say) name further single addresses belonging to the same target.

=back

The C<_ip> match is anchored at the start of the key, so a key belongs to a
target only when it begins with that target's name: C<< ocfp_bosh_ip >> is
C<ocfp_bosh>'s address and is never claimed by C<bosh>. Unanchored, a
neighbouring target's reservation would be absorbed into this target's
static range.

C<< ${target}_ip_a >> and its siblings are neither spelling. The bracket-pair
loop looks for C<< ${target}_a >> and so never sees them, which leaves them
to the C<_ip> match, where they would silently widen the allocation. They are
excluded and reported instead.

The records are read for the target and for each of its aliases, in the
order L</_reserved_ip_targets> returns them. For each spelling, the first
name in that order with a record of that spelling supplies it.

The C<dynamic_subnets> model reads these own records once per subnet and
uses them three ways. It removes them from the free pool and from the saved
claim, counts the ones inside the band toward the network's size, and adds
them back to the statics or the allocated range afterwards. A record's
owner keeps it even when another network's claim also holds it (see
L</_warn_own_records_in_other_claims>).

B<Parameters:>

=over 4

=item C<$target>

Network target name.

=item C<\%subnet>

A subnet definition hashref with a C<reserved-ips> entry.

=back

B<Returns:> A two-element list C<($allocation, $static)> where C<$allocation>
is a simplified C<IPv4> range object and C<$static> is the static flag value.

B<Examples:>

    my ($reserved_ips, $is_static) = $self->_get_reserved_allocation('bosh', $subnet);
    # Returns: (IPv4 range of bosh-reserved IPs, 1)

=head2 _is_neighbour_annotation

    my $bool = _is_neighbour_annotation($key, $value, $anchor);

Returns true when a C<< <target>_ip_<suffix> >> key records the address
immediately before or after C<< <target>_ip >>. Plain function, not a method
-- no invocant.

An OCFP carve written under C<scheme_version> 2 stores the neighbouring
address on either side of a single reservation, C<_a> for the one below
C<< <target>_ip >> and C<_b> for the one above, so that a densely packed run
carries its own context. Those keys are left out of the allocation because
the address belongs to whichever target sits beside this one, but they are
deliberate rather than malformed, so
L</_get_reserved_allocation> uses this to tell them from a key it should
warn about. Every bloc writes the shape, so warning on it would fire on
every lookup.

B<Parameters:>

=over 4

=item C<$key>

The reservation key being examined, such as C<bosh_ip_a>.

=item C<$value>

The address that key holds.

=item C<$anchor>

The address held by the C<< <target>_ip >> the suffix sits beside.

=back

B<Returns:> A boolean. False unless the key ends in C<_ip_a> or C<_ip_b>,
both addresses are defined and parseable, and the value is adjacent to the
anchor on the side the suffix names.

B<Errors:> None. An unparseable address is caught and reported as false, so
a malformed value falls through to the caller's warning rather than dying.

B<Limitations:> Only C<_a> and C<_b> are recognised, and only at a distance
of exactly one address. A carve that annotated a neighbour two addresses out,
or used another letter, would be reported as malformed.

B<Examples:>

    # bosh_ip is 10.8.0.5; _a holds its predecessor
    my $bool = _is_neighbour_annotation('bosh_ip_a', '10.8.0.4', '10.8.0.5');
    # Returns: 1

    # the wrong side for the suffix
    my $bool = _is_neighbour_annotation('bosh_ip_a', '10.8.0.6', '10.8.0.5');
    # Returns: 0

    # not an annotation at all
    my $bool = _is_neighbour_annotation('bosh_ip_a', '10.8.0.40', '10.8.0.5');
    # Returns: 0

=head2 _all_reserved_ip_records

    my $by_owner = $self->_all_reserved_ip_records(\%subnet, $target);

target that owns them, leaving out C<$target> and its aliases (see
L</_reserved_ip_targets>). With C<$target> undefined, it returns every
owner. The C<dynamic_subnets> model uses the result to keep other targets'
addresses out of a network's free pool and saved claim, and to name the
owner in its messages.

Keys in C<< $subnet->{'reserved-ips'} >> are read as follows.

=over 4

=item C<< <owner>_ip >>

An address owned by C<< <owner> >>.  The value can be a single address, a
comma list, a dash range, or a CIDR.  Whitespace around the value, around the
dash of a range, and around the commas of a list is ignored, so
C<10.0.0.5 - 10.0.0.9> is the whole range.  The same goes for the values of the
C<< <owner>_a >> and C<< <owner>_b >> bounds.

=item C<< <owner>_ip_<word> >>, C<< <owner>_ips >>, C<< <owner>_ip2 >>

More addresses of C<< <owner> >>, as for C<< <owner>_ip >>.  The key does not
say where the owner's name ends, so the split uses the owners that other keys
name beyond doubt, which are C<< <owner>_ip >>, C<< <owner>_ip_a >>,
C<< <owner>_ip_b >>, C<< <owner>_a >>, and the target being asked about.  The
longest of those that the key starts with is its owner, so
C<my_ipsec_ip_smoke> goes to C<my_ipsec> when C<my_ipsec_ip> is present.  When
no such key names an owner, the key splits at its first C<_ip>, and
C<my_ipsec_ip_smoke> alone goes to C<my>.  Name the owner with its own
C<< <owner>_ip >> or C<< <owner>_a >> key to avoid that.

=item C<< <owner>_a >>, C<< <owner>_b >> (and C<_c>, C<_d>, ...)

Exclusive bounds, so each pair names the addresses strictly between them.
Bounds that are adjacent, equal, or reversed name nothing, so the pair gives
an empty range and its owner holds nothing from it.  An unpaired trailing
bound is ignored.  The pair is a pair even when the owner's name holds C<_ip>,
so C<my_ipsec_a> and C<my_ipsec_b> bound a range for C<my_ipsec>.

=item C<director_ip> and a bare C<ip>

The director's address, owned by C<bosh>, because both name it on every
3-compact band.

=item Skipped keys

C<reserved*> and C<available*> keys, C<scheme_version>, C<*_static> flags
(including C<< <owner>_ip_static >>, which is a flag and never an address),
and the scheme 2 neighbour annotations C<< <owner>_ip_a >> and
C<< <owner>_ip_b >>. Values that are not made of addresses are skipped too.

=back

B<Parameters:>

=over 4

=item C<\%subnet>

A subnet definition hashref with an optional C<reserved-ips> entry.

=item C<$target>

B<(optional)> The asking network's target, whose own records and its
aliases' records are left out.

=back

B<Returns:> A hashref mapping each owning target to an C<IPv4> range of its
addresses. Owners with no addresses are not included.

B<Examples:>

    my $by_owner = $self->_all_reserved_ip_records($subnet, 'compilation');
    # Returns: { haproxy => IPv4 range 10.61.148.229, bosh => IPv4 range 10.61.148.194 }

=head2 _parse_reserved_ip_records

    my $by_owner = _parse_reserved_ip_records(\%reserved_ips, known => \@owners);

Reads a subnet's reserved-ips records into one entry per owner. Plain
function, not a method -- no invocant. L</_get_reserved_allocation> and
L</_all_reserved_ip_records> both read through it, so the two can never
disagree about which keys name an address. The key forms are the ones
listed under L</_all_reserved_ip_records>, including C<director_ip> and a
bare C<ip>, which belong to C<bosh>.

B<Parameters:>

=over 4

=item C<\%reserved_ips>

The C<reserved-ips> hashref of a subnet.

=item C<known>

B<(optional)> An array reference of owner names the caller is certain of,
such as the asking target and its aliases.  They join the owners that the keys
name, to settle which owner a suffixed key such as C<< <owner>_ip_smoke >>
belongs to, as described under L</_all_reserved_ip_records>.

=back

B<Returns:> A hashref mapping each owner to a hashref with C<ranges> and
C<ips> (C<IPv4> ranges of the addresses its range pairs and its single
address keys name), C<malformed> (its C<< <owner>_ip_<suffix> >> keys), and
C<anchor> (the value of C<< <owner>_ip >>, or undef).

B<Examples:>

    my $by_owner = _parse_reserved_ip_records({bosh_a => '10.0.0.1', bosh_b => '10.0.0.6', director_ip => '10.0.0.9'});
    # $by_owner->{bosh}{ranges} is 10.0.0.2-10.0.0.5, {ips} is 10.0.0.9

=head2 _prune_claim_of_reserved_records

    $self->_prune_claim_of_reserved_records(
        $target, $network_id, $subnet_name, $existing, \%other_records_by_owner
    );

Checks a network's saved claim for addresses that another target's
reserved-ips records name. When there are none, it returns quietly. When
there are some, it either warns that the claim will drop them, or stops the
build, depending on the network.

It warns, and lets the caller drop the addresses, when the network is a BOSH
director's compilation network (target C<compilation> built by a
C<Genesis::Hook::CloudConfig::Director> hook), because compilation VMs exist
only during a deploy. It also warns when C<$network_id> appears in the
comma-separated C<GENESIS_ALLOW_CLAIM_PRUNE> environment variable, which lets
an operator accept one prune for one run after checking C<bosh vms>. Every
other network stops, because dropping the addresses would move any VM that
holds one.

The caller removes the addresses from the claim afterwards. This method only
decides whether that is allowed.

B<Parameters:>

=over 4

=item C<$target>

Network target name.

=item C<$network_id>

The full network name, such as C<ocfp-cf1-lab-ocf.cf.net-ocf>, which is
what C<GENESIS_ALLOW_CLAIM_PRUNE> is matched against.

=item C<$subnet_name>

Subnet name, for the messages.

=item C<$existing>

An C<IPv4> range of the saved claim, with the subnet-reserved range already
removed.

=item C<\%other_records_by_owner>

Other targets' records by owner, as L</_all_reserved_ip_records> returns
them.

=back

B<Returns:> Nothing meaningful.

B<Errors:>

=over 4

=item C<"Network %s on subnet %s has %s in its saved claim, but those addresses are reserved-ips records for %s. ...">

The PRUNE error. The placeholders are the network, the subnet, the
addresses, and each owner with its addresses. The message goes on to say
that nothing changed, that the claim was probably saved by a Genesis build
that did not check reserved addresses or that the record was written after
the claim, and that the operator should check with C<bosh vms> that no VM on
the network holds those addresses and then re-run with
C<GENESIS_ALLOW_CLAIM_PRUNE> set to the network name for that one run.

=back

B<Examples:>

    $self->_prune_claim_of_reserved_records(
        'compilation', 'lab-ocf.bosh.net-compilation', 'ocfp-2', $existing, $others
    );
    # Returns: nothing; warns that 10.61.148.229 leaves the compilation claim

=head2 _bail_on_claim_clash

    $self->_bail_on_claim_clash(
        $network_id, $subnet_name, $existing, \%other_claims_by_network
    );

Stops the build when a network's repaired saved claim still overlaps another
network's claim on the same subnet. By this point both reserved-ips records
and own records have been removed from the claim, so an overlap means two
dynamic claims hold the same addresses and nothing says which is right.

B<Parameters:>

=over 4

=item C<$network_id>

The full name of the network being built.

=item C<$subnet_name>

Subnet name, for the message.

=item C<$existing>

An C<IPv4> range of the repaired saved claim.

=item C<\%other_claims_by_network>

Every other network's claim on the subnet, keyed by network name.

=back

B<Returns:> Nothing meaningful.

B<Errors:>

=over 4

=item C<"Network %s and network %s both claim %s on subnet %s, and no reserved-ips record names an owner for those addresses. ...">

The CLASH error. The placeholders are this network, the other network, the
shared addresses, and the subnet. The message goes on to say that neither
claim changed, that two deploys probably saved claims without holding the
network claims lock or the director's network exodus was edited by hand,
and that the operator should find the right owner with C<bosh vms>, remove
the wrong claim from the director's exodus C<network> record, and run
again.

=back

B<Examples:>

    $self->_bail_on_claim_clash('lab.cf.net-ocf', 'ocfp-0', $existing, $other_claims);
    # Returns: nothing when the claims are disjoint

=head2 _warn_own_records_in_other_claims

    $self->_warn_own_records_in_other_claims(
        $target, $network_id, $subnet_name, \%subnet, $own_records,
        \%other_claims_by_network
    );

Warns once for each other network whose claim holds one of this target's own
reserved-ips records. The record's owner wins, so this network keeps the
address, and the warning says that both networks list it until the other one
is rebuilt. It names the record's owner, and when an alias owns the record it
names the alias as well as the target, as in C<haproxy (target 'ocf')>. When
the other network is a director's compilation network, named
C<< <env>.<type>.net-compilation >>, the warning gives the exact
C<genesis bosh-configs upload --type cloud --name E<lt>envE<gt>.E<lt>typeE<gt>.director -y>
command that rebuilds it. Otherwise it says to rebuild the cloud config of
the deployment that owns the other network.

B<Parameters:>

=over 4

=item C<$target>

Network target name.

=item C<$network_id>

The full name of the network being built.

=item C<$subnet_name>

Subnet name, for the message.

=item C<\%subnet>

The subnet definition, used to find which alias owns a record.

=item C<$own_records>

An C<IPv4> range of this target's own records on the subnet.

=item C<\%other_claims_by_network>

Every other network's claim on the subnet, keyed by network name.

=back

B<Returns:> Nothing meaningful.

B<Examples:>

    $self->_warn_own_records_in_other_claims(
        'ocf', 'lab-ocf.cf.net-ocf', 'ocfp-2', $subnet, $own, $other_claims
    );
    # Warns: Address 10.61.148.229 on subnet ocfp-2 is a reserved-ips record for
    #        haproxy (target 'ocf'), so network lab-ocf.cf.net-ocf keeps it, but
    #        network lab-ocf.bosh.net-compilation also claims it. ...

=head2 _build_logical_subnet_amalgamation

    my $lsa = $self->_build_logical_subnet_amalgamation($target, \@subnet_configs);

Merges multiple subnet definitions sharing the same CIDR range into a single
Logical Subnet Amalgamation (LSA) hashref. Validates that all subnets have
the same range and gateway, deduplicates AZs and DNS servers, and calculates
merged reserved and static ranges. Returns C<undef> if all IPs in the range
are reserved.

A child carries either a single C<az> or an C<azs> list, depending on which
branch of C<_subnet_definition> built it, and the merged C<azs> is the union
of whichever each child has. Reading C<az> alone contributes an C<undef>
for a child built through the C<azs> branch.

Cloud properties are taken from the first child by sorted name once every
child has been shown to agree, and an empty hash is left off the result
rather than emitted, matching what C<_subnet_definition> does when the IaaS
branch resolves to nothing.

B<Parameters:>

=over 4

=item C<$target>

Network name (used in error context).

=item C<\@subnet_configs>

Arrayref of subnet hashrefs, each with C<name>, C<range>, C<gateway>,
C<az>/C<azs>, C<dns>, C<reserved>, and optionally C<static> and
C<cloud_properties>.

=back

B<Returns:> An LSA hashref, or the single input subnet if only one is given,
or C<undef> if the range is fully reserved.

B<Errors:>

=over 4

=item C<"Cannot create LSA for subnets with different ranges:\n%s">

Thrown when input subnets have different CIDR ranges.

=item C<"Cannot create LSA for subnets with different gateways:\n%s">

Thrown when input subnets have different gateways.

=item C<"Cannot create LSA for subnets with different cloud properties in network %s:\n%s\n...">

Thrown when the input subnets do not all carry the same cloud properties. A
BOSH subnet holds one C<cloud_properties> hash and applies it to every AZ in
the subnet, so subnets that disagree cannot be merged. The message lists each
differing flattened property key with the value each subnet carries for it,
and names the override path that can reconcile them.

=back

B<Examples:>

    my $lsa = $self->_build_logical_subnet_amalgamation('deployment', \@subnet_configs);
    # Returns: { range => '10.0.1.0/24', azs => ['z1','z2'], reserved => [...], ... }
