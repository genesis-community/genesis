=head1 NAME

Genesis::Env - A deployable environment in a Genesis deployment repository

=head1 SYNOPSIS

    use Genesis::Top;
    use Genesis::Env;

    my $top = Genesis::Top->new('.');

    # Load an existing environment
    my $env = Genesis::Env->load(
      top  => $top,
      name => 'us-west-1-preprod',
    );

    # Create a new environment (interactive)
    my $env = Genesis::Env->create(
       top  => $top,
       name => 'us-west-1-preprod',
       kit  => $top->local_kit_version('some-kit', 'latest'),
    );

    # Query environment properties
    print $env->name;             # us-west-1-preprod
    print $env->deployment_name;  # us-west-1-preprod-bosh
    print $env->type;             # bosh
    print $env->secrets_base;     # /secret/us/west/1/preprod/bosh/

    # Deploy
    $env->deploy(yes => 1);

=head1 DESCRIPTION

The Env class represents a single, deployable unit of YAML files in a
Genesis deployment repository / working directory, and wraps up all of the
core rules for dealing with the set as a whole.

To load an existing environment, all you need is the C<Genesis::Top> object
that represents the top of the deployment repository, and the name of the
environment you want:

    use Genesis::Top;
    use Genesis::Env;

    my $top = Genesis::Top->new('.');
    my $env = Genesis::Env->load(
      top  => $top,
      name => 'us-west-1-preprod',
    );

To create a new environment, you need a bit more information.  You also need
to be ready to run through interactive ask-the-user-questions mode, for
things like the C<new> hook:

    my $env = Genesis::Env->create(
       top  => $top,
       name => 'us-west-1-preprod',
       kit  => $top->local_kit_version('some-kit', 'latest'),
    );

You can also avail yourself of the C<new> constructor, which does a lot of
the validation, but won't access the environment files directly:

    my $env = Genesis::Env->new(
       top  => $top,
       name => 'us-west-1-preprod',
    );

=head1 CONSTRUCTORS

=head2 new(%opts)

    my $env = Genesis::Env->new(%opts);

Create a new Env object without making any assertions about the filesystem.
Usually, this is not the constructor you want.  Check out C<load> or
C<create> instead.

The following options are recognized:

=over 4

=item B<name> (required)

The name of your environment.  See L</NAME VALIDATION> for details on naming
requirements.

=item B<top> (required)

The C<Genesis::Top> object that represents the root working directory of the
deployments repository.  This is used to fetch things like deployment
configuration, kits, etc.

=item B<secrets_path>

A path in the Genesis Vault, under which secrets for this environment should
be stored.  Normally, you don't need to specify this.  When an environment
is loaded it will probably be overridden by the operator's C<genesis.secrets_path>
parameter.  Otherwise, Genesis can figure out the correct default value.

=back

Unrecognized options will be silently ignored.

B<Returns:> a blessed C<Genesis::Env> object.

B<Errors:>

=over 4

=item *

Calls C<bug("No '$_' specified in call to Genesis::Env->new!!")> if C<name> or C<top> is missing.

=item *

Calls C<bail("Bad environment name '$opts{name}': %s", $err)> if the name fails validation.

=item *

Calls C<bail("No deployment type specified in .genesis/config!\n")> if the repository has no deployment type.

=back

B<Examples:>

    my $env = Genesis::Env->new(
      top  => Genesis::Top->new('.'),
      name => 'us-east-1-sandbox',
    );
    # Returns a Genesis::Env object (kit not loaded, files not read)

=head2 load(%opts)

    my $env = Genesis::Env->load(%opts);

Create a new Env object by loading its definition from constituent YAML
files on-disk (by way of the given C<Genesis::Top> object).  If the given
environment cannot be loaded, this constructor calls C<bail>, so callers
that want to handle failures gracefully should wrap the call in C<eval>.

C<load> validates the environment file, checks for deprecated parameters
(C<kit.subkits>, C<params.genesis_version_min>, C<params.bosh>), normalizes
C<genesis.use_create_env> to a boolean, validates C<bosh-configs> keys,
checks Genesis version requirements, and loads the kit.

B<Parameters:>

=over 4

=item B<%opts>

Same options as for C<new>: C<name> (required) and C<top> (required).

=back

B<Returns:> a C<Genesis::Env> object with its kit loaded and parameters
parsed from the environment hierarchy.

B<Errors:>

=over 4

=item *

Calls C<bug("No '$_' specified in call to Genesis::Env->load!!")> if C<name> or C<top> is missing.

=item *

Bails with C<"Environment #C{%s} could not be loaded:\n[[- >>%s\n\nPlease fix the above errors and try again."> if validation fails.

=item *

Bails if the environment file fails C<is_valid_env_file> validation (file not found, missing C<genesis.env>, name mismatch, missing kit info).

=item *

Bails if C<kit.subkits> is present (deprecated, use C<kit.features>).

=item *

Bails if C<genesis.use_create_env> has an invalid value.

=item *

Bails if C<bosh-configs> contains unrecognised keys.

=item *

Bails if the Genesis version does not meet the environment or repository minimum.

=item *

Bails if the kit cannot be found.

=item *

Bails with C<"Cannot use the selected kit."> if kit prerequisites fail.

=back

B<Examples:>

    my $env = Genesis::Env->load(
      top  => Genesis::Top->new('.'),
      name => 'us-east-1-sandbox',
    );
    print $env->kit->id;
    # prints my-kit/1.2.3

=head2 exists

    my $bool = $env->exists;
    my $bool = Genesis::Env->exists(name => $name, top => $top);

Returns true (C<1>) if the environment exists on-disk and passes validation,
false otherwise.

When called as an instance method (C<$env->exists>), checks whether the
environment's YAML file exists.  When called as a class method
(C<Genesis::Env->exists(name =E<gt> ..., top =E<gt> ...)>), delegates to
C<is_valid_env_file> in scalar context.

B<Parameters:>

=over 4

=item B<%args>

When called as a class method, requires C<name> and C<top> keys.
When called as an instance method, no arguments are needed.

=back

B<Returns:> boolean.

B<Errors:>

=over 4

=item *

Calls C<bug("%s::exists called without name and/or top named arguments", __PACKAGE__)> if called as a class method without the required arguments.

=back

B<Examples:>

    if (Genesis::Env->exists(name => 'us-east-1-sandbox', top => $top)) {
      my $env = Genesis::Env->load(name => 'us-east-1-sandbox', top => $top);
    }
    # prints 1 if exists

=head2 create(%opts)

    my $env = Genesis::Env->create(%opts);

Create a new Env object by running the user through the wizardly setup of
the C<hooks/new> kit hook.  This often cannot be run unattended and
definitely cannot be run without access to the Genesis Vault.

If the named environment already exists on-disk, C<create> throws an error
and dies.  After the C<new> hook runs, C<create> reloads the environment
using C<load> and then calls C<add_secrets>.  If secrets generation fails,
the environment file is removed and C<undef> is returned.

C<create> recognizes the following options, in addition to those recognized
by and required by C<new>:

=over 4

=item B<kit> (required)

A C<Genesis::Kit> object for provisioning this environment.

=item B<vault>

A vault target alias or descriptor URL.

=item B<create-env>

Boolean.  Force or prevent use of C<bosh create-env> deployment method.

=item B<secrets_mount>

The Vault mount point for secrets (default: C</secrets/>).

=item B<exodus_mount>

The Vault mount point for exodus data (default: C<$secrets_mount/exodus>).

=item B<ci_mount>

The Vault mount point for CI secrets (default: C<$secrets_mount/ci>).

=item B<secrets_path>

Override the path under C<secrets_mount> for environment secrets.

=item B<root_ca_path>

Path to a common root CA for signing otherwise self-signed certificates.

=item B<credhub_env>

Environment that provides the CredHub login credentials.

=back

B<Returns:> a C<Genesis::Env> object on success, or C<undef> if secrets
generation fails.

B<Errors:>

=over 4

=item *

Calls C<bug("No '$_' specified in call to Genesis::Env->create!!")> if C<name>, C<top>, or C<kit> is missing.

=item *

Dies with C<"Environment file $env->{file} already exists.\n"> if the environment file already exists.

=item *

Bails with C<"Cannot find a vault target with alias '$opts{vault}'"> if the vault alias cannot be resolved.

=item *

Bails with C<"No vault specified or configured."> if no vault is available.

=item *

Bails with C<"Cannot continue with existing secrets for this environment"> if existing secrets cannot be removed.

=item *

Bails with C<"Could not move existing ... to ...: ..."> when an existing environment file cannot be moved aside.

=item *

Bails with C<"Cannot specify a bosh environment for environments that use create-env deployment method."> when a BOSH environment is named for a create-env deployment.

=item *

Bails with C<< "Kit ... requires use of create-env, but --no-create-env option was specified" >>, C<< "Kit ... cannot use create-env, but --create-env option was specified" >>, or C<< "Kit ... does not support the --[no-]create-env option" >> when the requested create-env mode conflicts with what the kit supports.

=item *

Bails with C<"Kit %s is not supported in Genesis %s (no hooks/new script).  Check for a newer version of this kit."> if the kit lacks the C<new> hook.

=back

B<Examples:>

    my $env = Genesis::Env->create(
      top  => $top,
      name => 'us-east-1-sandbox',
      kit  => $top->local_kit_version('bosh', 'latest'),
    );
    # Returns undef if secrets generation fails; Genesis::Env otherwise

=head1 CLASS FUNCTIONS

=head2 from_envvars

    my $env = Genesis::Env->from_envvars($top);

Builds a pseudo-environment object from the current process's environment
variables.  This is only valid during a C<new> kit hook callback, where
Genesis populates the process environment with serialized environment state.

B<Parameters:>

=over 4

=item B<$top>

A C<Genesis::Top> object for the deployment repository.

=back

B<Returns:> a C<Genesis::Env> object populated from environment variables
rather than YAML files.

B<Errors:>

=over 4

=item *

Bails with C<"Can only assemble environment from environment variables in a kit hook callback"> if called outside a C<new> hook callback.

=item *

Calls C<bug("No 'GENESIS_$_' found in enviornmental variables - cannot assemble environemnt!!")> if C<GENESIS_ENVIRONMENT>, C<GENESIS_KIT_NAME>, C<GENESIS_KIT_VERSION>, or C<GENESIS_ENVIRONMENT_PARAMS> is missing.

=item *

Bails with C<"Unable to locate ... kit for ... environment."> when the kit named by the environment variables cannot be found.

=item *

Bails with C<<< "Environment `...` requires Genesis v... or higher." >>> when the environment declares a minimum Genesis version newer than the running one.

=item *

Bails with C<< "Kit #M{...} is not compatible with #C{secrets_mount} feature" >> or the corresponding C<exodus_mount> message when the kit predates the mount feature the environment uses.

=item *

Bails with C<"No vault specified or configured."> when no Vault target is available.

=back

B<Examples:>

    # Inside a hooks/new script called by Genesis:
    my $env = Genesis::Env->from_envvars($top);
    print $env->name;
    # prints us-east-1-sandbox

=head2 is_valid_env_file

    # List context: (1) on success or (undef, @errors) on failure
    my ($ok, @errors) = Genesis::Env->is_valid_env_file($name, $top);

    # Scalar context: truthy on success, falsy on failure
    my $ok = Genesis::Env->is_valid_env_file($name, $top);

Validates an environment file without fully instantiating a C<Genesis::Env>
object.  Results are cached by absolute file path.

Checks performed in order: name validity, file existence, presence of a
single matching C<genesis.env> declaration, and kit name/version availability
in the file hierarchy.

B<Parameters:>

=over 4

=item B<$name>

The environment name (C<.yml> suffix is stripped automatically).

=item B<$top>

A C<Genesis::Top> object identifying the deployment root.

=back

B<Returns:> In list context, C<(1)> on success or C<(undef, @errors)> on
failure.  In scalar context, truthy on success or C<undef> on failure.

B<Errors:>

=over 4

=item *

Calls C<bug("No 'top' specified in call to is_valid_env_file!!")> if C<$top> is not provided.

=back

B<Examples:>

    my ($ok, @errs) = Genesis::Env->is_valid_env_file('us-east-1-sandbox', $top);
    if (!$ok) {
      print "Invalid: $_\n" for @errs;
    }
    # prints (no output when environment is valid)

=head2 search_for_env_file

    my ($deployment_root, $file_path) =
      Genesis::Env->search_for_env_file($env_pattern, $deployment_type);

Searches for an environment YAML file matching C<$env_pattern> across known
deployment roots (current directory, parent directory, and roots configured
in C<.genesis/config>).

B<Parameters:>

=over 4

=item B<$env>

The environment name or glob pattern.  C<^> and C<$> anchors are stripped
and the value is wrapped in C<*> wildcards.  Pass C<'*'> to match all.

=item B<$deployment>

Optional deployment type to restrict the search.  When omitted, only C<bosh>
and C<bosh-deployments> directories are searched.

=back

B<Returns:> a two-element list C<($deployment_root, $file_path)>.  If
multiple files match and a terminal is available, prompts the user to choose.

B<Errors:>

=over 4

=item *

Bails with C<"No environment files found matching #C{%s}"> if no files match.

=item *

Bails with C<"Ambiguous environment name: #C{%s} matches multiple files:\n  - %s\n\nPlease refine your match criteria."> if multiple files match and no terminal is available.

=item *

Bails with C<"No environment file selected."> if the user cancels the interactive prompt.

=back

B<Examples:>

    my ($root, $file) =
      Genesis::Env->search_for_env_file('us-east-1-sandbox', 'bosh');
    # Returns: ('/path/to/bosh-deployments', '/path/to/bosh-deployments/us-east-1-sandbox.yml')

=head1 METHODS

=head2 name

    my $name = $env->name;

Returns the bare environment name (without the C<.yml> file suffix).

B<Returns:> string.

B<Examples:>

    my $env = Genesis::Env->load(top => $top, name => 'us-west-1-preprod');
    print $env->name;
    # prints us-west-1-preprod

=head2 file

    my $filename = $env->file;

Returns the environment file name (the environment name with a C<.yml>
suffix appended).

B<Returns:> string.

B<Examples:>

    print $env->file;
    # prints us-west-1-preprod.yml

=head2 kit

    my $kit = $env->kit;

Returns the C<Genesis::Kit> object for this environment.

B<Returns:> L<Genesis::Kit> object.

B<Errors:>

=over 4

=item *

Calls C<bug("Incompletely initialized environment '...': no kit specified")> when the environment was not built through C<load> or C<create>.

=back

B<Examples:>

    my $kit = $env->kit;
    print $kit->id;
    # prints bosh/2.0.1

=head2 top

    my $top = $env->top;

Returns the C<Genesis::Top> object representing the deployment repository
root directory for this environment.

B<Returns:> L<Genesis::Top> object.

B<Errors:>

=over 4

=item *

Calls C<bug("Incompletely initialized environment '...': no top specified")> when the environment was not built through C<load> or C<create>.

=back

B<Examples:>

    my $top = $env->top;
    print $top->path;
    # prints /home/user/deployments

=head2 type

    my $type = $env->type;

Returns the deployment type for this environment (e.g. C<bosh>,
C<concourse>, C<cf>).  Delegates to C<< $env->top->type >>.

B<Returns:> string.

=head2 path

    my $abs = $env->path;
    my $abs = $env->path($relative);

Returns the absolute path to the deployment repository root directory.
If C<$relative> is given, it is appended to the root path.
Delegates to C<< $env->top->path >>.

B<Returns:> string (absolute filesystem path).

B<Examples:>

    print $env->path;
    # prints /home/user/deployments/bosh

    print $env->path('us-west-1-preprod.yml');
    # prints /home/user/deployments/bosh/us-west-1-preprod.yml

=head2 signature

    my $sig = $env->signature;

Returns a unique 12-character hexadecimal identifier for this environment,
derived from a SHA-1 hash of the environment name, type, file path, and
file contents.  The result is memoized.

B<Returns:> string (12 hex characters).

B<Examples:>

    print $env->signature;
    # prints a1b2c3d4e5f6

=head2 deployment_name

    my $dep = $env->deployment_name;

Returns the BOSH deployment name for this environment, constructed as
C<E<lt>env-nameE<gt>-E<lt>typeE<gt>> (e.g. C<us-west-1-preprod-bosh>).
The result is memoized.

B<Returns:> string.

B<Examples:>

    print $env->deployment_name;
    # prints us-west-1-preprod-bosh

=head2 manifest_store

    my $store = $env->manifest_store;

Returns the manifest storage strategy for this environment: C<'exodus'>,
C<'hybrid'>, or C<'repository'>.  Environments that do not specify a
C<genesis.minimum_version> of 3.1.0 or higher always return C<'repository'>
because older Genesis versions cannot update exodus deployment audit data.

B<Returns:> string (C<'exodus'>, C<'hybrid'>, or C<'repository'>).

B<Examples:>

    print $env->manifest_store;
    # prints hybrid

=head2 effective_minimum_version

    my $version = $env->effective_minimum_version;

Returns the higher of the environment's declared minimum
(C<genesis.min_version> / C<genesis.minimum_version>) and the repository's
(C<minimum_version> in the repo config), with any leading C<v> stripped.

Feature gates consult this single floor rather than either value alone, so a
low environment minimum cannot artificially disable kit features that the
higher repository minimum already guarantees, and vice versa.

The result is memoized.

B<Returns:> A version string; C<'0.0.0'> when neither side declares one.

B<Examples:>

    print $env->effective_minimum_version;
    # prints 3.2.0

=head2 effective_minimum_version_source

    my $source = $env->effective_minimum_version_source;

Returns which side contributed L</effective_minimum_version>: C<'environment'>
or C<'repository'>.

The result is memoized.

B<Returns:> C<'environment'>, C<'repository'>, or C<undef> when neither side
declares a minimum.

B<Examples:>

    print $env->effective_minimum_version_source;
    # prints repository

B<Limitations:> When both sides declare the same version the tie resolves to
C<'repository'>, on the grounds that it is the broader scope.  The value is
therefore not sufficient to tell whether the environment also declared a
minimum -- only which one is being enforced.

=head2 deployment_state

    my $state = $env->deployment_state;

Returns the current deployment state of this environment.  Deprecated --
use C<< $env->deployments->current_state >> instead.

B<Returns:> string (e.g. C<'deployed'>, C<'undeployed'>, C<'terminated'>).

B<Examples:>

    print $env->deployment_state;
    # prints deployed

=head2 is_bosh_director

    my $bool = $env->is_bosh_director;

Returns true if the kit used by this environment provides the C<director>
service, indicating this is a BOSH director deployment.

B<Returns:> boolean.

B<Examples:>

    print $env->is_bosh_director ? 'yes' : 'no';
    # prints yes

=head2 stemcell_os

    my $os = $env->stemcell_os;

Returns the operating system this environment's stemcells run, or C<undef>
when nothing declares one. It reads C<bosh-configs.stemcells.os> from the
environment file first, then the first entry of the manifest's C<stemcells>
block, and then, on a create-env manifest, the director's own stemcell under
C<resource_pools>, resolving a C<((stemcell_url))> style reference through the
manifest's C<bosh-variables>. It never guesses a distribution.

B<Returns:> string such as C<ubuntu-noble>, or C<undef>.

B<Examples:>

    my $os = $env->stemcell_os
      // bail("Set bosh-configs.stemcells.os in %s", $env->name);

=head2 use_create_env

    my $bool = $env->use_create_env;

Returns true if this environment must be deployed via C<bosh create-env>
rather than C<bosh deploy>.  While memoization is in progress (circular
evaluation), returns the string C<'unknown'> as a sentinel.

B<Returns:> C<1>, C<0>, or C<'unknown'> during circular evaluation.

B<Examples:>

    if ($env->use_create_env) {
      print "uses bosh create-env\n";
    }
    # prints uses bosh create-env

=head2 can_build_cloud_configs

    my $bool = $env->can_build_cloud_configs;

Returns true if this environment supports building cloud configs (requires
feature compatibility with 3.1.0-rc.9 and C<genesis.manage-cloud-configs>
not set to false).

B<Returns:> boolean.

B<Examples:>

    print $env->can_build_cloud_configs ? 'yes' : 'no';
    # prints yes

=head2 minimum_genesis_version

    my $version = $env->minimum_genesis_version;

Returns the effective minimum Genesis version required by this environment,
determined by comparing the environment's C<genesis.min_version> parameter
against the repository's configured minimum.  Returns C<'0.0.0'> if no
minimum is specified.  The result is memoized.

B<Returns:> version string (e.g. C<'2.8.0'>).

B<Examples:>

    print $env->minimum_genesis_version;
    # prints 2.8.0

=head2 feature_compatibility

    my $bool = $env->feature_compatibility($version);

Returns true if the effective minimum Genesis version for this environment
meets or exceeds C<$version>.

B<Parameters:>

=over 4

=item B<$version>

A version string to test against (e.g. C<'3.0.0'>).

=back

B<Returns:> boolean.

B<Examples:>

    if ($env->feature_compatibility('3.0.0')) {
      print "supports 3.0.0 features\n";
    }
    # prints supports 3.0.0 features

=head2 validate_genesis_version_requirements

    my $result = $env->validate_genesis_version_requirements;

Checks the environment's declared minimum Genesis version against the
running Genesis binary and the repository's minimum version, returning a
hashref with keys: C<errors>, C<warnings>, C<effective_minimum>,
C<running_version>, and C<source>.

B<Returns:> hashref.

B<Examples:>

    my $r = $env->validate_genesis_version_requirements;
    print $r->{effective_minimum};
    # prints 2.8.0

=head2 get_call_path

    my $bin = $env->get_call_path;

Returns the path to the Genesis binary as it would appear in user-facing
output.  The result is memoized.

B<Returns:> string.

B<Examples:>

    print $env->get_call_path;
    # prints /usr/local/bin/genesis

=head2 get_call_path_with_env

    my $cmd    = $env->get_call_path_with_env;
    my ($bin, $env_ref) = $env->get_call_path_with_env;

Returns a string (in scalar context) or two-element list (in list context)
of the Genesis binary path and environment reference, suitable for use in
user-facing messages.

B<Returns:> string or two-element list C<($bin, $env_ref)>.

B<Examples:>

    my $cmd = $env->get_call_path_with_env;
    print $cmd;
    # prints /usr/local/bin/genesis us-west-1-preprod

=head2 workpath($relative)

    my $dir  = $env->workpath;
    my $path = $env->workpath('manifest.yml');

Returns a temporary working directory path for this environment.  If
C<$relative> is given, it is appended to the temporary root.

B<Parameters:>

=over 4

=item B<$relative>

Optional relative path to append.

=back

B<Returns:> string path.

B<Examples:>

    my $dir = $env->workpath;
    print -d $dir ? 'exists' : 'missing';

=head2 potential_environment_files

    my @files = $env->potential_environment_files;

Assembles the list of candidate YAML files that could comprise this
environment by calling C<relate> with no other environment.  If
C<PREVIOUS_ENV> is set, files shared with that environment are taken from
C<.genesis/cached/$env> instead of the top level.

B<Returns:> list of file path strings.

B<Examples:>

    my @files = $env->potential_environment_files;
    print scalar(@files), " candidate files\n";
    # prints 4 candidate files

=head2 actual_environment_files

    my @files = $env->actual_environment_files;

Returns the subset of C<potential_environment_files> that actually exist on
disk, including any files explicitly inherited via C<genesis.inherits>
directives.  The C<$seen> parameter is an internal recursion guard and
should not be passed by callers.  The result is memoized.

B<Returns:> list of file path strings.

B<Examples:>

    my @files = $env->actual_environment_files;
    print "$_\n" for @files;
    # prints ./us.yml
    #         ./us-west-1.yml
    #         ./us-west-1-preprod.yml

=head2 relate($them, [$common_base, [$unique_base]])

    my @files  = $env->relate($them, $common_base, $unique_base);
    my $struct = $env->relate('us-west-1-prod', '.cache', 'NEW');

Relates this environment to another environment and returns the set of
possible YAML files that comprise the environment.  In list context returns
a flat list (common files first, then unique).  In scalar context returns a
hashref with C<common> and C<unique> arrayrefs.

B<Parameters:>

=over 4

=head2 instance_group_azs

    my @azs = $env->instance_group_azs;

Returns the sorted, deduped list of AZ names appearing across every
C<instance_groups[].azs> list in the environment's merged manifest.  Returns
an empty list when there are no instance groups, or when none of them declare
any AZs.  Non-hash entries in C<instance_groups> are filtered; groups with a
missing or empty C<azs:> key are skipped.

B<Returns:> list of strings (sorted, unique).

B<Bails> when any AZ value is an unresolved spruce operator -- that is, a
whole value matching C<(( ... ))>.  The merged manifest is produced without
C<--skip-eval>, so a surviving operator means the fully-evaluated invariant
has been broken and downstream AZ/CPI resolution would run on unreliable
data.  The most common cause is a spruce operator placed inside the C<value:>
block of a go-patch ops document: Genesis merges with
C<spruce merge --multi-doc --go-patch>, and spruce applies go-patch documents
verbatim without evaluating operators inside them, so the marker survives.
An unresolved C<(( grab ))> (missing target) or C<(( vault ))> (vault
unreachable at merge time) arrives by the same route.

Filtering the marker instead of bailing would be actively harmful: an
unconsumed C<(( replace ))> means the AZ entries it was meant to drop are
still present alongside the intended replacement, so silently removing the
marker leaves corrupted data behind and destroys the evidence.

B<Errors:>

=over 4

=item *

Bails with C<< "Unresolved spruce operator(s) in #C{instance_groups.*.azs}: ..." >> when an AZ value still contains an unevaluated spruce operator.

=back

B<Examples:>

    my @azs = $env->instance_group_azs;
    # returns ('z1', 'z2', 'z3')

B<Limitations:>

=over

=item *

The guard anchors on the whole value, so a partially-interpolated AZ name
such as C<"z1-(( grab x ))"> is not detected.  Spruce operators are
whole-value by design, so this is not expected in practice.

=item *

The bail names the offending value and the anti-pattern, but cannot identify
I<which> ops file introduced it -- the merged manifest carries no provenance.
Callers must trace it back through the blueprint's merge order.

=back

=head2 prefetch_configs

    my @configs = $env->prefetch_configs(@hooks);

Everything L</required_configs> returns, plus C<cpi> for hooks that build
toward a deployable manifest (blueprint, check, manifest, pre-deploy,
post-deploy).  Drives what gets downloaded and displayed, never what gets
gated on.

Fetching cpi up front surfaces the whole director inventory in the
"Downloading configs from..." block rather than having cpi fetches happen
implicitly later inside the CPI checks.  C<download_configs> treats cpi as
always-optional, so a director with none uploaded simply no-ops.

B<Returns:> list of config type strings.

B<Limitations:> Keeping this distinct from L</required_configs> is
load-bearing, not stylistic.  While the two were one method, C<cpi> was
effectively required, C<has_config('cpi')> could never become true on a
single-iaas director, and manifest viability checking was silently skipped on
every deploy against such a director.

    # returns ('cloud', 'cpi') -- cloud required, cpi opportunistic

    my @configs = $env->prefetch_configs('cloud-config');
    # returns () -- the kit signalled a skip, so cpi is not appended

=head2 config_file

    my $path = $env->config_file($type, $name);

Returns the path of the registered config file for the given type and
optional name, or an empty string if none is registered.

B<Parameters:>

=over 4

=item B<$type>

Config type.

=item B<$name>

Optional config name.

=back

B<Returns:> string (path or empty string).

The path is looked up in two places, in order: the overlay a prior caller
registered through L</use_config> -- normally via L</download_configs> -- and
then C<GENESIS_E<lt>TYPEE<gt>_CONFIG[_NAME]> in the environment, which an
enclosing C<< genesis -> shell >> call sets.

B<Examples:>

    print $env->config_file('cloud') || 'none';
    # prints /tmp/cloud.yml

B<Limitations:>

The empty-string return is a fragile contract, and L</has_config> and
L</config_contents> delegate here and inherit it.

When neither lookup finds anything the method returns C<''> rather than
signalling that nothing was registered.  A caller reading that as "no config"
degrades silently; one that feeds it to a spruce merge -- L</_cc_yaml_files>
does -- fails at merge time with a file-not-found error that points at the
merge rather than at the missing download.

This is latent rather than live: L</download_configs> always calls
L</use_config> on success, so every current path into C<config_file> has

the overlay nor the environment has anything, which needs a config-file getter
on the director so its cache can be consulted first; or quietly fall back to
that cache as a third layer, which is lower friction but hides the
missing-download bug class entirely.

=head2 prepare_branch

creates the branch from the current commit when it does not yet exist, adds

when that environment is introduced.

=item *

=head2 _ensure_vault_ready_for_exodus

    my $ready = $env->_ensure_vault_ready_for_exodus($noprompt);

Confirms the Vault can record exodus data after a successful deploy, failing
fast when it cannot.

How it recovers a Vault that is not ready depends on what the deploy just did
to it.

=over 4

=item *

When this deployment runs the secrets Vault as a cluster of more than one
node, which L</_pre_deploy> records with L</_secrets_vault_cluster_nodes>, any
status other than C<ok> hands over to L</_unseal_secrets_vault_cluster>. That
method unseals every node through its own address and then waits, within a
bound, for the cluster to elect an active node. Without Strongbox, a
single-target C<safe unseal> is never used on such a cluster, because it opens
one node, and one node of a Raft cluster cannot elect a leader alone. Once
standby reads are disabled, nothing authenticated works until a leader
exists. With Strongbox on, C<safe unseal> walks every node itself, so it
still goes first, and the cluster pass runs only if the Vault is not ready
afterwards.

=item *

Otherwise a sealed Vault gets one C<safe unseal> attempt, exactly as before.
This covers a single-node self-hosted provider, such as the BOSH kit's
openbao feature, when it comes back sealed after its own VM is recreated.

=back

If the Vault is still unusable and no operator can answer a prompt, this bails
rather than letting a downstream C<safe> call block indefinitely on an
interactive authentication prompt. No unseal key appears in anything this
prints.

B<Parameters:>

=over 4

=item C<$noprompt>

When true, treat the situation as unattended even within a controlling
terminal.

=back

B<Returns:> C<1> when the Vault is ready; C<0> when it is not but an operator is
present to be prompted.

B<Errors:>

=over 4

=item *

Calls C<bail("The deployment itself succeeded, but the vault is %s, so the exodus data for this deployment cannot be recorded, and no terminal is available to answer a vault authentication prompt.")> when the Vault is unusable and C<$noprompt> is set or no controlling terminal exists.  The deployment is already up, so the guidance is to restore Vault access and re-run the deploy, which completes the exodus update.

=back

B<Examples:>

    my $ready = $env->_ensure_vault_ready_for_exodus(0);
    # Returns: 1 when the vault is reachable, unsealed, and authenticated

    # Redeploying a three-node OpenBao cluster that is its own secrets
    # provider, under --yes.  All three nodes come back sealed, all three
    # are unsealed, a leader is elected, and exodus can be written.
    my $ready = $env->_ensure_vault_ready_for_exodus(1);
    # Returns: 1

=head2 _deployment_may_affect_secrets_vault

    my $bool = $env->_deployment_may_affect_secrets_vault;

Returns true if this deployment may seal or disrupt the Vault being used
for secrets (e.g. if deploying a Vault kit with shared static IPs).

For a kit that provides the C<vault> service, it compares the manifest's
static IPs with the addresses from L</_secrets_vault_addresses>. Both sides
are in canonical form and static IP ranges are expanded, so a hostname
target, an IPv6 target, and a target in the middle of a range all match
their static IPs, and none of them can abort the deploy.
C<genesis.unseal_vault_after_deploy> overrides the check when it is set.

B<Returns:> boolean.

=head2 _secrets_vault_addresses

    my %port_for = $env->_secrets_vault_addresses;

Lists every address the secrets Vault answers on, with the port it answers on
there. C<safe status> lists every node with its port when Strongbox is on, and
only the target otherwise, so the target URL always counts too. A port that
C<safe status> reports for a node wins over the target's port. Hostnames are
resolved with L</_resolve_host_addresses>, and every address is in canonical
form.

B<Returns:> A hash of canonical address to port, empty when nothing resolves.

=head2 _stop_renewer_for_self_deploy

    my $stopped = $env->_stop_renewer_for_self_deploy;

When the deployment would affect the secrets Vault (as detected by
L</_deployment_may_affect_secrets_vault>), stops the background token
renewer armed by L<Service::Vault::Remote/start_token_renewer>. The
renewer would otherwise issue periodic C<vault token renew> calls
against a half-deployed vault.

No explicit re-arm is needed: the next vault method that calls
L<Service::Vault::Remote/authenticate> picks up the renewer through
C<_on_auth_success>.

Defensive: only fires when the vault responds to
C<stop_token_renewer>. Vaults without it (e.g.
L<Service::Vault::Local> or bare mocks) are no-ops.

B<Returns:> C<1> when a renewer was stopped, C<0> otherwise.

=head2 _secrets_vault_cluster_nodes

    my @nodes = $env->_secrets_vault_cluster_nodes;

Finds the nodes of the secrets Vault when this deployment runs it. The Vault's
own addresses come from C<safe status>, which lists every node with its port
when Strongbox is on, and from the target URL, whose host is resolved when it
is a name. In each instance group, the network whose static IPs include one of
those addresses carries the API, and its static IPs are the nodes, one per
instance. Other networks on the same instances are ignored, and instance
groups that share no address are left out, so seal keys only ever go to the
Vault's own nodes. Static IPs may be IPv4 or IPv6 addresses, or IPv4 ranges.

When the manifest plainly holds a cluster that cannot be found, this warns
loudly rather than letting the deploy fall back in silence to unsealing the
targeted node alone. That happens when no static IP matches the Vault while
an instance group runs more than one instance, or when a matched group runs
more instances than it has static IPs.

It has to run before the deploy, while the Vault still answers, which is why
L</_pre_deploy> calls it and records the result.

B<Returns:> A list of nodes in manifest order, each an address and port such
as C<10.0.0.5:443> or C<[fd00::5]:8200>. The port is the one C<safe status>
reported for that node, or else the port of the matching address. The list
is empty when the kit does not provide the C<vault> service or no instance
group holds the Vault's address.

=head2 _recovered_create_env_state

    my $recovered = $env->_recovered_create_env_state();

Returns the state file, and the credentials store beside it, left behind by
the most recent C<create-env> deploy that failed.

C<bosh create-env> rewrites the state file as it works, so an attempt that
died partway still recorded what it had already changed on the IaaS: the VM it
deleted, the stemcell it uploaded, the persistent disk it created.  Genesis
archives that state with the failed deployment record, and it is newer than
anything the last successful deploy left behind, so the next attempt has to
build on it.  Starting again from the older state would have bosh delete a VM
that is already gone and upload a stemcell that is already there, orphaning
one stemcell template on the IaaS for every retry.

Repository-mode environments get an empty hashref, because a failed deploy
refreshes F<.genesis/manifests/> directly and the file on disk is already the
newest one.  So does an environment whose newest state came from a deploy that
succeeded, since nothing needs recovering there.

B<Returns:> a hashref with C<state>, C<store>, and C<timestamp> keys, or an
empty hashref when there is nothing to recover.  C<state> and C<store> are
paths to files extracted under the environment's work path.

B<Examples:>

    my $recovered = $env->_recovered_create_env_state();
    # returns {} when the last deploy succeeded
    # returns {state => '/path/to/env-state.json', ...} after a failed deploy
