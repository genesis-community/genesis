=encoding utf8

=head1 NAME

Genesis - Core utility functions for the Genesis deployment toolkit

=head1 SYNOPSIS

    use Genesis;

    # Initialise Genesis for the current run
    Genesis::Init();

    # Run an external command and capture output
    my ($out, $rc, $err) = run({ stderr => 0 }, 'spruce json "$1"', $file);

    # Parse and compare semantic versions
    my @parts = semver('1.2.3-rc.1');
    bail("Need genesis >= 2.0") unless new_enough($Genesis::VERSION, '2.0');

    # Navigate directories with a stack
    pushd('/some/path');
    # ... do work ...
    popd();

=head1 DESCRIPTION

C<Genesis> is the central utility library for the Genesis BOSH deployment
toolkit. It exports a large set of general-purpose functions that are used
throughout the codebase and in kit hooks. All functions are exported by
default via C<Exporter>.

Functions cover:

=over 4

=item * Initialisation and runtime environment setup (C<Init>)

=item * Logging and error reporting (C<bail>, C<bug>, C<logger>, and friends)

=item * External command execution (C<run>, C<curl>, C<lines>)

=item * Filesystem helpers (C<slurp>, C<mkfile_or_fail>, C<pushd>, etc.)

=item * Data manipulation (C<flatten>, C<unflatten>, C<deep_merge>, C<struct_lookup>, etc.)

=item * Semantic version handling (C<semver>, C<by_semver>, C<new_enough>)

=item * Time and duration formatting (C<strfuzzytime>, C<pretty_duration>)

=item * Array and string utilities (C<uniq>, C<in_array>, C<sentence_join>, etc.)

=item * Global configuration validation (C<validate_global_config>, C<global_config_schema>)

=back

The package also exports the constants C<EXODUS_TIME_FORMAT> and
C<EXODUS_TIME_FORMAT_SHORT> used when reading or writing Exodus deployment
metadata timestamps.

=head1 FUNCTIONS

=head2 Init

    Genesis::Init();
    Genesis::Init($version);

Initialises the Genesis runtime. Loads and validates the global configuration
file at C<~/.genesis/config>, configures logging, and populates a set of
C<GENESIS_*> environment variables that child processes and kit hooks depend on.

Must be called exactly once at process startup before any other Genesis
operations.

B<Parameters:>

=over 4

=item C<$version> (optional)

The version string to advertise as C<GENESIS_VERSION>. Defaults to
C<$Genesis::VERSION>.

=back

B<Returns:> nothing.

B<Examples:>

    Genesis::Init();        # Returns: nothing
    Genesis::Init('2.8.0'); # Returns: nothing

=head2 init_forked_child

    Genesis::init_forked_child();

Defensive setup run inside the child branch immediately after C<fork>
in any Genesis-spawned helper process (background token renewer,
future background workers).

The child is B<expected> to exit via C<POSIX::_exit> so Perl's C<END>
blocks and object destructors do not fire. C<init_forked_child> is
belt-and-suspenders for accidental C<exit> or unhandled C<die> paths
in the child's body, and for terminal contention with the parent.

What it does:

=over 4

=item *

Empties C<$Genesis::Commands::END_HOOKS> so any C<at_exit> callbacks
the parent registered before the fork do not run in the child.

=item *

Redirects C<STDIN> to C</dev/null> (rather than closing it) so the
child does not contend for the parent's terminal input, and so fd 0
stays bound to a benign source — a closed fd 0 can be reclaimed by
the next C<open> in the child and silently land on something else.

=item *

Installs C<$SIG{TERM}>, C<$SIG{INT}>, and C<$SIG{HUP}> handlers that
exit via C<POSIX::_exit(0)>, so signal-driven termination also
bypasses C<END> and C<DESTROY>.

=back

What it does B<not> need to do:

=over 4

=item *

Clear the C<Service::Vault> singleton cache.
C<Service::Vault::Local::shutdown> already self-guards by comparing
the encoded parent PID against C<$$>, so a child running its
C<DESTROY> chain is a no-op rather than killing the parent's C<safe>
process.

=back

B<Parameters:> None.

B<Returns:> nothing.

B<Examples:>

    my $pid = fork();
    die "fork failed: $!" unless defined $pid;
    if ($pid == 0) {
        Genesis::init_forked_child();
        # ... renewer / worker body ...
        POSIX::_exit(0);
    }

=head2 deployment_roots_map

    my ($labels_ref, $roots_ref) = Genesis::deployment_roots_map(@extras);
    my $map = Genesis::deployment_roots_map(@extras);

Reads the C<deployment_roots> list from the global Genesis configuration,
expands each path (tilde and environment-variable expansion, then
C<abs_path> resolution), and assigns human-readable labels. Optional
C<@extras> entries (array-references of C<[$label, $path]>) are merged in.

In list context returns a two-element list: an array reference of label
strings in order, and a hash reference mapping label to absolute path. In
scalar context returns a hash reference with keys C<labels> (array ref) and
C<roots> (hash ref).

B<Parameters:>

=over 4

=item C<@extras> (optional)

Zero or more C<[$label, $path]> array references representing additional
deployment roots to include. Paths are expanded before comparison.

=back

B<Returns:>

In list context: C<(\@labels, \%roots)>.

In scalar context: C<{ labels => \@labels, roots => \%roots }>.

B<Errors:>

=over 4

=item C<"Deployment root labels cannot start with a '\@' character.  This is reserved for Genesis internal use.  Please check your configuration file or GENSIS_DEPLOYMENT_ROOTS environment variable.">

Raised when a labelled root uses a label starting with C<@>.

=item C<"Duplicate deployment root label '%s' found">

Raised when two roots resolve to the same label. C<%s> is the duplicate label.

=back

B<Examples:>

    # list context
    my ($labels, $roots) = Genesis::deployment_roots_map();
    for my $label (@$labels) {
        printf "%s => %s\n", $label, $roots->{$label};
        # prints: staging => /home/user/deployments/staging
    }

    # scalar context
    my $map = Genesis::deployment_roots_map([staging => '~/deployments/staging']);
    # Returns: { labels => ['staging'], roots => { staging => '/home/user/deployments/staging' } }

=head2 expand_path

    my $abs = expand_path($path);
    my $abs = expand_path($path, $base_path);

Expands C<$path> into an absolute path by:

=over 4

=item 1. Substituting leading C<~> or C<~username> with the home directory.

=item 2. Expanding C<$VAR> and C<${VAR}> environment-variable references.

=item 3. Resolving the result to an absolute, symlink-free path, optionally
relative to C<$base_path>.

=back

Returns C<undef> if C<$path> is undefined.

B<Parameters:>

=over 4

=item C<$path>

The path to expand. May contain C<~>, C<~user>, or C<$VAR>/C<${VAR}>
sequences.

=item C<$base_path> (optional)

If supplied, the working directory is temporarily changed to C<$base_path>
before resolving the path, so relative paths are interpreted from there.

=back

B<Returns:> The expanded absolute path string, or C<undef> if C<$path> is
undefined.

B<Errors:>

=over 4

=item C<"Unknown user '$1' in path expansion">

Raised when a C<~username> expansion cannot find the named user. C<$1> is
the username.

=item C<"Environment variable '%s' is not set in path %s">

Raised when a C<$VAR> reference in the path refers to an unset variable.
C<%s> (first) is the variable name; C<%s> (second) is the partially expanded
path.

=back

B<Examples:>

    my $path = expand_path('~/deployments');
    # Returns: '/home/user/deployments'

    my $path = expand_path('$GENESIS_LIB/kits', '/tmp');
    # Returns: absolute path to kits under $GENESIS_LIB, resolved from /tmp

=head2 absolute_path

    my $abs = absolute_path($path);
    my $abs = absolute_path($path, $base_path);

Legacy alias for C<expand_path>. Accepts and returns the same arguments.

B<Returns:> The result of C<expand_path(@_)>.

B<Examples:>

    my $abs = absolute_path('~/foo');
    # Returns: '/home/user/foo'

=head2 logger

=head2 deprecation

    deprecation($fmt, @args);

Dispatches a deprecation notice: a WARNING-level message tagged with the
C<deprecation> context and labelled C<DEPRECATED>.

B<Use this rather than C<warning> for anything deprecation-related.> The
context tag is what lets a log target suppress deprecation notices
independently of other warnings -- a console can stay quiet about them while
file logs keep them for auditing. A plain C<warning> cannot be filtered that
way.

Code B<inside> C<Genesis::Log> must not call this: it would route back
through the logger it is part of. That code calls the singleton's C<warning>
with the context option directly instead.

B<Parameters:>

=over 4

=item C<$fmt>

A C<sprintf>-style format string. C<csprintf>-style color codes are
supported.

=item C<@args> (optional)

Arguments interpolated into C<$fmt>.

=back

B<Returns:> Nothing.

B<Examples:>

    deprecation("Template '%s' uses the implicit form; use '%s'", $old, $new);
    # prints a DEPRECATED-labelled warning, suppressible by context

=head2 bail

    bail($fmt, @args);
    bail(\%opts, $fmt, @args);

Formats a FATAL-level error message and exits the process. When called inside
an active C<eval> block (and C<GENESIS_IGNORE_EVAL> is not set), C<bail>
C<die>s instead of exiting; the die string begins with C<"\n"> followed by
the formatted message.

Multiple leading hash-reference arguments may be passed; their keys are
merged, with C<offset> values summed.

B<Parameters:>

=over 4

=item C<\%opts> [, C<$more_options>, ...] (optional)

One or more hash references passed as leading arguments. Keys are merged
across all supplied hash references, with C<offset> values summed. Supported
keys:

=over 4

=item C<exitcode>

Integer exit code. Defaults to 1.

=item C<offset>

Stack-frame offset used when reporting the call site. Defaults to 0.

=back

=item C<$fmt>

A C<sprintf>-style format string for the error message.
C<csprintf>-style color codes are supported.

=item C<@args> (optional)

Arguments interpolated into C<$fmt>.

=back

B<Returns:> Does not return; exits the process (or C<die>s inside an active
C<eval> block).

B<Errors:>

When called inside an active C<eval> block and C<GENESIS_IGNORE_EVAL> is not
set, C<bail> throws an exception whose string begins with C<"\n"> followed by
the formatted message.

B<Examples:>

    bail("Need genesis >= 2.0") unless new_enough($Genesis::VERSION, '2.0');
    # prints: FATAL-level message to STDERR, then exits with code 1

    bail({exitcode => 2}, "Too many arguments: expected %d, got %d", $exp, $got);
    # prints: FATAL-level message to STDERR, then exits with code 2

=head2 bug

    bug($fmt, @args);
    bug(\%opts, $fmt, @args);

Prints a fatal error message that identifies the problem as a Genesis
internal bug, appends a stack trace, and requests the operator file a GitHub
issue. In an active C<eval> block it C<die>s rather than exiting.

In development builds (when C<$Genesis::VERSION> contains C<"dev">) an
additional note is printed asking the user to reproduce with an official
release before filing.

B<Parameters:>

=over 4

=item C<$more_options> (optional)

A hash reference (or multiple hash references, consumed with C<shift>) with
optional keys C<exitcode> (integer exit code, defaults to C<1>) and C<offset>
(stack offset for log attribution).

=item C<$fmt, @args>

A C<sprintf>-style format string and arguments.

=back

B<Returns:> Does not return (exits or dies).

B<Errors:>

When called inside an active C<eval> block (and C<GENESIS_IGNORE_EVAL> is not
set), C<bug> calls C<die> with a message starting with C<"\n"> followed by the
formatted bug report. This allows callers to catch it for cleanup. The die
message format is C<"\n"> followed by the formatted report.

B<Examples:>

    bug("Unexpected ref type '%s' in pipeline", ref($obj));
    # Returns: does not return -- exits process or dies in eval

=head2 workdir

    my $dir = workdir();
    my $dir = workdir($suffix);

Returns a temporary scratch directory that is automatically cleaned up when
the process exits.

When called without arguments (or with an empty C<$suffix>), returns a
freshly created temporary directory every call.

When called with a C<$suffix>, returns a stable directory for that suffix:
if one was already created (or is specified by the C<GENESIS_WORKDIR$SUFFIX>
environment variable), the same path is returned on subsequent calls.
The chosen path is also exported as C<GENESIS_WORKDIR$SUFFIX> so that child
processes inherit it.

B<Parameters:>

=over 4

=item C<$suffix> (optional)

A short name (upcased and prefixed with C<_>) that identifies a named work
directory. For example, C<workdir('spruce-diff')> uses the key
C<_SPRUCE-DIFF>.

=back

B<Returns:> An absolute path to the temporary directory.

B<Examples:>

    my $tmp = workdir();
    # Returns: '/tmp/.../tmp_XXXXXXXXXX'

    my $scratch = workdir('my-plugin');
    # Returns: '/tmp/.../tmp_XXXXXXXXXX' (same path on second call)

=head2 semver

    my $parts_ref = semver($v);
    my ($major, $minor, $patch, $rc) = semver($v);

Parses a semantic version string. Recognises formats such as C<1>,
C<1.2>, C<1.2.3>, and C<1.2.3-rc2> / C<1.2.3-rc.2> / C<1.2.3-rc-2>.

In scalar context returns an array reference C<[$major, $minor, $patch, $rc]>.
In list context returns the four components directly.

Missing components default to C<0>. Release-candidate numbers are stored as
C<$rc_number - 100000>, making them sort below their corresponding release.

Returns nothing (empty list or undef) if C<$v> does not match the expected
format.

B<Parameters:>

=over 4

=item C<$v>

The version string to parse. A leading C<v> is accepted (e.g., C<v1.2.3>).

=back

B<Returns:>

In list context: C<($major, $minor, $patch, $rc_offset)>.

In scalar context: C<[$major, $minor, $patch, $rc_offset]>, or C<undef> on
parse failure.

B<Examples:>

    my ($maj, $min, $pat, $rc) = semver('1.2.3-rc.2');
    # Returns: (1, 2, 3, -99998)

    my $parts = semver('2.0');
    # Returns: [2, 0, 0, 0]

    semver('not-a-version');
    # Returns: undef (scalar), () (list)

=head2 by_semver

    my @sorted = sort { by_semver($a, $b) } @versions;

Comparison function for sorting semantic version strings. Returns C<-1>,
C<0>, or C<1> following the convention of C<< <=> >> and C<cmp>. Release
candidates sort below their corresponding release (e.g., C<1.0.0-rc5> is
less than C<1.0.0>).

If either argument cannot be parsed as a semver, returns C<0>.

B<Parameters:>

=over 4

=item C<$a>

First version string.

=item C<$b>

Second version string.

=back

B<Returns:> C<-1>, C<0>, or C<1>.

B<Examples:>

    my @sorted = sort { by_semver($a, $b) } qw/2.0.0 1.9.0 2.0.0-rc1/;
    # Returns: ('1.9.0', '2.0.0-rc1', '2.0.0')

=head2 new_enough

    my $ok = new_enough($version, $minimum);

Returns true if C<$version> is semantically greater than or equal to
C<$minimum>. Returns false (C<0>) if either string fails to parse as a semver.

B<Parameters:>

=over 4

=item C<$version>

The version to test.

=item C<$minimum>

The required minimum version.

=back

B<Returns:> Boolean (true/false).

B<Examples:>

    new_enough('2.8.1', '2.0.0');  # Returns: 1

=head2 strfuzzytime

    my $fuzzy = strfuzzytime($datestring);
    my $fuzzy = strfuzzytime($datestring, $output_format);
    my $fuzzy = strfuzzytime($datestring, $output_format, $input_format);

Converts a date or duration into a human-readable natural-language
approximation such as C<"about 3 hours ago"> or C<"in about a week">.

The function supports two operating modes determined by C<$input_format>:

=over 4

=item * B<Time-point mode> (default): C<$datestring> is parsed as a timestamp
using C<$input_format> (default C<"%Y-%m-%d %H:%M:%S %z">). The returned
string is relative to the current time, e.g. C<"about 2 days ago">.

=item * B<Duration mode>: When C<$input_format> is C<'seconds'>, or when
C<$datestring> is a Time::Seconds object, the value is treated as an
elapsed duration rather than a point in time. The returned string describes
the duration itself, e.g. C<"about 5 minutes">.

=back

When C<$output_format> is provided it is used as a C<strftime>-style template
with the additional C<%~> atom that is replaced by the fuzzy string. Example:
C<"%Y-%m-%d (%~)"> might produce C<"2024-01-15 (about 2 months ago)">.

B<Parameters:>

=over 4

=item C<$datestring>

A timestamp string, a Time::Piece object, a Time::Seconds object, or
a plain integer number of seconds.

=item C<$output_format> (optional)

A C<strftime>-style format string. If it contains C<%~>, that placeholder is
replaced by the fuzzy description. Without C<$output_format>, only the fuzzy
string is returned.

=item C<$input_format> (optional)

The C<strptime> format for parsing C<$datestring>. Defaults to
C<"%Y-%m-%d %H:%M:%S %z">. Pass C<'seconds'> to treat the input as an elapsed
duration.

=back

B<Returns:> A human-readable string describing the time or duration.

B<Errors:>

=over 4

=item C<"Invalid input for 'seconds' format: %s">

Raised (via C<bug>) when C<$input_format> is C<'seconds'> but C<$datestring>
is not a Time::Seconds object, does not have a C<seconds> method, and is
not a plain integer. C<%s> is the ref type or the raw value.

=back

B<Examples:>

    my $fuzzy = strfuzzytime('2024-01-01 00:00:00 +0000');
    # Returns: 'about 1 year ago' (depending on current time)

    my $str = strfuzzytime('2024-01-01 00:00:00 +0000', 'Updated: %~');
    # Returns: 'Updated: about 1 year ago'

    my $dur = strfuzzytime(300, undef, 'seconds');
    # Returns: 'about 5 minutes'

=head2 run

    my ($out, $rc, $err) = run(\%opts, $command, @args);
    my $out               = run($command);

Executes a shell command and returns its output and exit code.

Three calling styles are supported:

    # 1. Single string with embedded arguments
    my ($out, $rc) = run("safe read a/b/c | spruce json");

    # 2. Pre-tokenized command and arguments
    my ($out, $rc) = run('spruce', 'merge', '--skip-eval', @files);

    # 3. Template string with positional arguments (recommended)
    my ($out, $rc, $err) = run('spruce merge "$1" - "$2" < "$3.yml"',
                                $file1, $file2, $file3);

Style 3 is recommended because it safely encapsulates arguments. References
to C<$1>, C<$2>, etc. in the command string are replaced with the
corresponding arguments before the shell sees them.

B<Parameters:>

=over 4

=item C<\%opts> (optional)

A hash reference controlling execution behaviour:

=over 4

=item C<interactive>

If true, runs the command with the C<system> call so that it shares the
terminal. Captured output is undefined.

=item C<passfail>

If true, returns C<1> (success) or C<0> (failure) rather than output.

=item C<onfailure>

A message string to C<bail> with if the command exits non-zero. The command's
stderr and stdout are appended to the message.

=item C<env>

A hash of environment variable names to values (or C<undef> to unset) that
are applied only for the duration of the command.

=item C<shell>

The shell to use. Defaults to C</bin/bash>.

=item C<stderr>

Controls stderr disposition. The default (C<'&1'>) merges stderr into stdout.
Pass C<undef> to let stderr reach the terminal unredirected. Pass C<0> to
capture stderr separately (returned as the third list element, or as the
scalar return value on non-zero exit).

Any B<other> value is used verbatim as the shell redirect target, so the
command is run as C<< 2>$value >>. That allows an explicit destination:

    run({stderr => '/dev/null'}, 'some-noisy-command')

A bare positive integer is the exception: it is read as the file descriptor
it plainly means, and coerced accordingly.

    run({stderr => 1},    ...)  # 2>&1 -- coerced, with a debug note
    run({stderr => '&1'}, ...)  # 2>&1 -- written explicitly

Without that coercion C<stderr =E<gt> 1> would render C<< 2>1 >> and write a
file called C<1> into the working directory instead of merging the streams.
It is a silent failure -- the command still succeeds and nothing reports the
stray file -- and it has happened in a shipped kit hook, whose output file
was committed to a deployment repository before anyone noticed.

The coercion is logged at debug rather than warned about: an operator running
a deploy cannot fix a hook's arguments, but whoever maintains that hook
should find it in the trace. Note that C<0> is B<not> coerced; it retains its
meaning above.

Prefer writing C<'&1'> explicitly. The coercion is a safety net for a mistake
that is otherwise invisible, not an idiom to rely on.

=item C<dir>

Change to this directory before executing the command.

=item C<stdin>

Redirect stdin for the command.

=item C<redact_output>

If true, suppresses output from trace/debug logs.

=item C<redact_stderr>

If true, keeps the command's captured stderr out of trace and debug logs, and
out of the C<onfailure> message, in the same way C<redact_output> does for its
output. The caller still receives the stderr unchanged.

=item C<redact_env>

If true, redacts environment variable values in trace/debug logs.

=item C<eval_var_args>

If true, expands environment variable references in C<@args> before the
command runs: C<$NAME> and C<${NAME}> are replaced with the variable's value,
and a name that is not set becomes the empty string. A backslash-escaped
C<\$> is left alone.

Off by default. Arguments are handed to the shell positionally, so they are
data rather than shell source, and expanding them unasked corrupts any value
containing a literal C<$> -- passwords and generated secrets especially. Turn
this on only where the caller genuinely wants its arguments treated as
templates, as the kit hook runners do for addon and reaction arguments.

    # $HOME is expanded and arrives as $1; $$ is left for the shell itself
    run({eval_var_args => 1}, 'echo "Home: $1, process: $$"', '$HOME');

=back

=item C<$command>

The command string, with optional C<$1>-style argument placeholders.

=item C<@args>

Positional arguments substituted into C<$command>'s C<$1>, C<$2>, ...
placeholders.

=back

B<Returns:>

In list context (default): C<($out, $rc, $err)>. C<$err> is defined only when
C<stderr => 0> was passed.

In scalar context: C<$out>, or C<$err> if the exit code is non-zero and stderr
was captured.

When C<passfail> is set: C<1> on success or C<''> (empty string) on failure.

When C<onfailure> is set and the command succeeds: the bare C<$out> scalar
(not a three-element list).

When C<interactive> is set: C<(undef, $rc)> in list context, C<$rc> in scalar.

Returns C<undef> in void context.

B<Errors:>

=over 4

=item C<"Could not open pipe to run #C{%s}">

Raised via C<bail> if the pipe to the child process cannot be opened. C<%s>
is the full command string.

=back

B<Examples:>

    # Capture stdout and exit code
    my ($out, $rc) = run('git log --oneline -5');
    # Returns: (git log output string, 0)

    # Separate stderr
    my ($out, $rc, $err) = run({ stderr => 0 }, 'spruce json "$1"', $file);
    # Returns: (json string, 0, '')

    # Bail on failure
    run({ onfailure => "git fetch failed" }, 'git fetch origin');
    # Returns: nothing (exits on failure)

=over 4

=item C<@args>

=back

    # Returns: "'bosh' 'attach-disk' 'web/0' 'disk-1|meta'"
    # A shell re-parsing this sees 4 words; the | is never a pipe.

=head2 fake_tty

    my @cmd = fake_tty($output_file, @cmd);

Wraps C<@cmd> in an OS-specific C<script> invocation so that the child
process believes it is running in a TTY. The output is also written to
C<$output_file>. Supports macOS (C<darwin>) and Linux.

B<Parameters:>

=over 4

=item C<$output_file>

The file path where C<script> will record the session output.

=item C<@cmd>

The command and arguments to run inside the fake TTY.

=back

B<Returns:> The modified command array ready to pass to C<run()>, a list of
separate arguments on both platforms. On Linux the subcommand is flattened
into a single C<script -c> argument via C<shell_quote>, so command values
containing shell metacharacters (pipes, semicolons, quotes) survive the
inner shell's re-parsing intact instead of being split or executed as
injected commands.

Both forms pass C<-e>, so C<script> exits with the wrapped command's exit
code.  macOS C<script> always does that and accepts C<-e> for compatibility.
util-linux C<script> exits 0 without it, whatever the command did, so
dropping C<-e> on Linux makes C<run()> report every wrapped command as a
success.  C<spruce_diff> depends on it with util-linux releases older than
2.35, which write no exit code trailer.

B<Examples:>

    my @cmd = fake_tty('/tmp/out.log', 'spruce', 'diff', $a, $b);
    # Returns (macOS): ('script', '-qeF', '/tmp/out.log', 'spruce', 'diff', $a, $b)
    # Returns (Linux): ('script', '-qef', '/tmp/out.log', '-c', "'spruce' 'diff' '$a' '$b'")
    run(@cmd);

=head2 spruce_diff

    my ($diff, $rc, $err) = spruce_diff($first, $second);

Runs C<spruce diff> against two YAML sources and returns the coloured diff
output, exit code, and any stderr.

The exit code is spruce's own on both platforms: 0 when the sources match, 1
when they differ, and 2 or higher when spruce could not compare them, in
which case the output holds spruce's error.  C<fake_tty> runs spruce under
C<script -e>, which passes the code through on both platforms.  On Linux the
C<[COMMAND_EXIT_CODE="N"]> trailer of the typescript records the code as
well, and the trailer's code is the one returned.  A trailer that carries a
reason instead of a code, such as C<< [<terminated by signal 15>] >>, is
reported as rc 2 or higher with the reason appended to the output.  The
typescript's header and trailer never appear in the returned output.

Call this rather than running C<spruce diff> under C<fake_tty> directly,
which leaves the typescript's header and trailer in the output and the
trailer's reason unread.

Each argument can be:

=over 4

=item * A file path string (must exist on disk).

=item * A hash reference with exactly one of:

=over 4

=item C<file> -- path to an existing file (plus an optional C<label> key).

=item C<object> -- a Perl data structure serialised to a temporary YAML file.

=item C<content> -- a YAML string written to a temporary file.

=back

=back

B<Parameters:>

=over 4

=item C<$first>

The first YAML source (file path or hash reference).

=item C<$second>

The second YAML source (file path or hash reference).

=back

B<Returns:> C<($diff_output, $rc, $err)>.

B<Errors:>

=over 4

=item C<"spruce diff requires two files">

Raised via C<bug> if called with other than exactly two arguments.

=item C<"Can only specify one of 'file', 'object', or 'content' in the %s argument hashref">

Raised via C<bug> when a hash-ref argument specifies more than one source key.
C<%s> is C<"first"> or C<"second">.

=item C<"%s argument hashref must contain a 'file', 'object', or 'content' key">

Raised via C<bug> when a hash-ref argument has none of the expected keys.
C<%s> is C<"first"> or C<"second">.

=item C<"Invalid %s argument type '%s', expected a file path, or a hashref with 'file', 'object', or 'content' key, or a string">

Raised via C<bug> when an argument is neither a file path nor a recognised hash
reference. C<%s> (first) is C<"first"> or C<"second">; C<%s> (second) is the

B<Examples:>

    #          (spruce's error, 2) when spruce cannot compare them

=head2 pretty_duration

    my $str = pretty_duration($duration);
    my $str = pretty_duration($duration, $good, $bad, $wrap, $prefix, $style, $force);

Formats a floating-point duration (in seconds) as a colourised human-readable
string such as C<"(1.2 s)"> or C<"[2 m 15 s]">. Returns the empty string
unless C<GENESIS_SHOW_DURATION> is set or C<$force> is true.

Durations are formatted with adaptive precision:

=over 4

=item * Under 1 ms -- microseconds (µs)

=item * Under 2 s -- milliseconds (ms)

=item * Under 10 s -- one decimal place in seconds

=item * Under 60 s -- whole seconds

=item * Under 1 hour -- minutes and seconds

=item * 1 hour or more -- hours and minutes

=back

B<Parameters:>

=over 4

=item C<$duration>

Elapsed time in seconds (floating-point).

=item C<$good> (optional)

If the duration is at or below this threshold, the output is green.

=item C<$bad> (optional)

If the duration is at or above this threshold, the output is red.

=item C<$wrap> (optional)

A two-character string whose first character is the opening bracket and last
is the closing bracket (e.g., C<'()'>, C<'[]'>). Defaults to C<'()'>.

=item C<$prefix> (optional)

A string prepended before the opening bracket. Defaults to C<' '>.

=item C<$style> (optional)

A C<csprintf> color code applied to the brackets and prefix. Defaults to
C<'-'> (plain).

=item C<$force> (optional)

If true, output is produced even when C<GENESIS_SHOW_DURATION> is not set.

=back

B<Returns:> A colourised duration string, or the empty string.

B<Examples:>

    pretty_duration(0.5, undef, undef, '()', ' ', '-', 1);
    # Returns: ' (500 ms)'

    pretty_duration(125, 60, 300, '[]', ' took ', 'b', 1);
    # Returns: ' took [2 m 5 s]' (coloured red when over $bad threshold)

=head2 count_nouns

    my $str = count_nouns($count, $noun);
    my $str = count_nouns($count, $noun, %opts);

Returns a string combining C<$count> and the appropriately pluralised form
of C<$noun>. Handles common English pluralisation rules:

=over 4

=item * Singular (count == 1): C<"$noun"> unchanged.

=item * Words ending in C<ch>, C<sh>, C<x>, C<ss>: append C<"es">.

=item * Words ending in vowel + C<s> or C<z>: append C<"es"> (e.g., C<"buzzes">).

=item * Words ending in consonant + C<y>: replace C<y> with C<"ies">.

=item * All others: append C<"s">.

=back

B<Parameters:>

=over 4

=item C<$count>

The numeric count.

=item C<$noun>

The noun to pluralise.

=item C<suppress_count> (optional)

If true, the count is not included in the output.

=item C<prefix> (optional)

An array reference of two strings: C<[$singular_prefix, $plural_prefix]>.
The appropriate element is prepended to the output.

=back

B<Returns:> A string such as C<"1 file">, C<"3 files">, C<"2 churches">.

B<Examples:>

    count_nouns(1, 'file');    # Returns: '1 file'
    count_nouns(3, 'file');    # Returns: '3 files'
    count_nouns(2, 'church');  # Returns: '2 churches'
    count_nouns(0, 'match', suppress_count => 1);  # Returns: 'matches'

In scalar context: an array reference of the same.

=head2 global_config_schema

    my $schema = global_config_schema();

Returns a hash reference describing the schema for the Genesis global
configuration file. Each top-level key is a configuration setting name; its
value is a descriptor hash with fields such as C<type>, C<default>,
C<envvar>, C<description>, and for enumeration types a C<values> list.

The schema covers the following settings:

=over 4

=item C<default_bosh_target>

Enum (C<ask>, C<self>, C<parent>). Controls default BOSH target selection.
Env var: C<GENESIS_DEFAULT_BOSH_TARGET>.

=item C<legacy_repo_suffix>

Boolean. Use the legacy C<-deployments> repository suffix.
Env var: C<GENESIS_LEGACY_REPO_SUFFIX>.

=item C<embedded_genesis>

Enum (C<ignore>, C<check>, C<warn>). How to handle embedded genesis versions.

=item C<output_style>

Enum (C<plain>, C<fun>, C<pointer>). CLI output style.

=item C<show_duration>

Boolean. Show command execution duration.
Env var: C<GENESIS_SHOW_DURATION>.

=item C<automatic_config_upgrade>

Enum (C<no>, C<yes>, C<silent>). Automatic configuration upgrade behaviour.
Env var: C<GENESIS_CONFIG_AUTOMATIC_UPGRADE>.

=item C<fix_on_deploy>

Enum (C<always>, C<ask>, C<never>). Automatic fix behaviour during deployment.
Env var: C<GENESIS_FIX_ON_DEPLOY>.

=item C<confirm_release_overrides>

Enum (C<always>, C<outdated>, C<never>). Release override confirmation policy.
Env var: C<GENESIS_CONFIRM_RELEASE_OVERRIDES>.

=item C<spec_cache_dir>

String. Directory for caching kit specifications.
Env var: C<GENESIS_SPEC_CACHE_DIR>.

=item C<bosh_logs_path>

String. Path for storing BOSH deployment logs. Defaults to
C<< <DEPLOYMENT_ROOT>/bosh_logs >>.
Env var: C<GENESIS_DEPLOYMENT_LOGS_PATH>.

=item C<deployment_roots>

Array of strings or label=path pairs. Deployment root directories.
Env var: C<GENESIS_DEPLOYMENT_ROOTS> (colon-separated).

=item C<kits_path>

String. Override path for kit storage.

=item C<suppress_warnings>

Hash with sub-keys C<oversized_secrets>, C<bosh_target>, and
C<deprecations> (all booleans). Setting C<deprecations> to true silences
deprecation log entries globally; equivalent to setting the
C<GENESIS_SUPPRESS_DEPRECATIONS> env var.

Per-target suppression is also available - any log target in C<logs:> can
specify a C<suppress_contexts:> list (currently supporting C<deprecation>);
when present, the per-target list is authoritative and the global setting
is not consulted for that target.

=item C<ui>

Hash with sub-key C<colors> controlling C<code> and C<warning_alert> display
colors.

=item C<logs>

Array of log-destination hashes. Each entry supports C<file>, C<level>,
C<show_stack>, C<truncate>, C<style>, C<lifespan>, and C<timestamp>.

=back

B<Returns:> A hash reference (the schema definition).

B<Examples:>

    my $schema = global_config_schema();
    # Returns: hashref with keys like 'output_style', 'show_duration', etc.
    print $schema->{output_style}{default};  # prints 'plain'

=head2 _lookup_key

    my ($found, $value) = _lookup_key($what, $key);

Traverses a nested Perl data structure (hash refs and array refs) using a
dot/bracket key path and returns a two-element list: a boolean indicating
whether the key was found, and the value at that location (or C<undef>).

Array elements may be addressed by numeric index (C<[0]>) or by a
C<name=value> search among the keys C<name>, C<key>, and C<id> (or any
explicit key via C<key=value> syntax). Double-dot (C<..>) in the key is
treated as a literal dot in a hash key name.

B<Parameters:>

=over 4

=item C<$what>

The data structure to traverse (hash ref, array ref, or scalar).

=item C<$key>

A dot/bracket path string.

=back

B<Returns:> C<(1, $value)> on success, C<(0, undef)> when the key is not found.

B<Examples:>

    my ($found, $val) = _lookup_key({ a => { b => 42 } }, 'a.b');
    # Returns: (1, 42)

    my ($found, $val) = _lookup_key({ a => 1 }, 'x');
    # Returns: (0, undef)
