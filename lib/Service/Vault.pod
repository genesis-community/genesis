=head1 NAME

Service::Vault - Abstract base class for Vault access via safe

=head1 SYNOPSIS

  use Service::Vault;

  # Look up all configured vault targets
  my @all = Service::Vault->find();

  # Find vaults matching a specific property
  my @local = Service::Vault->find(name => 'my-vault');

  # Get the system default vault
  my $vault = Service::Vault->default;

  # Read a secret
  my $value = $vault->get('secret/myapp', 'password');

  # Write a secret
  $vault->set('secret/myapp', 'password', 'hunter2');

  # Check vault health
  my $health = $vault->status;  # Returns: 'ok', 'sealed', 'unreachable', etc.

=head1 DESCRIPTION

C<Service::Vault> is the abstract base class for Vault service objects in
Genesis. It models a single Vault target as known to the C<safe> CLI and
provides a unified interface for reading and writing secrets, checking status,
and managing vault lifecycle (target selection, authentication, unsealing).

Concrete behaviour is provided by the two derived classes:

=over 4

=item L<Service::Vault::Local>

A locally-managed Vault instance (e.g. a dev vault started by C<safe local>).

=item L<Service::Vault::Remote>

A remote Vault instance defined in the user's C<~/.saferc>.

=back

The class maintains three shared caches: the list of all known vaults, the
system default vault, and the "current" vault most recently targeted by
Genesis. These caches can be cleared with C<clear_all>.

=head1 ABSTRACT METHODS

Subclasses must implement the following methods. Calling them on the base
class directly raises an error.

=head2 create

  Service::Vault::Local->create();
  Service::Vault::Remote->create();

Factory method that subclasses must override to create and register a new
vault object. Calling this on C<Service::Vault> directly raises
C<"Cannot directly instantiate a Genesis::Vault - use a derived class">.

B<Errors:>

Raises C<"Cannot directly instantiate a Genesis::Vault - use a derived class">
when called on C<Service::Vault> directly.

Raises C<"Expected $class to provide 'create' method, but it did not (or called SUPER)">
when a subclass calls SUPER without overriding.

B<Examples:>

  # Must be called on a derived class
  Service::Vault::Local->create('my-vault');
  # Returns: a Service::Vault::Local object

=head2 connect_and_validate

  $vault->connect_and_validate();

Subclasses must implement this to connect to and validate the vault.
Sets the vault as current on success.

B<Errors:>

Raises C<"Expected %s to provide 'connect_and_validate' method, but it did
not (or called SUPER)"> when called on the base class. C<%s> is the class name.

B<Returns:> Defined by subclass implementation.

B<Examples:>

  # Subclasses call connect_and_validate internally during target/attach
  my $vault = Service::Vault::Remote->target('prod-vault');
  # Returns: subclass-defined (target() calls connect_and_validate internally)

=head2 authenticate

  $vault->authenticate();

Subclasses must implement this to authenticate using credentials available
in the environment.

B<Returns:> Defined by subclass.

B<Errors:>

Raises C<"Expected %s to provide 'authenticate' method, but it did not (or called SUPER)">
when called on the base class. C<%s> is the class name.

B<Examples:>

  # Implemented and called via subclass
  Service::Vault::Remote->authenticate();
  # Returns: implementation-defined

=head1 METHODS

=head2 new

  my $vault = Service::Vault->new($url, $name, $verify, $namespace, $strongbox, $mount);

Low-level constructor. Do not call directly; use a subclass factory method
(C<create>, C<target>, C<attach>, or C<rebind>), which validate the target
before returning a blessed C<Service::Vault> object.

B<Parameters:>

=over 4

=item $url

The Vault server URL, e.g. C<https://vault.example.com:8200>.

=item $name

The target alias as known in C<~/.saferc>.

=item $verify

Boolean. If true, TLS certificates are verified. If false, verification is
skipped. JSON::Boolean values are coerced to plain C<1> or C<0>.

=item $namespace

Optional Vault namespace string. Defaults to C<''>.

=item $strongbox

Optional tri-state boolean. C<1> and C<0> are recorded as stated values;
C<undef> is preserved as C<undef>, meaning nothing has stated the flag. It
is deliberately not defaulted -- see L</strongbox>.

=item $mount

Optional secret mount path. Leading and trailing slashes are normalized.
Defaults to C</secret/>.

=back

B<Returns:> A blessed C<Service::Vault> object.

B<Examples:>

  my $vault = Service::Vault->new(
    'https://vault.example.com:8200',
    'prod-vault',
    1,      # verify
    '',     # namespace
    1,      # strongbox
    '/secret/',
  );
  # Returns: a Service::Vault object

=head2 target

  my $vault = Service::Vault->target($target, %opts);

Resolves an alias or URL to exactly one vault and connects to it, returning
the result of C<connect_and_validate>.

This handles the non-interactive case only -- a target must be given.
Subclasses may override to add semantics for the no-target case, as
C<Service::Vault::Remote> does with its interactive picker; when they do they
should still delegate here for the target-given path, so the lookup below
stays consistent.

B<The lookup is deliberately class-agnostic.>  It calls
C<< Service::Vault->find >> rather than C<< $class->find >>, because a target
given as C<--vault URL_OF_LOCAL_VAULT> should resolve to the C<Local> vault
living at that URL rather than failing because the caller happened to be
C<Service::Vault::Remote>.  A subclass override of C<find> would filter that
vault out silently.

B<Parameters:>

=over 4

=item C<$target>

An alias or URL.  Required.

=item C<%opts>

Reserved for subclass overrides; unused here.

=back

B<Returns:> the connected and validated vault object.

B<Errors:>

=over 4

=item *

Bails with C<"Service::Vault-E<gt>target requires an alias or url"> when C<$target> is missing or empty.

=item *

Bails with C<< "Safe target \"#M{...}\" not found." >> when no target matches.

=item *

Bails with C<< "Multiple safe targets use url #M{...}" >> when more than one C<.saferc> target shares the resolved URL, listing the duplicates.  C<.saferc> cannot hold two targets for one URL.

=back

B<Examples:>

  my $vault = Service::Vault->target('prod-vault');
  # returns the connected Service::Vault::Remote for that alias

  my $vault = Service::Vault->target('http://127.0.0.1:8201');
  # returns a Service::Vault::Local when that URL is a local vault

=head2 rebind

  my $vault = Service::Vault->rebind();

Resolves C<$ENV{GENESIS_TARGET_VAULT}> to a concrete vault and makes it
current.  Bash hooks that shell back into C<genesis lookup>,
C<genesis has-feature>, and friends arrive in a subprocess with that variable
set by the outer command; this is how they recover the vault.

Accepts either form the variable may take: a URL, looked up class-agnostically,
or a legacy named target, matched against the default vault.

B<This lives on the base class deliberately.>  Callback callers cannot know
which kind of vault the URL points at and should not have to.  While it lived
on C<Service::Vault::Remote>, its C<find> was class-filtered and silently
excluded C<Local> vaults, so any callback running under a C<safe local -m>
vault -- kit-validator test runs, proto-BOSH development loops -- failed with
"not found in .saferc".

B<Returns:> the vault, having been set as current; or nothing when the
variable holds a legacy name that does not match the default vault.

B<Errors:>

=over 4

=item *

Bails with C<"Cannot rebind to vault in callback due to missing environment variables!"> when C<GENESIS_TARGET_VAULT> is unset.

=item *

Bails with C<"Cannot rebind to vault at address '...' - not found in .saferc"> when the variable holds a URL with no matching target.

=back

B<Examples:>

  local $ENV{GENESIS_TARGET_VAULT} = 'http://127.0.0.1:8201';
  my $vault = Service::Vault->rebind();
  # returns the local vault at that URL, now set as current

=head2 all_vaults

  my @vaults = Service::Vault->all_vaults();

Returns all vault targets defined in the C<safe> configuration as a list
of C<Service::Vault> objects sorted by name. Local vaults are returned as
C<Service::Vault::Local> objects; all others as C<Service::Vault::Remote>.

The target list comes from C<safe targets --json>, but the C<strongbox>
value does not: that listing reports the conclusion safe reached after
applying its own default, which cannot distinguish an unstated flag from a
disabled one. It is read from C<~/.saferc> via L</strongbox_intent> instead,
so the objects every caller works with carry the tri-state rather than a
definite C<0> for a target that said nothing.

B<Returns:> A list of C<Service::Vault> objects.

=head2 strongbox_intent

  my $sb = Service::Vault::strongbox_intent($alias);

Reads C<$HOME/.saferc> directly and reports what it actually B<states>
about a target's Strongbox setting, as opposed to what C<safe targets
--json> concludes after applying safe's current default.

Both keys are honoured: C<strongbox> as written by safe v1.20.0 and later,
and the legacy C<no_strongbox> written by v1.4.0 through v1.10.0, inverted.
When both appear -- which happens mid-migration, since safe rewrites the
legacy key -- C<strongbox> wins, as the newer intent.

Every version of safe that has shipped locates its rc at C<$HOME/.saferc>
with no environment override, so no discovery is required.

B<Parameters:>

=over 4

=item $alias

The safe target alias to look up.

=back

B<Returns:> C<1> if the file states Strongbox is on, C<0> if it states it is
off, C<undef> if it says nothing about this target.

B<Errors:> None. This function never dies. A missing, unreadable, or
unparseable C<.saferc>, an unknown alias, and an entry carrying neither key
all return C<undef>. The file belongs to safe rather than to Genesis, and a
malformed one must not take down a command over a flag that only affects
seal-state reporting.

B<Examples:>

  # ~/.saferc entry: {url: ..., strongbox: true}
  Service::Vault::strongbox_intent('ops');
  # Returns: 1

  # ~/.saferc entry: {url: ..., no_strongbox: true}
  Service::Vault::strongbox_intent('ops');
  # Returns: 0

  # ~/.saferc entry with neither key -- how every pre-v1.20.0 target
  # with Strongbox enabled appears on disk
  Service::Vault::strongbox_intent('ops');
  # Returns: undef

  Service::Vault::strongbox_intent('never-targeted');
  # Returns: undef

=head2 find

  my @vaults = Service::Vault->find(%filter);

Returns all vaults matching the given filter criteria. Without filters,
returns all known vaults. Filter keys are matched as strings against vault
object properties. Valid filter keys are C<url>, C<name>, C<verify>, and
C<namespace>.

Results are cached after the first call. Use C<clear_all> to invalidate the
cache.

B<Parameters:>

=over 4

=item %filter

Optional hash of property/value pairs to filter on.

=back

B<Returns:> A list of matching C<Service::Vault> objects (may be empty).

B<Examples:>

  # All configured vaults
  my @all = Service::Vault->find();
  # Returns: list of Service::Vault objects

  # Vault with a specific alias
  my ($v) = Service::Vault->find(name => 'prod-vault');
  # Returns: the matching vault object

=head2 find_by_target

  my @vaults = Service::Vault->find_by_target($alias_or_url);

Returns all C<Service::Vault> objects sharing the URL of the given target
alias or URL string.

B<Parameters:>

=over 4

=item $alias_or_url

A target alias name or a full URL. If an alias is given, its URL is
resolved first, then all aliases sharing that URL are returned.

=back

B<Returns:> A list of C<Service::Vault> objects (may be empty).

B<Examples:>

  my @shared = Service::Vault->find_by_target('my-vault');
  # Returns: list of vault objects sharing the same URL

=head2 default

  my $vault = Service::Vault->default($refresh);

Returns the vault set as the system default in C<safe> (the target
C<safe target --json> reports). The result is cached; pass a true value
for C<$refresh> to force a fresh lookup.

B<Parameters:>

=over 4

=item $refresh

Optional. If true, clears the cached default and re-queries C<safe>.

=back

B<Returns:> A C<Service::Vault> object, or C<undef> if no default is set.

B<Examples:>

  my $default = Service::Vault->default();
  print $default->name;
  # Returns: name of the current default vault

=head2 set_default

  Service::Vault->set_default($vault);

Sets the given vault as the system default C<safe> target by running
C<safe target $name>.

B<Parameters:>

=over 4

=item $vault

A C<Service::Vault> object to set as the default target.

=back

B<Returns:> The C<$vault> object passed in.

B<Errors:>

Dies with C<"Could not set default vault to #C{%s}:\n%s"> if the C<safe target>
command fails. C<%s> is the vault name; the second C<%s> is the error output
from safe.

B<Examples:>

  my ($vault) = Service::Vault->find(name => 'prod-vault');
  my $result = Service::Vault->set_default($vault);
  # Returns: $vault

=head2 current

  my $vault = Service::Vault->current();

Returns the vault most recently set as the Genesis current vault by
C<target>, C<attach>, or C<rebind> (in subclasses), or by an explicit call
to C<set_as_current>.

B<Returns:> A C<Service::Vault> object, or C<undef> if none has been set.

B<Examples:>

  my $cur = Service::Vault->current();
  print $cur->name if $cur;
  # Returns: name of the current vault

=head2 clear_all

  Service::Vault->clear_all();
  $vault->clear_all();   # can also be called on an instance (for chaining)

Clears all cached vault data: the vault list, the default vault, and the
current vault. Also removes the cached environment hash from each known
vault object. Returns the invocant to allow method chaining.

Primarily used in tests, but also useful when the C<safe> configuration
changes during a Genesis run.

B<Returns:> The invocant (class or object).

B<Examples:>

  Service::Vault->clear_all();

  # After clearing, the next find() re-queries safe
  my @fresh = Service::Vault->find();
  # Returns: fresh list of vault objects

=head2 find_single_match_or_bail

  my $vault = Service::Vault->find_single_match_or_bail($url, $current_name);

Finds all vaults matching the given URL and returns the single match.
If more than one alias is registered for the URL, dies with an error
listing all conflicting aliases.

B<Parameters:>

=over 4

=item $url

The Vault URL to look up.

=item $current_name

Optional. The alias currently in use, highlighted in the error output.

=back

B<Returns:> The single matching C<Service::Vault> object, or C<undef> if
none found.

B<Errors:>

Dies with a multi-line message beginning with
C<"\nMore than one target is specified for URL '%s'\n"> listing the
conflicting aliases and instructions to edit C<~/.saferc>. C<%s> is the URL.

B<Examples:>

  my $vault = Service::Vault->find_single_match_or_bail(
    'https://vault.example.com:8200', 'my-vault'
  );
  # Returns: the matching Service::Vault object

=head2 bare_target_name

  my $name = Service::Vault->bare_target_name($input);

Says whether C<$input> names a safe target rather than describing a vault,
and returns the name if so.  Input that, once trimmed, is a single token
with no URL scheme (nothing like C<https://> at its start) is a name.  A
name never shadows a descriptor that could work, because a descriptor needs
a URL.  A name may still be a clause keyword such as C<verify> or
C<no-strongbox>, contain C<:> or C</>, start with C<$>, or be C<0>, since
all of those are legal in a target name.

L</get_vault_from_descriptor> uses it to decide how to resolve its input,
and C<genesis new> uses it to decide whether to record the resolved
target's descriptor in place of what was typed.

B<Parameters:>

=over 4

=item $input

The text given for a vault, such as the value of C<--vault>.

=back

B<Returns:> The trimmed name, or C<undef> when C<$input> is a descriptor or
blank.  It never consults F<~/.saferc>, so a name it returns may still match
no target.

B<Examples:>

  Service::Vault->bare_target_name('  prod-vault ');   # 'prod-vault'
  Service::Vault->bare_target_name('lab:ops');          # 'lab:ops'
  Service::Vault->bare_target_name('https://vault.example.com');  # undef
  Service::Vault->bare_target_name('ops as ops');       # undef

=head2 get_vault_from_descriptor

  my $vault = Service::Vault->get_vault_from_descriptor($descriptor, $source);
  my $vault = Service::Vault->get_vault_from_descriptor($input, $source, target_name => 1);

Parses a vault descriptor string (as used in C<genesis.vault> or given to
C<genesis new --vault>) and resolves it to a connected vault through
L<Service::Vault::Remote/attach>.

With C<target_name>, the input may instead be the name of a safe target,
as decided by L</bare_target_name>; everything else is parsed as a
descriptor.  The named target is used as found, connected and validated,
without a second lookup through C<attach>.  The name has already picked
exactly one target, and C<attach> would read a leading C<$> in the name as
an environment variable.  The named target must be the only one at its URL,
because Genesis hands a vault to safe, and to hooks, by URL, and safe will
not choose between targets that share one.

Only C<genesis new --vault> passes C<target_name>.  A target name lives in
one operator's F<~/.saferc>, so an environment file, which is committed and
read on other machines, keeps to descriptors.

This is the only descriptor resolver.  C<Genesis::Env::vault> and the
C<create> command both call it, so a descriptor that resolves in an
environment file resolves the same way on the command line.  It must keep
delegating to C<attach> rather than building its own C<find> filter: an
exact match on every parsed field excluded targets over strongbox (which
only selects a seal-state sidecar), over the C<verify> default of an http
URL, and over a namespace the descriptor never stated, and then returned
C<undef> instead of saying why.

The filter therefore compares C<url>, C<namespace> (an absent namespace is
the root namespace, C<''>), and C<verify> only for an https URL.  Strongbox
breaks ties between otherwise identical targets and is reconciled against
the target, but never excludes one.  The alias likewise only breaks ties.

B<Parameters:>

=over 4

=item $descriptor

A vault descriptor string in the format accepted by C<parse_vault_descriptor>.

=item $source

Optional. A label identifying the source of the descriptor used in error
messages. Defaults to C<'genesis.vault'>.

=item target_name

Optional. When true, a bare safe target name is accepted as described
above.  Defaults to false, which accepts descriptors only.

=back

B<Returns:> The matching vault, connected and validated.  It never returns
C<undef> for a descriptor whose target is missing; that case bails.

B<Errors:>

C<"Safe target '...' given by the ... was not found."> when a target name is
accepted and no safe target has it.  The message says how to list targets
and what a descriptor looks like, and, for a name that is also a clause
keyword, that a descriptor needs a URL.

C<"Safe target '...' shares its URL ... with ...">, naming the other
targets, when a target name is accepted and another target has the same URL,
whatever its namespace.

Everything C<parse_vault_descriptor> raises for a malformed descriptor.

Everything C<attach> raises: a list of similar targets when one at the URL
differs in namespace or verify, "Safe target for ... not found" with the
C<safe target> command to run when none is at the URL and no vault
credentials are in the environment, and a list of duplicates when several
targets match and the alias does not pick one.

B<Examples:>

  my $vault = Service::Vault->get_vault_from_descriptor(
    'https://vault.example.com:8200 as prod-vault no-verify'
  );
  # Returns: the matching Service::Vault::Remote object

  my $vault = Service::Vault->get_vault_from_descriptor(
    'prod-vault', '--vault option', target_name => 1
  );
  # Returns: the vault of the safe target named prod-vault

=head2 parse_vault_descriptor

  # Scalar context - returns a hash reference
  my $parsed = Service::Vault->parse_vault_descriptor($vault_info, $source);

  # List context - returns a flat list
  my ($url, $verify, $namespace, $alias, $strongbox) =
    Service::Vault->parse_vault_descriptor($vault_info, $source);

Parses a vault descriptor string into its component parts. The descriptor
format is:

  http[s]://<domain-or-ip>[:<port>][/<namespace>] [as <alias>] [no-]verify [no-]strongbox

In scalar context, returns a hash reference with keys C<url>, C<verify>,
C<alias>, C<namespace>, C<strongbox>, C<tls>, C<domain>, and C<port>.

In list context, returns C<($url, $verify, $namespace, $alias, $strongbox)>.

C<strongbox> is tri-state and has B<no default>: a descriptor carrying
neither clause has stated nothing, and is reported as C<undef>. It formerly
defaulted to enabled, which meant every environment whose descriptor omitted
the clause -- now the common case, since L</build_descriptor> emits one only
for a stated setting -- looked as though it had asked for Strongbox, and
drew a warning against targets that had simply said nothing.

The alias may be the last element of the descriptor; it is not required to
be followed by another clause.

The host stops at the first C<:> or C</>, so a path after the host is the
namespace whether or not a port precedes it, and a trailing C</> names no
namespace.  Letting the host run to the next C<:> folded the path into the
URL, which then matched no safe target.  C<tls> is C<1> or C<0>, and
C<verify> defaults to it.

B<Parameters:>

=over 4

=item $vault_info

The vault descriptor string to parse.

=item $source

Optional. Label for the descriptor source, used in error messages.
Defaults to C<'genesis.vault'>.

=back

B<Returns:> In scalar context, a hash reference. In list context, a
five-element list C<($url, $verify, $namespace, $alias, $strongbox)>.

B<Errors:>

Dies with a message beginning with C<"Unknown clause in #G{$source}: '#Y{$clause}'\n">
if the descriptor contains an unrecognised token.

Dies with a message beginning with C<"Missing connect clause in #G{$source}\n">
if no URL clause is present.

B<Examples:>

  my $info = Service::Vault->parse_vault_descriptor(
    'https://vault.example.com:8200 as prod no-verify'
  );
  # Returns: { url => 'https://vault.example.com:8200', alias => 'prod',
  #            verify => 0, strongbox => 1, ... }

  my ($url, $verify, $ns, $alias, $sb) = Service::Vault->parse_vault_descriptor(
    'https://10.0.0.1:8200/ns1 as local verify no-strongbox'
  );
  # Returns: ('https://10.0.0.1:8200', 1, 'ns1', 'local', 0)

=head2 url

  my $url = $vault->url();

Returns the URL of the Vault target in the form C<scheme://host:port>. The
port is optional; it is implied as C<80> for C<http> and C<443> for C<https>.

B<Returns:> A string such as C<'https://vault.example.com:8200'>.

B<Examples:>

  print $vault->url();
  # Returns: 'https://vault.example.com:8200'

=head2 port

  my $port = $vault->port();

Returns the port from the target URL.

B<Returns:> The port as it appears in the URL, or C<undef> when the URL
carries none. Chiefly of interest for local vaults, which always bind an
explicit port; see L<Service::Vault::Local>.

B<Limitations:> Reports only what the URL states -- it does not infer the
scheme default (C<80>/C<443>), so C<< https://vault.example.com >> yields
C<undef> rather than C<443>. The host pattern is IPv4/hostname only; a
bracketed IPv6 literal such as C<< http://[::1]:8200 >> yields C<undef>.

B<Examples:>

  print $vault->port();
  # Returns: 8200

=head2 name

  my $name = $vault->name();

Returns the target alias as registered in C<~/.saferc>.

B<Returns:> A string (the target alias, e.g. C<'prod-vault'>).

B<Examples:>

  print $vault->name();
  # Returns: 'prod-vault'

=head2 verify

  my $verify = $vault->verify();

Returns whether TLS certificate verification is enabled for this vault.

B<Returns:> C<1> if verification is enabled, C<0> if disabled.

B<Examples:>

  print $vault->verify();
  # Returns: 1

=head2 namespace

  my $ns = $vault->namespace();

Returns the Vault namespace string configured for this vault.

B<Returns:> A string, or C<''> if no namespace is set.

B<Examples:>

  print $vault->namespace();
  # Returns: ''

  # When the vault URL includes a namespace path
  print $vault->namespace();
  # Returns: 'admin'

=head2 strongbox

  my $sb = $vault->strongbox();

Returns whether Strongbox is enabled for this target. This is B<tri-state>:
C<undef> means no safe target ever stated the flag, which is a distinct
condition from stating that it is off.

The distinction matters because safe omits the key for whichever state is
its own default, and that default changed. Builds up to v1.10.0 wrote
C<no_strongbox> only when Strongbox was disabled; builds from v1.20.0 write
C<strongbox> only when it is enabled. An absent key therefore means opposite
things in the two eras, and C<safe targets --json> reports only the
conclusion its own default produced. Treating that conclusion as a stated
intent is what allowed a safe upgrade to silently disarm Strongbox on every
target that had it. See L</strongbox_intent>.

B<Returns:> C<1> if enabled, C<0> if explicitly disabled, C<undef> if
unstated.

B<Examples:>

  print $vault->strongbox() // 'unstated';
  # Returns: 1

  # A target whose ~/.saferc entry carries neither key
  print defined($vault->strongbox()) ? 'stated' : 'unstated';
  # Returns: 'unstated'

=head2 tls

  my $is_tls = $vault->tls();

Returns whether the vault URL uses HTTPS. This is computed from the URL
rather than stored as a separate property.

B<Returns:> True (C<1>) if the URL starts with C<https://>, false (empty
string) otherwise.

B<Examples:>

  print $vault->tls() ? 'TLS' : 'plaintext';
  # Returns: 'TLS'

=head2 query

  my ($out, $rc, $err) = $vault->query();

Runs a C<safe> command against this vault and returns the output, exit code,
and stderr. The command is automatically prefixed with C<safe> if not already
present. C<SAFE_TARGET> is always set to this vault's reference, and C<DEBUG>
is always cleared.

B<Parameters:>

=over 4

=item \%opts

Optional hash reference of options passed to the C<run> helper. The C<env>
key may be provided to supply additional environment variables, though
C<SAFE_TARGET> and C<DEBUG> are always overridden.

=item @cmd

The safe subcommand and arguments (e.g. C<'get', 'secret/foo:bar'>).
The leading C<'safe'> may be omitted.

=back

B<Returns:> A three-element list C<($output, $exit_code, $stderr)>.

B<Examples:>

  my ($out, $rc) = $vault->query('get', 'secret/myapp:password');
  die "Failed" unless $rc == 0;

  # With options
  my ($out, $rc) = $vault->query({passfail => 1}, 'exists', 'secret/myapp');
  # Returns: ('', 0, '') when the path exists

=head2 get

  my $value  = $vault->get($path, $key);
  my $value  = $vault->get("$path:$key");
  my $values = $vault->get($path);

Reads a secret value or all key/value pairs from the vault.

When C<$key> is provided (either as a second argument or embedded in
C<$path> as C<path:key>), returns the value of that specific key as a
string, or C<undef> if not found.

When no key is given, fetches the entire path and returns a hash reference
of all key/value pairs at that path. Returns an empty hash reference C<{}>
on error.

B<What counts as an error.> A non-zero exit from C<safe> is a failure. A
zero exit is not automatically a success: C<safe> has not reliably set a
non-zero exit code on failure, so the payload is the deciding evidence --
if it parses as a hash the read succeeded, and if it does not the read is
treated as failed and the C<safe> output is reported.

Anything C<safe> writes to standard error while exiting zero is
B<not> treated as failure. Some builds emit a TLS notice on every call
against a C<noverify> target, and treating that as an error discarded
otherwise complete reads and reported them as missing permissions. What
was written is recorded at trace level rather than dropped. The same
reasoning is applied to the JSON paths by
C<Genesis::read_json_from>, which overrides its error on a zero exit for
exactly this reason.

B<Parameters:>

=over 4

=item $path

The vault secret path. May include a key suffix in C<path:key> form.

=item $key

Optional. The key name within the path.

=back

B<Returns:> A string value when a key is requested, or a hash reference
when only a path is given.

B<Errors:>

Dies with C<"Expected #C{%s} to return a hash of key/value pairs, but got a %s">
when the path returns something other than a hash. The first C<%s> is the
path, the second is the Perl ref type returned.

B<Examples:>

  # Fetch a single key
  my $pw = $vault->get('secret/myapp', 'password');
  # Returns: 'hunter2'

  # Fetch with combined path:key
  my $pw = $vault->get('secret/myapp:password');
  # Returns: 'hunter2'

  # Fetch all keys at a path
  my $data = $vault->get('secret/myapp');
  # Returns: { password => 'hunter2', user => 'admin' }

=head2 get_path

  my $data = $vault->get_path($path);

Reads all secrets under C<$path> and all subpaths, returning a nested hash
structure. Uses C<safe export> to retrieve the entire tree in a single JSON
call, and reads every export version through L</normalize_export>.
Automatically unflattens paths stored with the C<__flattened__> marker.

Returns an empty hash reference C<{}> when the export fails or cannot be
parsed. A value under the path that is not a string is not a failed read; it
dies, as L</normalize_export> does, rather than read as an empty tree or as
a converted string.

B<Parameters:>

=over 4

=item $path

The root vault path to export from. Leading and trailing slashes are stripped.

=back

B<Returns:> A nested hash reference. Keys at each level correspond to path
segments; leaf values are hash references of key/value pairs.

B<Examples:>

  my $tree = $vault->get_path('secret/myapp');
  # Returns: { password => 'hunter2', db => { host => 'localhost' } }

=head2 get_path_strict

  my $data = $vault->get_path_strict($path);

Reads the tree under C<$path> as C<get_path> does, but tells a failed read
from a path with nothing stored. Returns C<undef> when C<safe> reports that no
secret exists at the path, and dies with the path, the vault URL, the error,
the likely causes, and what to check for any other failure, such as an
unreachable or sealed vault, an expired token, or an export that cannot be
parsed.

A token that can list a path but cannot read it makes C<safe> report that no
secret exists, after a refusal. When the output holds C<403>, C<permission
denied>, or C<forbidden> as well, the read is treated as failed and dies,
since the path was never read.  The path that C<safe> quotes in its "no secret
exists" line is not searched, so an environment name that holds C<403> or
C<forbidden> reads as absent when nothing is stored.

Use it where a read that failed must not pass for an empty record, such as
before a write that clears the record it replaces.

B<Parameters:>

=over 4

=item $path

The root vault path to export from. A leading slash is stripped.

=back

B<Returns:> A nested hash reference as C<get_path> returns, or C<undef> when
nothing is stored at the path.

B<Errors:>

=over 4

=item C<"Could not read #C{%s} from vault at #M{%s}: %s">

Raised (via C<bail()>) when C<safe export> fails for any reason other than
the path having nothing stored, or when its output cannot be parsed as JSON.
The placeholders are the path, the vault URL, and the reason, which is the
text C<safe> wrote to stderr, or C<safe exited with code N> when it wrote
none. The message goes on to name the likely causes (a token without read on
the path, a sealed vault, or an unreachable vault) and to say to run
C<safe export> on the path and C<safe vault status>. The text here is the
start of it.

=item C<"Cannot use the safe export ...">

Raised by L</normalize_export> when the export holds a value that is not a
string, or is in a format it does not read.

=back

B<Examples:>

  my $tree = $vault->get_path_strict('secret/myapp');
  # Returns: { password => 'hunter2', db => { host => 'localhost' } }

  my $none = $vault->get_path_strict('secret/never-written');
  # Returns: undef

  # With the vault sealed or the token expired
  $vault->get_path_strict('secret/myapp');
  # Dies: Could not read secret/myapp from vault at https://...: <safe's error>

=head2 normalize_export

  my $export = Service::Vault::normalize_export($data);

Reduces a decoded C<safe export> of any export version to the flat shape of
version 1, a hash of full vault path to the key/value pairs stored there,
with every value a string. Every reader of C<safe export> output goes
through it, so none of them depends on which version C<safe> chose to write.
It is a function, not a method.

C<safe> writes version 1, a bare object of path to key/value pairs, when
every secret has one version and every value is a string. It writes version
2, an array holding one object with C<export_version> 2 and a C<data> object
of paths, when some secret has more than one version. Each path there holds
a C<versions> list, oldest first, and each version has a C<value> object and
C<deleted> and C<destroyed> flags. Version 3 is the same shape with
C<export_version> 3, written when some value is not a string, and its values
keep the JSON type they were stored with.

The last version of each path is its current one, and its C<value> is what
is returned. When that version is deleted or destroyed, the path has nothing
a read returns, so the path is left out, and an older version is not used in
its place. A path with no versions is left out too, and so is a version 1
path whose value is C<null>. A current version with no C<value> gives an
empty hash.

A value that is not a string makes it die rather than turn the value into
one. That covers JSON objects, lists, numbers, booleans, and C<null>.
Genesis reads every secret as a string, and the text Perl would make of a
number or a boolean is not always the text C<safe> shows for it, so a
converted value could differ from the secret without anything saying so. A
string in version 3 is a JSON string, so a string that spells a number, such
as C<"42">, is a string and is kept. An integer too large for Perl is
decoded by C<JSON::PP> as its digits, so it reads as a string.

B<Parameters:>

=over 4

=item C<$data>

The decoded export, as C<load_json> or C<read_json_from> returns it, of any
export version. It is not modified.

=back

B<Returns:> A new hash reference of full vault path to a hash of key/value
pairs, or C<undef> when C<$data> is C<undef>.

B<Errors:>

Every message starts with C<Cannot use the safe export>, which is what
L</is_export_error> looks for.

=over 4

=item C<"Cannot use the safe export of #C{%s}: its #C{%s} key holds a typed value, a JSON %s, not a string. ...">

Raised (via C<bail()>) when the current value of a key is not a string. The
placeholders are the path, the key, and the JSON type, one of C<object>,
C<list>, C<number>, C<boolean>, or C<null>.

=item C<"Cannot use the safe export: it is export_version %s, and Genesis reads only versions 1, 2, and 3. ...">

Raised when a versioned export has an C<export_version> other than 2 or 3,
or none, which shows as C<(none)>.

=item C<"Cannot use the safe export: it is not an object or an array, but a JSON %s.">

Raised when the export is neither a version 1 object nor a versioned array.

=item C<"Cannot use the safe export: a versioned export is an array holding one export object, but this one holds %d %s.">

Raised when the array of a versioned export does not hold exactly one
object.

=item C<"Cannot use the safe export: its #C{data} is not an object of paths.">

Raised when the C<data> of a versioned export is not an object.

=item C<"Cannot use the safe export of #C{%s}: its versions are not a list.">

Raised when a path of a versioned export has no C<versions> list.

=item C<"Cannot use the safe export of #C{%s}: it is not an object of keys, but a JSON %s.">

Raised when the value at a path is not an object of key/value pairs.

=back

B<Examples:>

  my $export = Service::Vault::normalize_export(load_json(
    '[{"export_version":3,"data":{"secret/myapp":{"versions":['.
    '{"value":{"password":"old"}},{"value":{"password":"hunter2"}}]}}}]'
  ));
  # Returns: { 'secret/myapp' => { password => 'hunter2' } }

  Service::Vault::normalize_export({'secret/myapp' => {port => 8443}});
  # Dies: Cannot use the safe export of secret/myapp: its port key holds
  #       a typed value, a JSON number, not a string. ...

=head2 is_export_error

  my $refused = Service::Vault::is_export_error($@);

Tells whether an error came from L</normalize_export>, so that a caller that
catches the errors of a read in an C<eval> can let this one through. A
secret Genesis cannot read is a different answer from a read that failed,
and treating it as one would hide a value that needs fixing. It is a
function, not a method.

B<Parameters:>

=over 4

=item C<$err>

The error to check, usually C<$@>. It may be C<undef> or empty.

=back

B<Returns:> True when C<$err> is an error raised by C<normalize_export>,
and false otherwise.

B<Examples:>

  my $deploys = eval { $env->vault->get_path($path) };
  die $@ if Service::Vault::is_export_error($@);
  # A failed read still falls through; an unreadable value does not.

=head2 set

  $vault->set($path, $key, $value);       # one key
  $vault->set($path, %pairs);             # several keys
  $vault->set($path, $key);               # interactive (prompts for value)
  $vault->set("$path:$key", $value);      # key joined onto the path

Writes one or more secrets to the vault. Trailing arguments are an
even-sized list of key/value pairs, of which the single C<($key, $value)>
form is the one-pair case.

A lone key, or an explicit C<undef> value, starts an interactive C<safe
set> prompt that hides input and requires confirmation; the caller must be
in a controlling terminal.

If C<$path> contains a colon, the portion after the last one is taken as
the key, as C<get> already does. That form names a single key, so it
accepts at most one value.

Pairs are written in as few C<safe set> commands as the command-length
limit allows, and each command is confirmed against a read before the next
is sent -- see L</needs_write_confirmation> and L</_confirm_written>.

B<Parameters:>

=over 4

=item $path

The vault secret path, optionally with C<:key> appended.

=item %pairs

An even-sized list of key names and string values. Undefined values are
written as the empty string, except in the two-argument form where an
explicit C<undef> selects interactive mode.

=back

B<Returns:> The stored C<$value> when exactly one pair was given. A hash
reference of everything written when more than one was given. The value
re-read from the vault via C<get> in interactive mode.

B<Errors:>

Dies with C<"Could not write #C{%s} to vault at #M{%s}:\n%s"> if a write
fails. The placeholders are the path, vault URL, and command output.

Dies with C<"Could not write #C{%s:%s} to vault at #M{%s}"> if the write
fails in interactive mode.

Dies with C<"Could not write to #C{%s} in vault at #M{%s}: set() takes
key/value pairs, but was given an odd number of arguments."> when the
trailing arguments cannot be paired.

Dies with C<"Could not write to #C{%s} in vault at #M{%s}: a joined
path:key names a single key, so it takes at most one value."> when more
than one value follows a joined path.

Dies with C<"Could not write to #C{%s} in vault at #M{%s}: no key was
given."> when no key is supplied at all.

Dies with C<"#R{[ERROR]} Cannot interactively provide secrets unless in a
controlling terminal - terminating!"> if no controlling terminal is available
when attempting interactive mode.

May also die from the read-back confirmation; see L</_confirm_written>.

B<Examples:>

  $vault->set('secret/myapp', 'password', 'hunter2');
  # Returns: 'hunter2'

  $vault->set('secret/myapp', user => 'admin', password => 'hunter2');
  # Returns: { user => 'admin', password => 'hunter2' }

  $vault->set('secret/myapp:password', 'hunter2');
  # Returns: 'hunter2'

  # Interactive (prompts the user)
  $vault->set('secret/myapp', 'password');
  # Returns: value read back from vault after interactive entry

=head2 clear

  $vault->clear($path, $recursive);

Removes a secret path from the vault. Without C<$recursive>, removes only
the exact path (if it exists). With C<$recursive> true, removes the path
and all subpaths using C<safe rm -rf>.

If the path does not exist and C<$recursive> is false, returns without
error.

On a target that needs it, the removal is confirmed against a read before
returning, including in the "path does not exist" case -- a stale read can
report a path absent while its keys are still there for the next write to
merge into. See L</_confirm_cleared>.

B<Parameters:>

=over 4

=item $path

The vault secret path to remove.

=item $recursive

Optional boolean. If true, recursively removes C<$path> and all subpaths.

=back

B<Returns:> C<1> on successful removal, or C<undef> if the path did not
exist (non-recursive only).

B<Errors:>

Dies with C<"Could not clear #C{%s} in vault at #M{%s}:\n%s"> if the
removal fails. The placeholders are the path, vault URL, and combined
stdout/stderr.

May also die from the read-back confirmation; see L</_confirm_cleared>.

B<Examples:>

  $vault->clear('secret/myapp');
  # Returns: 1

  $vault->clear('secret/myapp', 1);
  # Returns: 1 (recursive removal)

B<Limitations:>

The confirmation covers C<$path>'s own keys only. A recursive removal also
deletes subpaths, and those are not read back.

=head2 max_json_string_value_length

  my $bytes = $vault->max_json_string_value_length();

Return the maximum size, in bytes, of any single JSON string value
Vault will accept on an incoming write request. Used by chunked-write
callers (e.g. C<Genesis::Env::Deployment::commit>) to derive a safe
chunk size for writes that might otherwise exceed Vault's per-string
ceiling.

The limit comes from the Vault listener config option
C<max_json_string_value_length>, introduced in B<Vault 1.21.0>
(October 2025), defined in C<internalshared/configutil/listener.go>
and enforced in C<http/handler.go>. It caps the length of a single
string value inside a JSON request body. It does B<not> cap the total
request body (see C<max_request_size>, default 32 MiB) or the secret
as a whole. Earlier Vault releases impose no such per-string cap; we
still use the 1 MiB default in that case for conservative chunking.

Sources, in priority order:

=over 4

=item 1.

C<GENESIS_VAULT_MAX_JSON_STRING_VALUE_LENGTH> environment variable,
when set to a positive integer.

=item 2.

Vault server query via C<safe curl --data-only
/sys/config/state/sanitized>. When the response decodes to JSON and
exposes C<data.listeners[0].config.max_json_string_value_length>, that
value wins. A privileged token is required to read this endpoint;
permission failures fall through silently.

=item 3.

Vault's compiled-in default of C<1024 * 1024> = B<1 MiB> (1,048,576
bytes). Matches Vault 1.21+ source.

=back

The returned value is cached on the instance after the first call.
Query failure paths (network error, missing field, malformed JSON) all
fall through to the default without warning so callers can rely on a
sensible cap even when the vault is uncommunicative.

Derive your usable chunk size by subtracting headroom for the key
prefix (e.g. C<artifacts[N]=>), JSON envelope overhead, and any
base64 line-break padding. Genesis defaults to 2 KiB of headroom.

B<Example:>

  $ENV{GENESIS_VAULT_MAX_JSON_STRING_VALUE_LENGTH} = 2_097_152;
  my $vault = Service::Vault->new(...);
  my $cap   = $vault->max_json_string_value_length();   # => 2097152
  my $chunk = $cap - 2048;                              # 2 KiB headroom

=head2 needs_write_confirmation

  if ($vault->needs_write_confirmation) { ... }

Whether a write to this target has to be read back before it can be
treated as landed.

C<safe set> is read-modify-write. On a highly-available vault, a read
served by a raft standby can lag the leader, so a write merges into a base
that is already out of date and silently discards what was written before
it. Reading each write back before sending the next one prevents that: the
next read-modify-write cannot see a stale base if the previous write is
already visible.

Sources, in priority order:

=over 4

=item 1.

C<GENESIS_VAULT_CONFIRM_WRITES> environment variable, when set to C<0> or
C<1>.

=item 2.

The server's C</sys/leader> endpoint via C<safe curl --data-only>, which
reports C<ha_enabled>.

=item 3.

Fail safe: confirm. A confirmation that was not needed costs one read,
while skipping one that was needed loses data with no error, so an
unreachable, unparseable or unrecognised answer resolves to confirming.

=back

The decision is made on C<ha_enabled> and nothing else. It is deliberately
B<not> made on C<is_self>: leadership fails over, and the target URL is
usually a load balancer fronting several nodes, so C<is_self> describes
whichever node answered that one request rather than the one that will
serve the next.

Both Vault and OpenBao report C<ha_enabled> at this endpoint, so no
engine detection is involved.

The result is cached on the instance after the first call, so a chunked
write does not re-probe per chunk.

B<Returns:> C<1> if writes must be confirmed, C<0> otherwise.

B<Errors:>

None. Every probe failure resolves to C<1> rather than raising.

B<Examples:>

  # Single-node or dev vault
  $vault->needs_write_confirmation;   # => 0

  # Suppress it regardless of the server's answer
  local $ENV{GENESIS_VAULT_CONFIRM_WRITES} = '0';
  $vault->needs_write_confirmation;   # => 0

B<Limitations:>

Confirming through a read only proves that the node which answered holds
the write. Where the target URL fronts several standbys, the node serving
the next read-modify-write may still be behind. With a single standby the
confirmations are monotonic and this is airtight; with several it narrows
the window rather than closing it. OpenBao exposes no C<X-Vault-Index>
equivalent for a client to detect staleness directly (openbao/openbao#3877,
RFC openbao/openbao#1528), so polling is the only available mechanism.

=head2 kv_mount

  my $mount = $vault->kv_mount($path);

Finds the kv secrets engine that C<$path> is on, and which version of kv it
is, by asking the vault's C<sys/internal/ui/mounts> endpoint.  That is the
endpoint the C<vault> CLI asks, and any token with any access to the path
may read it.  Answers are remembered per mount, so each mount is asked
about once.

A vault that answers the endpoint with 404 predates kv v2, so every mount
it has is a kv v1 one.  A C<generic> engine is kv v1 under its old name.

B<Parameters:>

=over 4

=item C<$path>

A whole secret path, such as C<secret/exodus/lab/bosh/network-claim-lock>.
Leading and trailing slashes are ignored.

=back

B<Returns:> A hashref with C<path> (the mount, with a trailing slash, or
C<undef> for a vault that predates kv v2), C<type> (C<kv> or C<generic>),
and C<version> (C<1> or C<2>).

B<Errors:>

=over 4

=item *

Dies when C<$path> is on an engine other than kv, naming the engine and
its mount.

=item *

Dies when the vault refuses the request or cannot be reached, naming the
reason, the likely causes, and the C<safe curl> command that shows the
vault's answer.

=item *

Raises a bug when C<$path> is empty or contains a C<:key>.

=back

B<Examples:>

  my $mount = $vault->kv_mount('secret/exodus/lab/bosh/network-claim-lock');
  # Returns: { path => 'secret/', type => 'kv', version => 2 }

=head2 kv_read

  my $record = $vault->kv_read($path);

Reads a whole secret with the kv API, through C<safe curl>.  On a kv v2
mount it also returns the version that was read, which a check-and-set
write with L</kv_write> must name.

On kv v2, a secret that was never written is version C<0>, and a secret
whose latest version was deleted has no data but keeps that version, so
that the next check-and-set write can name it.

B<Parameters:>

=over 4

=item C<$path>

A whole secret path, as for L</kv_mount>.

=back

B<Returns:> A hashref with C<data> (the secret's fields as a hashref, or
C<undef> when there is no secret), C<version> (the kv v2 version, or
C<undef> on kv v1), and C<kv_version> (C<1> or C<2>).

B<Errors:>

Dies when the vault refuses the read for any reason other than the secret
not existing, or cannot be reached, so that a sealed vault is never
mistaken for an absent secret.  The message names the path, the reason,
the likely causes, and what to run to check.  Errors from L</kv_mount>
propagate.

B<Examples:>

  my $record = $vault->kv_read('secret/exodus/lab/bosh/network-claim-lock');
  # Returns: { data => { at => '...', user => 'ops', ... }, version => 4, kv_version => 2 }
  #       or { data => undef, version => 0, kv_version => 2 } when never written

=head2 kv_write

  my $result = $vault->kv_write($path, \%data, %opts);

Replaces a whole secret with C<\%data> through the kv API, using
C<safe curl>.  Unlike C<safe set>, it does not merge into what is there,
and on a kv v2 mount it can make a check-and-set write, which the vault
refuses unless the secret is still at the version named.  Of any number of
processes that read the same version and write with check-and-set, only
the first succeeds.

When L</needs_write_confirmation> is true, a kv v2 write waits until reads
return the version it made (see L</_confirm_kv_version>).

The body goes on the C<safe curl> command line, so this must not be used to
write anything secret.

B<Parameters:>

=over 4

=item C<$path>

A whole secret path, as for L</kv_mount>.

=item C<\%data>

The secret's new fields.  kv v2 accepts an empty hash; kv v1 refuses one.

=item C<%opts>

=over 4

=item cas

The version the secret must still be at for the write to happen, with C<0>
meaning that it must not exist yet.  kv v2 only.

=back

=back

B<Returns:> On kv v2, the version the write made, or C<0> when a
check-and-set write was refused because the secret had changed.  On kv v1,
C<1>.

B<Errors:>

=over 4

=item *

Dies when the vault refuses the write for any other reason, or cannot be
reached.  The message names the path, the reason, and the likely causes,
including the kv v2 data path that a policy has to grant.

=item *

Dies when a kv v2 write succeeds but the vault does not say which version
it made, and when reads never catch up with that version.

=item *

Raises a bug when C<cas> is given for a kv v1 mount, or is not a whole
number.

=back

B<Examples:>

  my $version = $vault->kv_write($path, { at => $now, user => 'ops' }, cas => 3);
  # Returns: 4, or 0 when another write got there first

  $vault->kv_write('secret/handshake', { knock => 'knock' });
  # Returns: 1 on kv v1, or the new version on kv v2

=head2 kv_delete

  my $ok = $vault->kv_delete($path);

Deletes a secret through the kv API, using C<safe curl>.  On a kv v1 mount
the secret is gone afterwards.  On a kv v2 mount the latest version is
deleted, which reads as missing from then on, while the metadata keeps its
version number, so a later check-and-set write still has to name it.

Unlike C<safe rm>, which reports success whatever the vault answered, this
says when the vault refused the delete.

B<Parameters:>

=over 4

=item C<$path>

A whole secret path, as for L</kv_mount>.

=back

B<Returns:> C<1> when the vault accepted the delete, including when there
was nothing at the path.

B<Errors:>

=over 4

=item *

Dies when the vault refuses the delete or cannot be reached.  The message
names the path, the reason, and the likely causes, including the kv v2 data
path that a policy has to grant.

=item *

Dies as L</kv_mount> does when the mount cannot be worked out.

=back

B<Examples:>

  $vault->kv_delete('secret/exodus/lab/bosh/network_lock');
  # Returns: 1

=head2 build_descriptor

  my $descriptor = $vault->build_descriptor();

Constructs a vault descriptor string from the vault's properties, in the
format accepted by C<parse_vault_descriptor>. Includes the URL, namespace
(if set), alias name, and the C<no-verify> and C<no-strongbox> flags if
applicable.

The alias is left out when the name would not read back as itself: a name
containing whitespace would end the alias early, and C<attach> reads a
leading C<$> as an environment variable.  The alias only breaks ties
between targets at one URL, which Genesis does not support, so the
descriptor without it still resolves to the same target.

A strongbox clause is emitted only for a B<stated> setting, in either
direction: C<strongbox> when enabled, C<no-strongbox> when disabled, and
nothing at all when unstated. The descriptor therefore carries all three
states, and L</parse_vault_descriptor> reads back exactly what was meant.

This matters because the descriptor is how the setting reaches
C<BOSH_EXODUS_VAULT> and the vault descriptor handed to kits and CI.
Emitting a clause for a target that never stated the flag would propagate
an opinion nobody holds; emitting nothing for one that did would let the
reader's default overwrite a real decision.

B<Returns:> A descriptor string such as
C<'https://vault.example.com:8200 as prod-vault no-verify'>.

B<Examples:>

  my $desc = $vault->build_descriptor();
  # Returns: 'https://vault.example.com:8200 as prod-vault'

  # strongbox => 1 (explicitly enabled)
  # Returns: 'https://vault.example.com:8200 as prod-vault strongbox'

  # strongbox => 0 (explicitly disabled)
  # Returns: 'https://vault.example.com:8200 as prod-vault no-strongbox'

  # strongbox => undef (unstated) -- no clause at all
  # Returns: 'https://vault.example.com:8200 as prod-vault'

=head2 fetch_unseal_keys

  my ($ok, $message) = $vault->fetch_unseal_keys($env);

Fetches vault unseal keys from C<E<lt>secrets_mountE<gt>vault/seal/keys>
and stores them at C<$self-E<gt>{unseal_keys}> for use by C<unseal>.
At least 3 keys must be present. The keys are stored in a fixed order, with
C<key1> to C<keyN> in numeric order first and any other fields after them by
name, so that every run offers them in the same order.

B<Parameters:>

=over 4

=item $env

A Genesis environment object that provides the C<secrets_mount> method.

=back

B<Returns:> A two-element list C<($success, $message)>. C<$success> is C<1>
on success or C<0> on failure. C<$message> is a human-readable status string.

B<Examples:>

  my ($ok, $msg) = $vault->fetch_unseal_keys($env);
  if ($ok) {
    $vault->unseal();
  } else {
    warn "Could not fetch keys: $msg\n";
  }
  # Returns: (1, 'Successfully fetched vault unseal keys from ...')

=head2 unseal

  my ($out, $rc, $err) = $vault->unseal();

Unseals the vault cluster using the unseal keys previously fetched by
C<fetch_unseal_keys>. Uses the first three stored keys (as required by
C<safe unseal>). Retries up to three times on failure, pausing briefly
between attempts but not after the last one.

Returns immediately with success if the vault is already unsealed.

C<fetch_unseal_keys> must be called first.

B<How far this reaches:> C<safe unseal> only covers the whole cluster when
Strongbox is enabled for the target -- it asks Strongbox for every node's
seal state and unseals each sealed one. Without Strongbox it falls back to
the single address it is targeting. A successful return therefore does not
by itself mean the cluster is unsealed, and nothing downstream can tell the
difference: C<status> also consults only the targeted node. When Strongbox
is not enabled, this method emits a warning saying so on success, and
includes the same explanation in C<$error> on failure. See
L</_strongbox_unseal_caveat>.

safe's own stderr is preserved and included in C<$error>, rather than being
discarded as it was previously; it is where safe reports that Strongbox was
off and only the targeted address was reached.

B<Returns:> A three-element list C<($output, $exit_code, $error)>.
On success, C<$exit_code> is C<0> and C<$error> is empty. On failure after
all retries, C<$exit_code> is non-zero and C<$error> carries safe's stderr,
safe's output, and the Strongbox caveat where it applies, joined by blank
lines.

B<Examples:>

  my ($ok, $msg) = $vault->fetch_unseal_keys($env);
  if ($ok) {
    my ($out, $rc, $err) = $vault->unseal();
    if ($rc == 0) {
      print "Vault unsealed\n";
    } else {
      warn "Failed to unseal: $err\n";
    }
  }
  # Returns: ($output, 0, '') on success

B<Security note:> The keys reach C<safe> on stdin, and never as an argument.
C<safe>'s output and stderr are kept out of the trace, a failed attempt is
traced by address only, and any key that C<safe> echoes is replaced with
C<E<lt>redactedE<gt>> in both C<$output> and C<$error> before either is
returned. The keys stay at C<E<lt>secrets_mountE<gt>vault/seal/keys> for anyone
who has to finish the unseal by hand.

=head2 unseal_nodes

  my @results = $vault->unseal_nodes(@addresses);
  my @results = $vault->unseal_nodes(\%pass, @addresses);

Unseals each node in C<@addresses> through that node's own C<sys/unseal>
endpoint, using the keys previously fetched by C<fetch_unseal_keys>. This is
the way to open a Raft cluster whose safe target reaches only one node,
because that node cannot elect a leader on its own.

Each node's seal status is read first. A node that is already open is left
alone, and one that does not answer is reported as unreachable. A sealed node
is given the keys a threshold's worth at a time, where the threshold is what
the node reports. OpenBao counts a well-formed but wrong key, such as one left
over from a rekey, like any other, and only throws the round away once the
threshold is reached. So after a failed round the next combination of keys is
tried, up to 64 combinations. A round that the node judged in full, with every
key sent, is recorded so that it is never sent to that node again. A round
that an error cut short, such as a new Raft node answering that it is not
initialized yet, says nothing about its keys, so it is not recorded and a
later pass may send it again. A node is reset only just before a round is
submitted to it, and only when it shows progress that the round did not make,
whether that is an operator unsealing it by hand or an earlier round of ours
that a malformed key cut short. A node that refuses the reset gets no keys,
and is reported as refusing. A node that stays sealed through every
combination, or stops answering, is reported as such.

Every request goes through L</_node_request>, so the keys travel on curl's
stdin, never in its arguments, and no key appears in a trace, a log line, a
curl configuration file's output, or a result.

B<Parameters:>

=over 4

=item C<\%pass>

Optional. A hashref that ties this call to a larger pass, as
L</unseal_cluster> uses it. Its C<deadline> is a time from L</_now>, against
which every request is capped. No request starts once less than a tenth of a
second remains, because curl would read a smaller limit as no limit at all. Its
C<failed_rounds> is a hashref in which the rounds that failed on each node are
recorded, so that a later call with the same hashref skips them.

=item C<@addresses>

The cluster's nodes, each an address with an optional port, as in
C<10.0.0.5:8200> or C<[fd00::5]:8200>. A node without a port is reached on
the target's port.

=back

B<Returns:> One hashref per node, in the order given, with C<address>,
C<unsealed> (C<1> or C<0>), and C<message>, which says whether the node was
already unsealed, was unsealed, was unreachable, presented a certificate that
failed verification, refused to reset, stopped answering, was not reached
before the deadline, stayed sealed through every combination of keys, needed
more keys than were fetched, or had no keys fetched at all.

B<Examples:>

  $vault->fetch_unseal_keys($env);
  my @results = $vault->unseal_nodes(qw/10.0.0.5 10.0.0.6 10.0.0.7/);
  # Returns: ({address => '10.0.0.5', unsealed => 1, message => 'unsealed'}, ...)

=head2 wait_for_active_node

  my $active = $vault->wait_for_active_node($timeout, @addresses);

Waits for a Raft cluster to elect an active node. Opening a quorum is not the
last step, because the cluster then has to elect a leader before any
authenticated request can succeed. This asks each node's unauthenticated
C<sys/health> endpoint every three seconds, and gives up once C<$timeout>
seconds of wall-clock time have passed. Each request is capped at the time
that remains, so a node that never answers cannot stretch the wait. Every
node is asked at least once, even when C<$timeout> is zero.

B<Parameters:>

=over 4

=item C<$timeout>

The longest time to wait, in seconds of wall-clock time.

=item C<@addresses>

The cluster's nodes, written as for L</unseal_nodes>.

=back

B<Returns:> The address of the active node, or C<undef> when none became
active within C<$timeout> seconds.

B<Examples:>

  my $active = $vault->wait_for_active_node(90, qw/10.0.0.5 10.0.0.6 10.0.0.7/);
  # Returns: '10.0.0.6' once that node leads, or undef after 90 seconds

=head2 unseal_cluster

  my $outcome = $vault->unseal_cluster($timeout, @addresses);

Unseals a Raft cluster and waits for it to elect a leader, all within
C<$timeout> seconds of wall-clock time. No request starts after the deadline,
and each one is capped at the time that remains. It runs L</unseal_nodes> over
every node, and while fewer than a quorum are open it pauses a few seconds and
asks the closed nodes again, since a node may still be starting. A round of
keys that failed on a node is never sent to it again. Once a quorum is open it
waits for an active node with L</wait_for_active_node> and then, if time
remains, gives any node that is still closed one more try, so the cluster ends
fully unsealed whenever every node can be reached in time. Without a quorum
no leader can be elected, so it does not wait for one.

A C<$timeout> of zero means "do not wait" rather than "do nothing". It still
makes one full pass over every node, with each request allowed its usual ten
seconds, and asks each node once for a leader, but it does not retry, pause,
or give late nodes another try.

B<Parameters:>

=over 4

=item C<$timeout>

The longest time to spend, in seconds of wall-clock time.

=item C<@addresses>

The cluster's nodes, written as for L</unseal_nodes>.

=back

B<Returns:> A hashref with C<nodes>, the per-node results from
L</unseal_nodes> in the order given, C<active>, the active node's address or
C<undef> when none emerged, C<open>, the number of unsealed nodes, and
C<quorum>, the number a majority needs.

B<Examples:>

  my $outcome = $vault->unseal_cluster(90, qw/10.0.0.5:443 10.0.0.6:443 10.0.0.7:443/);
  # Returns: {nodes => [...], active => '10.0.0.6:443', open => 3, quorum => 2}

=head2 _strongbox_unseal_caveat

B<Returns:> A C<(format, @args)> list, or the empty list when Strongbox is

B<Errors:> None.

B<Examples:>

  # Strongbox enabled
  my @none = $vault->_strongbox_unseal_caveat();
  # Returns: ()

=head2 _node_request

  my $reply = $vault->_node_request($node, $method, $path, $payload, $max_time);

Makes one API call to a single node of the cluster, for L</unseal_nodes> and
L</wait_for_active_node>. The request goes to the target's own URL, and
curl's C<--connect-to> sends the connection to the node's address and port.
TLS is therefore verified against the same name or address that C<safe>
verifies, whether the target is an IP address or a hostname, and C<-k> is
passed only when the target itself skips verification. Every time limit
handed to curl is rounded up to the next tenth of a second and is never below
one tenth, because curl reads a limit that rounds to zero as no limit, and a
node that accepts the connection but never replies would then hang the
deploy. The rule's first host
is left empty, as in C<:443:10.0.0.6:8200>, because curl compares it with the
URL's host only after normalising the URL, and an empty host matches whatever
that comes to. A target written in a non-canonical form therefore still
reaches the node rather than itself.

C<-q> comes first, so curl reads no configuration file that could add a trace
or a key log, and C<CURL_HOME> and C<SSLKEYLOGFILE> are cleared for the same
reason. A C<$payload> is encoded as JSON and handed to curl on stdin. It never
appears among curl's arguments, and the reply is kept out of the trace.

B<Parameters:>

=over 4

=item C<$node>

The node's address with an optional port, as in C<10.0.0.5:8200> or
C<[fd00::5]:8200>. Without a port, the target's port is used.

=item C<$method>

The HTTP method, such as C<GET> or C<PUT>.

=item C<$path>

The API path below C</v1/>, such as C<sys/seal-status>.

=item C<$payload>

Optional. A hashref sent as the JSON request body.

=item C<$max_time>

Optional. The most seconds the whole request may take, 10 by default.

=back

B<Returns:> The decoded reply as a hashref, or C<undef> when the node did not
answer with a JSON object. In list context a second value says why there is
no reply. A certificate that fails verification (curl exits 51, 58, or 60) is
reported as not verifying against the target name, naming the node, rather
than as the node being unreachable. A failed handshake (curl exit 35) is
reported as either a certificate mismatch or a node that is still starting,
since a node that resets the connection while it starts looks the same to
curl. Verification itself stays on, so such a node is never unsealed.

B<Examples:>

  my $state = $vault->_node_request('10.0.0.6', 'GET', 'sys/seal-status');
  # Returns: {sealed => 1, t => 3, progress => 0, ...}

so the first combination is the first C<$size> items. It stops at 64
combinations, which covers every choice of three keys from eight.

B<Parameters:>

=over 4

=item C<$size>

How many items each combination holds.

=item C<@items>

The items to choose from.

=back

B<Returns:> A list of array references.

B<Examples:>

  my @rounds = Service::Vault::_combinations(2, qw/a b c/);
  # Returns: (['a','b'], ['a','c'], ['b','c'])

=over 4

=item C<$seconds>

=back

B<Returns:> What C<Time::HiRes::sleep> returns.

B<Examples:>

  # Returns: 3, after three seconds

Returns C<1> if C<$target> is a syntactically valid Vault URL

  my ($url, @aliases) = Service::Vault::_get_targets($target)

Resolves a target name or URL to the canonical URL and all safe aliases

=head2 _write_pairs

  $vault->_write_pairs($path, \%pairs);

Writes C<%pairs> to C<$path> in as few C<safe set> commands as the
command-length limit allows, confirming each one before sending the next.

A command longer than 900 characters was found empirically to corrupt the
write, so pairs are accumulated until the next one would cross that mark;
the pair that crosses it starts the following batch. A single pair longer
than the limit on its own is sent anyway, since there is no smaller write
to fall back to.

Called by both C<set> and C<set_path>. C<set_path> uses it directly rather
than going through C<set>, because its keys are already the ones to store
and C<set>'s C<path:key> splitting would mangle any key containing a colon.

B<Parameters:>

=over 4

=item $path

The vault secret path.

=item \%pairs

Hash reference of key names to string values. Undefined values are written
as the empty string.

=back

B<Returns:> Nothing.

B<Errors:>

Propagates the errors of L</_write_batch>.

B<Examples:>

  $vault->_write_pairs('secret/myapp', {user => 'admin', port => 8080});

=head2 _write_batch

  $vault->_write_batch($path, \@batch, \%written);

Sends one C<safe set> for C<@batch>, then confirms everything written so
far is readable.

C<@batch> is a list of pre-joined C<"key=value"> strings. Each is folded
into C<%written>, which accumulates across every batch of a single
C<_write_pairs> call, and the confirmation checks that whole accumulation
rather than just this batch -- a batch that merged into a stale base drops
its predecessors, not itself, so checking only the newest would not notice.

B<Parameters:>

=over 4

=item $path

The vault secret path.

=item \@batch

Array reference of C<"key=value"> strings to write in this command. An
empty batch is a no-op.

=item \%written

Hash reference accumulating every key and value written to C<$path> so
far. Modified in place.

=back

B<Returns:> Nothing.

B<Errors:>

Dies with C<"Could not write #C{%s} to vault at #M{%s}:\n%s"> if the
command exits non-zero.

May also die from the confirmation; see L</_confirm_written>.

B<Examples:>

  my %written;
  $vault->_write_batch('secret/myapp', ['user=admin'], \%written);
  # %written is now (user => 'admin')

=head2 _confirm_timeout

  my $seconds = Service::Vault::_confirm_timeout();

How long a read-back may take before it is treated as a failure.

Reads C<GENESIS_VAULT_CONFIRM_TIMEOUT>, which accepts a positive number of
seconds and may be fractional. Anything else yields the default of C<10>.

B<Returns:> A number of seconds.

B<Errors:>

None. An unusable value falls through to the default.

B<Examples:>

  Service::Vault::_confirm_timeout();                  # => 10
  local $ENV{GENESIS_VAULT_CONFIRM_TIMEOUT} = '0.5';
  Service::Vault::_confirm_timeout();                  # => 0.5

=head2 _confirm_written

  $vault->_confirm_written($path, \%written);

Polls C<$path> until every key in C<%written> reads back with the value
that was sent, or the timeout expires.

The comparison is on B<values>, not key names. A batch that merged into a
stale base carries the right key names and the wrong contents, so a
presence check would pass while the result is wrong. Comparing values also
avoids matching against a returned path prefix, which C<safe> normalises.

Returns immediately when L</needs_write_confirmation> is false, which is
what keeps single-node and development vaults free of extra round-trips.

Polls every 250ms up to L</_confirm_timeout>.

B<Parameters:>

=over 4

=item $path

The vault secret path just written.

=item \%written

Hash reference of every key and value written to C<$path> so far.

=back

B<Returns:> Nothing.

B<Errors:>

Dies with C<"Wrote #C{%s} to the vault at #M{%s}, but %s of its %s keys
did not read back within %ss."> when the timeout expires with keys still
missing or holding a different value. A lost merge cannot be repaired
afterwards, so this stops rather than continuing.

B<Examples:>

  $vault->_confirm_written('secret/myapp', {user => 'admin'});
  # Returns normally once the value is readable

=head2 _readback_value

  my $flat = Service::Vault::_readback_value($value);

Flattens a value read back from the vault so it can be compared with what
was sent.

A write always sends a string, but a read does not always return one. A
path outside a kv mount, an approle role for one, hands a comma-separated
list back as an array reference and a numeric string back as a number, so
comparing the raw forms reports a difference where the contents match.
Both sides of the comparison in L</_confirm_written> go through this, which
is what keeps a correct write from being read as a lost one.

An array reference is joined with commas and every other value is
stringified. An undefined value, and an undefined element within an array
reference, both flatten to the empty string, so a missing value compares
equal to an empty one rather than raising.

B<Parameters:>

=over 4

=item C<$value>

The value to flatten. A scalar, an array reference, or undef.

=back

B<Returns:> The flattened value as a string.

B<Errors:>

None. Every input has a flattened form.

B<Examples:>

  Service::Vault::_readback_value('admin');        # => 'admin'
  Service::Vault::_readback_value(['a', 'b']);     # => 'a,b'
  Service::Vault::_readback_value(42);             # => '42'
  Service::Vault::_readback_value(undef);          # => ''

=head2 _confirm_cleared

  $vault->_confirm_cleared($path);

Polls C<$path> until it reads back with no keys, or the timeout expires.

A write that follows a clear merges into whatever a read returns, so keys
outliving the delete are carried straight into the new value. Those keys
are extras rather than missing ones, which is why L</_confirm_written>
cannot detect this case and it needs its own check.

Returns immediately when L</needs_write_confirmation> is false. Polls every
250ms up to L</_confirm_timeout>.

B<Parameters:>

=over 4

=item $path

The vault secret path just cleared.

=back

B<Returns:> Nothing.

B<Errors:>

Dies with C<"Cleared #C{%s} in the vault at #M{%s}, but %s of its keys
were still readable after %ss."> when the timeout expires with keys still
present.

B<Examples:>

  $vault->clear('secret/myapp');
  $vault->_confirm_cleared('secret/myapp');
  # Returns normally once the path reads empty

B<Limitations:>

Checks C<$path>'s own keys only. A recursive clear also removes subpaths,
and those are not read back.

=head2 _unpack_path_export

  my $tree = $vault->_unpack_path_export($path, $data);

Nests the paths of a C<safe export> under the path the export was made for,
for L</get_path> and L</get_path_strict>. The export is first reduced to a
flat hash of full vault paths to the key/value pairs stored at each by
L</normalize_export>, whatever its export version, and dies as that does on
a value that is not a string. The pairs stored at
C<$path> itself become the top level of the result, and the pairs at each
subpath are placed under the keys named by the rest of its path. A path
stored with the C<__flattened__> marker has the marker removed and is
unflattened with C<Genesis::unflatten>.

C<$data> itself is not modified, since the marker is deleted from the copies
C<normalize_export> makes.

B<Parameters:>

=over 4

=item C<$path>

The path the export was made for, without leading or trailing slashes.

=item C<$data>

The decoded export, of any export version.

=back

B<Returns:> A nested hash reference, empty when C<$data> holds no paths.

B<Errors:>

=over 4

=item C<"Cannot use the safe export ...">

Raised (via C<bail()>) by L</normalize_export> when the export holds a value
that is not a string, or is in a format it does not read.

=back

B<Examples:>

  my $tree = $vault->_unpack_path_export('secret/myapp', {
    'secret/myapp'    => {user => 'admin'},
    'secret/myapp/db' => {host => 'localhost'},
  });
  # Returns: { user => 'admin', db => { host => 'localhost' } }

=head2 _export_pairs

  my $pairs = _export_pairs($path, $value);

Checks the key/value pairs exported for one path for L</normalize_export>,
and returns a copy of them. It dies when C<$value> is not a hash, or when any
of its values is not a string, as C<_export_value_type> judges it.

B<Parameters:>

=over 4

=item C<$path>

The vault path the pairs were exported from, named in any error.

=item C<$value>

The decoded value exported for the path.

=back

B<Returns:> A new hash reference holding the same key/value pairs.

B<Errors:>

=over 4

=item C<"Cannot use the safe export of #C{%s}: it is not an object of keys, but a JSON %s.">

Raised (via C<bail()>) when C<$value> is not a hash reference.

=item C<"Cannot use the safe export of #C{%s}: its #C{%s} key holds a typed value, a JSON %s, not a string. ...">

Raised when a value is not a string. The first key in sorted order that
holds one is named.

=back

B<Examples:>

  my $pairs = _export_pairs('secret/myapp', {password => 'hunter2'});
  # Returns: { password => 'hunter2' }

  _export_pairs('secret/myapp', {enabled => JSON::PP::true});
  # Dies: Cannot use the safe export of secret/myapp: its enabled key holds
  #       a typed value, a JSON boolean, not a string. ...

=head2 _export_value_type

  my $type = _export_value_type($value);

Names the JSON type of a decoded value that is not a string, for
L</normalize_export> to refuse it. A hash is an C<object>, an array is a
C<list>, a C<JSON::PP::Boolean> is a C<boolean>, and C<undef> is C<null>.
A plain scalar is a C<number> when it has a numeric value and no string
value, which is how C<JSON::PP> decodes a JSON number and how it tells one
from a string when it encodes. The check is only sound on a value that has
not been used as a string since it was decoded, since that gives it a
string value.

B<Parameters:>

=over 4

=item C<$value>

A value from a decoded export.

=back

B<Returns:> The JSON type as a string, or C<undef> when the value is a
string.

B<Examples:>

  _export_value_type(load_json('{"n":42}')->{n});   # Returns: 'number'
  _export_value_type(load_json('{"n":"42"}')->{n}); # Returns: undef
  _export_value_type([]);                           # Returns: 'list'

=head2 _kv_curl

  my ($status, $reply, $reason) = $self->_kv_curl($method, $uri, $payload);

Makes one kv API call with C<safe curl>, and works out the HTTP status it
came back with from the status line of the response that safe prints.
Every safe that Genesis accepts prints the whole response, status line
first, when it is not given C<--data-only>.  The status line is read rather
than the exit code, because safe before 1.20 exits 0 whatever the vault
answered, which would make a refusal look like success.

C<safe curl> takes a body only as an argument, so C<$payload> ends up on
the command line, where other users of the host can see it.  Nothing
secret may be passed through here.

B<Parameters:>

=over 4

=item C<$method>

The HTTP method, such as C<GET> or C<POST>.

=item C<$uri>

The API path below C</v1/>, with no leading slash.

=item C<$payload>

Optional.  A hashref, sent as the JSON body.

=back

B<Returns:> A three-element list of the status (the vault's status, or
C<0> when no response came back), the decoded JSON reply or C<undef>, and
a one-line reason.  The reason is empty for a 2xx status.  Otherwise it is
taken from the reply's C<errors>, or from the status line, or, when no
response came back, from safe's stderr or exit code.

B<Examples:>

  my ($status, $reply, $reason) = $self->_kv_curl('GET', 'secret/data/x');
  # Returns: (404, { errors => [] }, 'GET /secret/data/x: 404 Not Found')

=head2 _kv_http_response

  my ($status, $text, $body) = _kv_http_response($out);

Splits a response, as C<safe curl> prints it, into its status, status text,
and body.  A body that came chunked is joined back together, because Go
prints it with its chunk sizes.  A function, not a method.

B<Parameters:>

=over 4

=item C<$out>

What C<safe curl> printed on stdout, starting with a status line such as
C<HTTP/1.1 404 Not Found> or C<HTTP/2.0 200 OK>.

=back

B<Returns:> A three-element list of the numeric status, the status text,
and the body, or an empty list when C<$out> does not start with a status
line.

B<Examples:>

  _kv_http_response("HTTP/1.1 404 Not Found\r\nContent-Length: 13\r\n\r\n{\"errors\":[]}");
  # Returns: (404, 'Not Found', '{"errors":[]}')

=head2 _confirm_kv_version

  $self->_confirm_kv_version($path, $version);

Waits until reads of C<$path> return C<$version> or newer, so that whatever
reads next does not act on an older version.  It does nothing unless
L</needs_write_confirmation> is true, and otherwise reads every quarter of
a second for up to C<GENESIS_VAULT_CONFIRM_TIMEOUT> seconds.

B<Parameters:>

=over 4

=item C<$path>

The secret that was written.

=item C<$version>

The kv v2 version the write made.

=back

B<Returns:> Nothing.

B<Errors:>

Dies when reads still return an older version at the timeout, naming both
versions and the likely cause, which is a vault target on a standby node
whose reads lag the leader.

B<Examples:>

  $self->_confirm_kv_version('secret/exodus/lab/bosh/network-claim-lock', 4);
  # Returns: nothing, once a read shows version 4 or newer
